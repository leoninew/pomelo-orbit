# 后端架构与测试治理

让业务规则和用例通过明确端口直接测试。以实际调用关系、当前业务行为和必要失败边界为验收依据，不以目录、抽象数量、测试数量或覆盖率证明治理完成。

测试是暴露后端依赖和职责问题的入口。发现测试慢、夹具重或需要补写内部字段时，沿生产调用链治理端口和装配；不要只调整测试让现有架构看起来容易测试。日常核心单测应提供秒级反馈，完整持久化/协议/进程验证单独计时，不把两者的耗时混为业务规则成本。

## 工作区与依据

先确认工作区为 Pomelo Orbit。本文中的 `cmd/`、`internal/`、`sql/` 等路径相对项目根目录。读取当前 [AGENTS.md](../../../AGENTS.md)、[后端架构](../../../docs/architecture/backend.md) 和目标实现；涉及 CD 行为时读取 [产品模型](../../../docs/product/cd-model.md) 与 [运行时约定](../../../docs/architecture/cd-runtime.md)。具体落点与代表测试按需查阅 [项目边界](references/backend-boundaries.md)。本 skill 自包含，不要求检出其他仓库或安装通用架构 skill。

用户指令和项目约束优先。架构或测试检查请求给出发现与证据；实施治理请求则完成授权范围内的代码、测试和验证。历史报告中的测试数量、授权和完成状态只属于当时，先核对当前代码与工作树。

## 定位问题

从代表入口追踪到应用用例、规则、Repository 或外部端口、具体适配器及 bootstrap 装配。对共享能力查找真实生产调用方；不只根据包名或 import 搜索下结论。

- 入站适配器调用应用，用例依赖业务模型、Repository 接口和应用端口；具体实现由 bootstrap 注入。
- Gin、HTTP/MCP 协议对象、SQLC Row、SQL/SDK 调用各留在适配边界。model 不依赖这些技术类型；common 不承载业务语义。
- 检查直接和传递依赖，也检查测试依赖。测试必须组装数据库或完整入口才能验证简单规则时，判断是测试边界过大，还是实现缺少已有职责应有的端口。
- 区分当前落点和目标边界：现有代码并非全部正确，也不因引用通用架构就强制改目录、增加领域层或统一全部接口。

对发现记录“当前 / 风险 / 建议”，给出具体文件、函数、调用链、必须保留的行为、测试调整理由和验收方式。续查同一治理任务时沿用原问题编号；普通局部调整无需新建整套治理文档。

连续治理时，在同一任务记录顶部维护总进度：按事务与失败收敛、应用依赖、外部适配、测试必要性及反馈成本列出已完成、已确认未完成、待核查范围和下一步验收。每轮从整体风险与实际成本选择范围，不自动沿上轮模块继续拆分。已登记问题的完成比例不代表整个后端的完成率；纯目录调整或抽象数量不能作为进展。

## 修正实现与测试

- 先复用现有规则、用例、模型和端口。只为真实职责拆分新增抽象，避免纯转发 facade、测试专用业务路径、泛化 DI 或事务框架。
- 将业务判断和跨端口编排放在 application 或 model；HTTP、MCP、worker handler 负责输入、身份上下文、调用和协议映射，SQL/外部适配器负责技术实现。
- 沿现有事务和资源边界调整，保留成员权限、Project 归属、执行身份、修订检查、取消、历史保留及失败传播。创建者、借用者、关闭者要明确；不要把 Docker、SSH、流会话和长文件操作包进长数据库事务。
- 单测执行真实规则或用例，只替换所需的 Repository、应用或外部能力端口。替身提供事实和记录请求，不重演被测业务规则，不靠构造器补丁、全局替换或绕过生产装配掩盖设计问题。
- 保留主要正向流程与真实、高风险失败边界，迁移错放在协议测试里的规则断言，删除重复、旧行为和实现细节断言；只补当前无法验证的必要行为。

## 后端测试边界

- 单元测试不要求数据库、迁移、完整 Gin/MCP 服务或真实 Docker/SSH。纯 mapper、规则和端口替身用例优先直接调用。
- Repository 查询、约束、原子写入、回滚和历史保留需要真实持久化证据时，已有临时 SQLite/文件测试可作为本地集成验证。明确分类和保留理由，不将它们称为纯单测，也不一律删掉或全部改成 SQL mock。
- 业务 Repository 的持久化验证使用当前迁移得到的表结构，不在夹具里复制局部业务 DDL，也不将普通查询测试钉在历史迁移版本。历史升级测试可保留明确的起始版本；通用事务机制用独立 probe 表验证提交/回滚，不需要整套业务 schema。测试名称应区分仓储自身原子性与参与调用方事务。
- Gin 中间件和 MCP 工具的协议契约可以使用 `httptest`、内存连接及应用替身验证。真实终端进程、socket 或跨层数据库用例属于组件/集成验证，即使位于 `*_test.go` 中。
- 外部数据库、Docker、Traefik 重启和远端 SSH 联调遵循现有显式启用条件；默认检查不启用这些条件。不能靠新增 skip、改标签、单线程运行或减少测试来证明实现已经修复。
- 前端不需要并发、性能、集成和复杂 UI 测试的约束只适用于前端。后端对取消、任务租约、提交/回滚和资源释放的真实承诺可保留最小有效验证；不穷举理论竞态或凭空增加性能测试。

遇到超时或偶发失败，先区分业务超时、清理超时、测试等待和环境负载。优先用明确同步点和端口替身隔离被测行为，不只放大超时。单独复跑通过不能覆盖首次全量失败；需要性能结论时先测量具体阶段。

资源释放测试应验证该会话拥有的资源及真实子进程，不用整个测试进程的句柄/线程总数代替责任判断。操作系统可能复用句柄值，检查时要识别资源类型；不能通过放宽全局计数容差来掩盖问题。

计时使用 `-count=1` 排除测试结果缓存，单独运行，记录编译/链接、进程启动、package 与具体用例耗时。大量包在首个用例前等待时，不能把整个 package 时间归因于业务逻辑。纯端口上的时间编排优先使用 `testing/synctest`；涉及真实文件、socket、进程时保留真实边界验证，不盲目放进虚拟时间。

`task test:go:unit -- -count=1` 验证 application/model/common/queue 的核心规则与用例，使用 `unit` build tag 排除已分类的本地集成和外部场景；普通 `go test` 与 `task test:go:all -- -count=1` 仍执行完整范围。分类必须跟随实际依赖，混在集成文件里的纯规则应迁出；不能通过标签隐藏失败或将缩小范围当成全量提速。修改公共夹具或实现后，两种入口都要通过。

## 警告、漂移与收尾

将日志关联到具体用例和注入的失败。预期的超时、不可用、panic recovery 等日志与测试失败分别记录；不全局静默日志，不把正常日志或测试名称中的 warning 当成异常。

实现删除、移动或重构后，核对生产调用方、fixture、状态/类型值、SQL、协议路径、替身及文档。没有生产用途的 helper 或包不能由旧测试继续维持；授权清理时同步删除。历史迁移或转换测试所需的旧数据按其真实目的保留，不机械替换所有旧值。不要为旧断言恢复移除行为或引入兼容兜底。迁移文件按项目约束处理。

在项目根目录运行现有 Go 测试入口；排查实际执行结果时可使用：

```powershell
go test -count=1 ./cmd/... ./internal/... ./sql
```

修改 Go 后端后执行项目要求的 `task check` 和 `go test ./cmd/... ./internal/...`；涉及迁移嵌入包时纳入 `./sql`。仅修改 skill 或文档时校验结构、引用和 diff 即可。遵循现有环境，不为验证安装、升级工具或启动开发服务器。

报告实际命令、范围、通过/失败/跳过、警告判断、每项治理状态及遗留问题。暂存、提交、数据库操作和外部写入按当前用户授权执行。
