一、设计完整度总结
-------------------------------------------

【核心设计】✓ 完成

1. 实体模型：Project, Credential, PipelineTemplate, PipelineRun, Artifact, Notification
2. 业务规则：Pipeline 集中管理、变量系统（三层）、Jinja2 语法
3. Job 模型：统一 stage/step、递归嵌套、串行/并行规则
4. Job 状态机：7 种状态 + 聚合规则 + fail-fast + 取消传播（参考 Deployment 状态机）
5. checkout action：完整接口规范（with 参数、outputs、凭据注入）
6. 制品管理：docker_image | file，显式声明
7. 执行层：PipelineExecutor 接口 + asyncio 实现路径
8. 重试机制：retry_of + skip_if_success + 依赖链传播
9. 并发控制：全局 + 项目级 concurrency_policy
10. 取消运行：waiting→canceled, running→canceling→canceled
11. 日志流：SSE 推送状态和日志
12. 事件通知：webhook | email 订阅

三、实施顺序建议
-------------------------------------------

【Phase 1：核心可跑】（预计 1-2 周）

实体层：
- Project CRUD（repository_url, pipeline_template_id, git_credential_id, variable_overrides）
- Credential CRUD（name, type, data 加密存储，复用 Fernet）
- PipelineTemplate CRUD（name, content, variable_declarations）
- PipelineRun 创建与查询（手动触发）
- Job 记录（状态、日志）

执行层：
- PipelineExecutor 接口定义
- AsyncioPipelineExecutor 实现（递归处理 Job 树）
- 容器执行器（docker run，挂载 workspace 和 artifacts）
- 日志收集（stdout/stderr 写入数据库）
- checkout action 实现（alpine/git + 凭据注入）

API 层：
- POST /projects
- POST /projects/{id}/runs（手动触发）
- GET /projects/{id}/runs
- GET /runs/{id}
- GET /runs/{id}/jobs/{job_name}/logs

前端：
- Project 列表与创建表单
- PipelineRun 列表
- 日志查看页面（文本展示）

交付标准：
- 能创建 Project 并关联 Credential 和 PipelineTemplate
- 能手动触发 PipelineRun
- 能看到 Job 执行日志和最终状态
- 能拉取代码并执行简单构建


【Phase 2：完整 CI】（预计 2-3 周）

新增功能：
- Webhook 接收端点（验证 webhook_secret）
- Job 并行执行（depends_on + asyncio.gather）
- Artifact 记录（docker_image | file）
- 重试逻辑（retry_of + skip_if_success + 依赖链传播）
- 变量系统完整实现（三层合并 + Jinja2 渲染）

API 层：
- POST /webhooks/git（接收 GitHub/GitLab webhook）
- GET /runs/{id}/artifacts
- POST /runs/{id}/retry

前端：
- Webhook 配置界面
- Artifact 列表与下载
- 重试按钮
- 变量配置表单

交付标准：
- 能接收 Git Webhook 自动触发构建
- 能并行执行 Job（如 lint 和 test 并行）
- 能记录和下载制品

【Phase 3：生产就绪】（预计 2-3 周）

- ProjectNotification CRUD + 事件触发（webhook | email）

API 层：
- POST /runs/{id}/cancel
- POST /projects/{id}/notifications
- GET /runs/{id}/events（SSE）
- GET /runs/{id}/jobs/{job_name}/logs/stream（SSE）

前端：

- 取消按钮
- 通知订阅配置
