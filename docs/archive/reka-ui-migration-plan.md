# Reka UI 迁移计划

## 概述

将 Pomelo Orbit 前端从 DaisyUI 迁移到 Reka UI，采用**渐进式迁移**策略：
- 先搭建纯静态页面（无业务逻辑）
- 基于截图还原 UI
- 逐页迁移业务逻辑

## 截图生成

运行 pomelo-pw 生成所有页面截图：

```bash
# 1. 启动后端服务
make dev-backend

# 2. 启动前端服务
make dev-frontend

# 3. 运行截图脚本（需要 pomelo-pw 工具）
pomelo-pw run .pomelo-pw.yaml
```

## 组件复用策略

### 可复用的现有组件

以下组件可以直接复用或稍作调整：

- Monaco Editor 集成
- Vue Flow 集成（DAG 可视化）
- 时间格式化工具
- API 请求封装
- 状态管理（Pinia stores）

### 需要重写的组件

- 所有 DaisyUI 组件（按钮、表单、对话框等）
- 表格组件（考虑使用 TanStack Table）
- Toast 通知
- Dropdown 下拉菜单

## 风险和应对

### 风险 1：表格组件缺失

**应对**：
- 方案 A：使用 TanStack Table（推荐）
- 方案 B：自己实现简单表格组件
- 方案 C：保留部分 DaisyUI 表格样式

### 风险 2：Monaco Editor 样式冲突

**应对**：
- 使用 CSS 作用域隔离
- 测试深色模式兼容性

### 风险 3：Vue Flow 样式冲突

**应对**：
- 使用 CSS 变量覆盖默认样式
- 确保与 Tailwind 不冲突

### 风险 4：迁移时间超预期

**应对**：
- 采用渐进式迁移，新旧并存
- 优先迁移高频页面
- 低频页面可以延后
