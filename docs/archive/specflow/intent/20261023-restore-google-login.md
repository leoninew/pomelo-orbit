# Intent / 意图：恢复 Google 登录
最后修改时间: 2026-10-23 11:52:34

## 审查状态

Accepted

## 背景

`e0e7fbd9` 已实现 Python Google OAuth 登录。迁移 Go 时，`62ea4620` 为两个 Google 路由加入临时 503 占位；之后切换运行入口并删除 Python 后端，功能未迁移。当前前端仍提供登录按钮和回调页面。

## 目标与场景

恢复点击 Google 登录、授权返回、查找或关联账号、创建新用户和签发 Orbit JWT 的完整流程。成功后恢复原始站内目标；取消或失败时返回登录页。沿用现有用户状态、权限和 Project 成员隔离。

## 非目标

不接入 Casdoor 或其他 OAuth 提供商，不改密码登录、不授予新用户角色或 Project 成员资格，不启动或重启开发服务器，不修改已执行迁移。

## 验收标准

- A01：配置完整时，GET `/api/auth/google` 重定向 Google，配置缺失时返回现有结构的 503；部分配置在启动阶段报错。
- A02：回调验证浏览器绑定的 state、有效期、PKCE、Google ID token 的签名、issuer、audience、有效期与 nonce；未验证邮箱不得登录。
- A03：优先按 Google subject 查用户；同邮箱且未绑定其他身份的账号可关联；新用户可创建；禁用账号与身份冲突不得登录，角色和成员关系不被扩大。
- A04：Google 网络请求在事务外，用户写入与登录记录在短事务内；成功提交后才返回 JWT。
- A05：前端回传 state，成功后恢复合法站内目标；失败及取消有可见反馈；本地回调配置与 9020 端口一致。
- A06：开发检查通过，测试覆盖主要业务分支、持久化回滚和 HTTP/OIDC 协议失败边界，错误不暴露 secret 或 Google token。

## 工作量评估

主要交付是一条登录链路，涉及配置、认证应用、Google 适配器、用户查询、HTTP 与前端回调。工作量中等；复杂度主要来自协议验证与事务边界；风险集中于身份关联、凭据泄露及禁用用户绕过。现有用户表已存 OAuth 字段，可直接恢复查询，无需数据库结构变更。

保持单任务：各层共享同一回调契约，按顺序实现和检查即可。安全边界加强测试，不额外拆分 task。候选子任务与协调不适用。

## 决策、风险与假设

- 保留现有 GET 授权入口和 POST 回调；恢复旧版账号关联行为，但必须验证邮箱且禁止覆盖其他已绑定身份。
- 使用成熟 OIDC 验证库；state/nonce/PKCE 会话通过带有效期的加密 HttpOnly cookie 绑定浏览器。
- 暂无需要用户确认的未决事项。真实 Google 登录依赖 Google 控制台登记正确回调地址及服务端网络可达，开发检查使用本地可控协议替身。
