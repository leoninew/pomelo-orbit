## Background and goals / 背景与目标

- 提供通用的跨项目服务复制功能，用户无需手动重建应用、版本、组件及服务配置。
- 复制源服务所属应用及版本组件声明；弹窗提供版本范围选择，默认复制最新版本，用户可以选择复制全部版本。无论范围，均复制源服务配置、环境值和组件覆盖。
- 保留应用名称、应用编码、版本信息、组件声明、服务编码及配置值。复制时按目标环境计算并允许编辑服务部署目录，其余挂载路径、端口、环境值或凭据保留；用户之后自行编辑，再自行部署。
- 用户确认在服务详情增加“复制”按钮，弹窗选择目标项目、版本范围并确认可编辑的目标部署目录；不增加改名、改编码或其他配置编辑步骤。
- 目标项目发生同名或编码冲突时拒绝复制，不覆盖已有资源、不自动改名、不合并复用已有定义。

仓库依据：

- `internal/application/application/usecase/service.go` 已有完整应用定义读取和创建能力，包含全部版本及组件。
- `internal/application/service/usecase/service.go` 已有服务定义读取和创建能力，包含服务环境值和组件覆盖。
- `internal/model/service.go` 中服务以 `Code` 标识，没有独立的名称字段；应用具有 `Name` 和 `Code`。
- `web/src/views/service/ServiceDetail.vue` 对应单个服务；`web/src/views/environment/EnvironmentPage.vue` 对应项目执行环境，目前没有单个源服务上下文。

## Non-goals / 非目标

- 不执行实际部署、停止、重建或其他容器操作，不迁移数据库记录、数据卷、宿主机文件或镜像文件。
- 不复制部署历史、操作记录和容器运行状态；目标服务处于未部署状态。
- 不修改源资源，不删除或重置目标资源、数据库、数据卷及已有凭据。
- 不复制项目环境、SSH 凭据、网关或自定义路由，不扩展为整个项目的交接或恢复。
- 仅服务部署目录按目标平台计算与校验；其他业务配置不自动修正，不生成或轮换凭据。
- 当前授权范围为按已接受计划实现及必要检查，不执行 Git 提交、推送或线上资源操作。

## Scenarios / 场景

1. 用户选择源服务并打开复制弹窗，选取另一个有访问权限的项目，确认后在目标项目获得完整且独立可编辑的应用、版本、组件和服务配置，并切换目标项目、跳转至新服务详情。
2. 源服务有多个版本；弹窗默认选择最新版本，用户可以改选全部版本。最新模式复制最新版本及组件，目标服务绑定该版本；全量模式复制所有版本及组件，目标服务绑定源服务当前版本的对应副本。
3. 源配置含 Windows 部署目录及挂载路径；复制弹窗按目标工作区计算并允许编辑部署目录，挂载路径、Service 环境值、`${KEY}` 引用及显式组件覆盖仍原样保留。
4. 目标已有冲突资源，复制失败并明确提示冲突，源与目标已有资源均不变。
5. 复制过程中写入失败，整体回滚，不留下只有应用或部分版本的残缺副本。

## Acceptance criteria / 验收标准

- A01：提供复制入口及目标项目、版本范围选择；版本范围默认“最新版本”，并允许选择“全部版本”。仅支持复制到其他有访问权限的项目；目录按目标环境生成且允许编辑，不要求重新填写名称、编码或其他配置。
- A02：目标创建新的应用及所选版本和组件，生成独立 ID，并正确映射应用、版本、组件和服务之间的内部引用；只复制最新版本时目标服务绑定该副本，复制全部版本时目标服务绑定源服务当前版本对应的副本；不继续绑定源项目定义。
- A03：业务配置完整保留，包括 Service 环境值、Version 中的 `${KEY}` 引用、组件声明、受控文件内容及组件覆盖；未设置和显式空值等既有语义保持一致，不展开继承值替代覆盖定义。服务部署目录使用弹窗按目标环境计算并经用户编辑确认的值，保存目标环境修订；源实际运行目录不带入目标。
- A04：服务编码及应用名称、编码的目标项目唯一性约束得到满足；发生冲突则拒绝整个复制，不覆盖、不自动改名、不复用已有应用或服务。
- A05：校验当前用户对源、目标项目的权限；复制作为一个事务完成，失败不留下部分资源。
- A06：源资源保持不变；目标服务未部署，不复制运行状态或部署历史，不触碰数据库与文件数据，不触发路由或环境操作。
- A07：复制保留已有环境值与凭据，不自动改写或生成；消息、错误和日志不得泄露凭据。
- A08：相关后端主要流程、冲突、权限及事务失败边界得到检查；前端遵循现有共享控件与轻量单测约定，运行项目要求的 lint、typecheck 和 Go 检查。

## Workload and decomposition / 工作量与拆分

- 工作量与复杂度：中等，涉及后端应用层编排、HTTP 协议与生成代码、前端 API 和详情页弹窗。已有完整定义读写能力可复用，无需另建数据迁移流程。
- 主要风险：漏复制版本或配置、引用仍指向源项目、冲突后留下部分副本，以及误把运行资源当作配置复制。
- Plan 需核对版本来源关系、组件关联引用与现有定义创建行为，确定唯一性检查、事务边界和复制后的页面反馈。
- 按用户要求拆为后端复制能力、前端入口与弹窗两个任务。后端交付固定接口、生成类型和事务行为，前端依赖该交付接入；二者分别承担 A02–A07 与 A01，A08 按各自边界检查，整体一致性在 Verification 核对。不为简单字段映射另建任务，不启动子 agent。

## Questions and decisions / 问题与决策

已确定：

- 复制版本范围由用户选择，默认最新版本，也可复制全部版本；两种模式均复制应用、组件及服务配置。
- 最新模式只复制最新版本及其组件，目标服务绑定此版本；全量模式复制全部版本并绑定源服务当前版本的映射。
- 配置是否适用于目标环境，由用户在复制后编辑决定；复制流程只计算目标服务部署目录，不改写其他业务配置，不承担部署。
- 弹窗选择目标项目及版本范围、确认可编辑目录，遇到冲突拒绝，不引入自动命名或合并分支。
- Service 环境值仍归 Service 管理，Version 保留已有占位引用；不将具体值写入版本声明。

待明确：

- 暂无。服务详情入口、版本范围及实施计划均已确认。

## Risks / assumptions / 风险 / 假设

- 原样复制的宿主机路径、端口和业务连接配置可能不适用于目标环境。这是预期行为，不在复制阶段增加适配或部署预检查。
- 名称冲突按当前模型落到应用名称、应用编码及服务编码；不为服务新增名称字段。
- 仅复制配置中的文件内容和引用，不承诺目标环境已存在所引用的外部文件、镜像或数据库数据。
- 信任项目内部已有类型和持久化契约，不为复制引入重复规范化、兜底或兼容逻辑；保留权限、唯一性和真实外部输入边界的校验。
