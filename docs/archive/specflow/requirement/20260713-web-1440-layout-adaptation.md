# Web 1440 中等屏布局适配
最后修改时间: 2026-07-13 23:19:12

Review status: Accepted

## Background

项目 Web UI 在 1440px 一类中等桌面屏幕上需要检查主要页面的可用宽度、列表密度、详情页分栏和工具栏换行表现，避免出现横向挤压、内容溢出或主操作区被压缩的问题。

## Goal

- 检查主要页面在 1440px 宽度下的布局表现。
- 优化中等桌面屏幕下的页面内容宽度、分栏断点、工具栏与表格容器，使信息可扫描且不会异常溢出。
- 保持移动端与大屏桌面既有体验不被破坏。

## Non-goal

- 不重做视觉风格或导航体系。
- 不改动业务接口、权限逻辑和数据模型。
- 不引入新的 UI 组件库。

## User scenarios

- 用户在 1440px 宽度桌面屏中浏览 CI/CD 列表页，工具栏和表格应保持稳定、可滚动、可扫描。
- 用户打开详情页时，主内容与侧栏或辅助信息区应按可用宽度合理排布，避免内容区域过窄。
- 用户在中等屏下使用顶部导航、侧边栏和主内容区时，不应出现明显遮挡或水平页面滚动。

## Acceptance

- 1440px 宽度下主要页面没有页面级水平溢出。
- 列表页工具栏、搜索框、筛选框和操作按钮在中等屏下排布紧凑且不相互遮挡。
- 详情页的多列布局在 1440px 宽度下合理降级或收缩，长内容区域可在自身容器内滚动。
- `yarn build` 或项目等价前端检查可以通过。
- 使用浏览器对代表性页面做 1440px 视觉复查。

## Open questions

- 暂无需要用户确认的未决事项。

## Decisions

- 采用轻量模式 / light。
- 本轮按用户“新任务直接开始”的要求，将 requirement 视为已接受并进入实现。

## Risk

- 部分页面依赖后端数据或登录态，视觉复查可能需要使用本地开发环境的默认账号或 mock 数据。
- 如果已有页面使用大量固定宽度列，优化需要优先控制容器滚动，而不是强行压缩数据列导致可读性下降。
