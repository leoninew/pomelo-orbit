# 核心概念

先区分三件事：**资源如何组织、应用如何声明、一次操作如何执行**。项目和环境回答资源归属与执行位置；应用版本回答要运行什么；服务和部署记录回答运行绑定及某次操作的结果。

本文沿用界面的业务术语，不是数据库字段或 API 参数参考。产品定位和工作区入口见[项目概览](../getting-started/overview.md)。

## 项目与执行环境

**项目（Project）**组织成员和业务资源。业务应用、应用流水线、服务及相关执行记录属于项目；切换项目时，不应将另一个项目的业务资源当作当前上下文。

**环境（Environment）**是项目唯一的 Docker Compose 执行目标，保存本机或 SSH 目标、工作区等信息。这里的环境不是一个应用版本，也不是服务名。项目初始化围绕环境及关联网关进行准备。

环境 Probe 用于诊断，不能替代真正执行时的目标、凭据和主机指纹校验。尤其不能因为 SSH 失败，就假定操作会退回本机执行。

不是所有资源都归项目私有：仓库、仓库凭据以及全局流水线和阶段模板用于跨项目复用。共享作用域也不代表任何用户都拥有相同的操作权限。

用户和系统角色属于实例；角色权限与项目成员关系分开检查。创建用户不自动加入项目，系统角色也不自动授予全部项目访问。成员和角色操作见[用户、权限与访问令牌](../guides/users-access.md)。

## 仓库身份、环境身份与访问令牌

| 名称 | 用途 | 不要混淆的边界 |
| --- | --- | --- |
| 仓库（Repository）与仓库凭据 | 表示源码来源，以及访问远程仓库所需的身份 | 是跨项目共享资源，不是某个项目的 SSH 执行身份 |
| 环境凭据（Environment Credential） | 保存某个 SSH 环境当前受管的连接凭据 | 归属环境，与仓库凭据分开；保存环境后还需显式初始化凭据 |
| 个人访问令牌 | 用于 MCP、CLI 等已有自动化入口的身份认证 | 对应用户身份和权限，不是 Git 密码或 SSH 私钥 |

这些凭据不能互相替代。展示、复制或配置凭据时，也不要把真实密钥、令牌或会话内容放进文档、问题反馈和公开日志。

接入方式和当前认证支持见[仓库与仓库凭据](../guides/repositories-credentials.md)。凭据类型可以保存，不等于流水线执行器已经支持该类型。

个人 PAT 与浏览器 JWT 不互换，也没有每令牌只读或项目范围。查看、有效期、撤销及自动化认证边界见[用户、权限与访问令牌](../guides/users-access.md)。

本地 MCP 以项目 ID 选择当前连接的上下文，环境 CLI 以精确项目编码定位 SSH 目标；两者都不从浏览器继承当前项目。接入前提和最小读取路径见[MCP 与 CLI](../reference/mcp-cli.md)。

应用内的[部署对话](../guides/deployment-dialogue.md)则使用当前 Web 用户，每轮绑定请求项目的内存 MCP，不要求个人 PAT。历史属于项目、不是创建者私有；对话可以触发真实工具，不是独立的只读建议层，也不能用删除会话撤销业务。

## 流水线、运行与制品

- **流水线模板和阶段模板**用于复用构建定义。模板本身不是可以直接运行的应用流水线。
- **应用流水线（Pipeline）**属于项目，关联应用和仓库，并保存自己的执行定义。它与作为来源的模板不是同一个对象。
- **运行记录（Run）**对应一次具体执行，关联使用的流水线定义快照，并保存执行状态、日志及输出信息。当前编辑器中的定义不能代替历史运行的快照。
- **制品（Artifact）**记录一次构建的输出。对已配置组件映射的镜像制品，可以形成新的应用版本；有制品不等于该版本已经部署。

因此，修改模板、执行流水线、生成应用版本和部署服务是不同动作，不应把其中一步成功理解为整个交付链路成功。

CI 的 Liquid 变量与 Service 环境变量属于不同层次，不会同名自动传递。取值优先级、精确占位符以及组件继承 / 覆盖 / 删除的区别见[变量与 Compose 约束](../reference/variables-compose.md)。

具体操作见[流水线与制品](../guides/pipelines-artifacts.md)，其中区分模板复用、当前配置重试、运行快照与制品到应用版本的条件。

## 应用、版本与组件

| 对象 | 解决的问题 | 示例 |
| --- | --- | --- |
| 业务应用（Application） | 这一组可部署内容是什么 | 订单系统 `orders` |
| 版本（Version） | 这一版应用的静态部署定义是什么 | `v1.0` 中使用的组件镜像及其配置 |
| 组件（Component） | 版本中一个 Compose 容器声明是什么 | `api` 和 `redis` 两个组件 |

版本描述镜像、变量声明、挂载、端口和组件依赖等内容。组件是版本定义的一部分，不是一次运行操作，也不是后文中管理整个应用运行绑定的 Service。

业务应用属于项目。网关等系统托管对象也复用应用及版本机制，但不应把内部托管定义误认为可以任意跨项目使用的业务应用。

## 服务与部署记录

**服务（Service）**是一个应用的运行绑定：选择版本，保存运行配置覆盖和部署目录，并跟踪运行状态。一个应用可以有多个服务绑定；每个服务选择自己的版本和配置。

例如，同一个项目中的 `orders-main` 选择订单系统 `v1.0`，`orders-preview` 选择 `v1.1`。两者是不同的服务绑定，并不是给项目创建了两个 Environment；它们仍需分别安排部署目录、端口等运行资源。

**部署记录（Deployment）**对应一次部署、重启或停止操作，记录当次冻结的目标和输入、状态、日志及错误。它不是另一个长期运行实例。服务可以经历多次操作，每次操作留下自己的记录。

常见区别：

- 保存或修改版本定义，不等于已经改变运行中的容器。
- 服务选择某个版本，不等于对该版本的部署已经成功。
- 操作请求已受理，不等于后台执行已经完成。
- 某条历史部署记录成功，不等于它就是服务的最新状态；判断当前结果还需要查看最新相关操作及服务状态。

## 网关、路由与 DNS

**网关（Gateway）**关联环境中的 Traefik 运行配置，为应用流量提供入口。**路由（Route）**描述 HTTP 或 TCP 流量如何进入目标，例如域名、路径和目标地址等条件。

**DNS 记录**解决域名到地址的解析问题。DNS 与 Traefik 路由属于不同层次：新增一条 A 记录不会自动部署服务，也不会自动创建流量路由。Cloudflare DNS 管理使用当前环境网关配置的 Token，其可见 Zone 受 Token 权限限制，也可能由多个环境共享。

组件的 `gateway` 端点随业务服务部署生成入口；自定义路由保存后还需显式同步。两者都不自动配置客户端 DNS 或证明业务访问成功，具体操作与检查见[网关、DNS 与路由](../guides/gateway-dns-routes.md)。

理解对象关系后，按[项目与执行环境](../guides/projects-environments.md)准备执行目标，再按[应用、版本与服务](../guides/applications-services.md)配置并部署应用；需要构建源码时，先接入[仓库与仓库凭据](../guides/repositories-credentials.md)。
