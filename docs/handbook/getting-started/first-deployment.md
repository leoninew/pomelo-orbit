# 部署首个应用

通过部署对话，请模型在当前项目中部署 NGINX，并通过自定义路由访问 `nginx.lvh.me`。本例不需要仓库、流水线、Cloudflare DNS 或证书。

## 准备

1. 完成[自托管运行](./installation.md)，登录并修改初始密码。
2. 在“系统管理 → 系统设置”配置支持工具调用的模型地址、API Key 和模型名，并按提示重新加载配置。具体字段见[启用模型](../guides/deployment-dialogue.md#启用模型)。
3. [创建项目](../guides/projects.md)，在初始化向导中配置本机或 SSH 执行环境，检查 Docker 和 Compose。填写并保存网关定义，按[网关部署步骤](../guides/gateway.md#部署与验证)完成部署，确认网关的 HTTP 入口可通过执行主机的 80 端口访问。
4. 确认执行主机能拉取可信的 NGINX 镜像。若使用其他镜像，在下面的对话中替换。

当前对话部署工具默认将服务加入 Traefik 网络，因此需要先部署网关以准备该网络。NGINX 的 80 端口使用 `internal` 模式，不直接映射宿主机端口；网关通过自定义路由转发请求。网关默认将 80 和 443 绑定到所有网卡，应按实际网络限制访问。

选择项目，打开“持续部署 → 对话”，点击“新对话”。当前用户需要是项目成员并具有对话权限；无需另外创建个人访问令牌。

::: warning 对话会执行真实操作
模型调用工具可能直接创建、修改或部署资源。提示模型先检查、等待确认有助于沟通，但不是强制只读或审批机制；发送前确认项目、权限和允许的操作范围。
:::

## 第一轮：确认方案

**你：**

> 请检查当前项目的执行环境，并准备部署一个 NGINX 示例。应用编码为 `hello-web`，服务编码为 `hello-web-main`，组件名为 `web`，镜像使用 `nginx:1.27-alpine`。
>
> 将组件的 HTTP 80 端口设置为 `internal`，不要直接映射到宿主机。创建 HTTP 自定义路由 `nginx-route`，域名为 `nginx.lvh.me`，路径为 `/`，目标是服务 `hello-web-main` 的 `web` 组件 HTTP 80 端点。
>
> 不创建 DNS 记录、证书或数据卷，也不要修改其他应用、服务和路由。
>
> 请先检查环境、同名资源及域名是否冲突，列出准备创建的资源和部署目录，暂时不要创建或部署。如果发现冲突，请停下来说明。

**助手回复示例，具体以实际结果为准：**

> 我会创建应用 `hello-web` 和服务 `hello-web-main`，使用 `nginx:1.27-alpine`，将组件 HTTP 80 端口设为 `internal`。自定义路由 `nginx-route` 将 `nginx.lvh.me` 指向该端点。建议的部署目录为 `/app/data/projects/first-example/deployment/hello-web-main`，请确认执行环境和目录。

核对模型查询到的目标、镜像和完整部署目录。使用[自托管运行](./installation.md)中的 Docker 示例时，目录可为 `/app/data/projects/first-example/deployment/hello-web-main`；其他环境使用其工作目录下的对应路径。

## 第二轮：部署

确认方案无误后，在同一对话中发送。以下路径对应自托管运行的 Docker 示例，使用其他工作目录时先替换为实际路径：

**你：**

> 确认刚才的方案，部署目录使用 `/app/data/projects/first-example/deployment/hello-web-main`。请创建应用、发布版本并创建服务，检查服务预览后部署并等待结果。然后创建停用状态的 `nginx-route`，仅预览启用该路由的同步，不要同步其他路由。请返回部署记录编号、最终状态和路由同步预览，等待我确认。

模型会根据工具结果继续操作；回复内容和工具调用顺序可能因模型而异。若模型询问部署目录或其他缺失信息，补充已核对的实际值。

## 第三轮：发布路由

核对同步预览：只包含 `nginx-route` 的启用，域名为 `nginx.lvh.me`，目标为 `hello-web-main` 的 `web` 组件 HTTP 80 端点。确认后发送：

**你：**

> 确认刚才预览的 `nginx-route` 同步，请发布该路由并返回同步结果。不要修改或同步其他路由。

路由预览失效或同步失败时，先检查实际状态，重新预览并确认；创建路由本身不会使其生效。

## 验证结果

1. 根据回复中的部署记录编号，在“持续部署 → 部署”检查本次记录和日志，确认已成功结束。
2. 在服务详情确认 `web` 容器正在运行，实际镜像和 HTTP 80 `internal` 端点与预期一致；在“自定义路由”和“Traefik 路由”确认路由已同步并加载。
3. 在 Docker 执行主机上访问网关，保留请求域名：

```bash
curl --fail --show-error --resolve nginx.lvh.me:80:127.0.0.1 http://nginx.lvh.me/
```

应返回 NGINX 欢迎页面。`--resolve` 将本次请求的域名指向执行主机的回环地址；浏览器使用 `http://nginx.lvh.me/` 时，域名也必须解析到能访问网关的地址。浏览器与网关不在同一电脑时，`127.0.0.1` 指向浏览器所在电脑，需配置安全的转发或解析。

如果对话超时、断流或没有最终回复，先检查已发生的工具调用及[部署记录](../guides/deployments.md)，不要直接重复提交。模型返回失败或访问异常时，查看部署日志和[故障定位](../operations/troubleshooting.md)。

结束练习时，先停用并同步撤下 `nginx-route`，再停止 `hello-web-main` 并保留 volumes；检查同步和停止结果。更多对话能力与限制见[部署对话](../guides/deployment-dialogue.md)。
