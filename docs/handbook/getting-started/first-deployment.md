# 首个应用部署

本文用一个无状态 HTTP 服务走通最短部署路径：创建项目 → 准备环境 → 声明应用版本 → 创建服务 → 预览与部署 → 检查访问。直接使用已有镜像，不需要先配置仓库、流水线、LLM、DNS 或证书。

本文适用于 `develop` 分支，建议在隔离 Docker 主机上操作。完成的标准是你能核对**本次部署记录、容器状态和实际 HTTP 响应**，不是页面上出现了一个服务。

## 开始前准备

- 已完成[自托管安装](./installation.md)，能够登录且已替换初始管理员密码。
- 有可用的 Docker / Compose 执行目标，知道平台程序、Docker daemon 和浏览器分别在哪台机器上。
- 准备一个可信、架构匹配且目标已确认能拉取的 Nginx 镜像，使用固定标签或 digest；要求默认提供 HTTP 页面、监听容器 `80`、无需额外秘密或数据挂载。下面的“你的镜像引用”必须换成真实值，不是可直接部署的镜像名。
- 执行目标的回环端口 `18080` 空闲；被占用时选择另一个空闲端口，并同步调整后文的访问地址，不停止未知服务。

首次练习不使用数据库、持久化卷或生产服务，不用公网端口检验是否部署成功。若你的镜像监听其他端口、需要认证或依赖额外组件，应先按镜像要求调整，而不是照抄本例。

## 1. 创建独立项目并保存环境

1. 打开“系统管理 → 项目”，创建名称“首次部署”、编码 `first-example` 的项目，然后确认当前项目已切换到它。
2. 进入“环境”或初始化向导，选择“本机”。这里的本机是 **Orbit 后端运行侧**，不是浏览器电脑。
3. 按安装方式填写独立工作目录：

| 安装方式 | 本例目录 |
| --- | --- |
| 使用安装篇的 Linux Docker Compose | `/app/data/projects/first-example`，位于已有持久化挂载内 |
| 原生程序包 | 由你准备的、程序执行用户可写的绝对路径，例如 Linux 的 `/srv/orbit-projects/first-example` |

4. 保存后运行“检查连接”，阅读结果与时间；失败时先处理 Docker、Compose、路径和权限，不直接进入部署。
5. 本例不使用 SSH。需要远程执行时先按[项目与执行环境](../guides/projects-environments.md)完成 SSH 初始化、可信主机指纹和探测，再按远端平台重选工作目录。

项目只有一个 CI/CD 共用执行目标。不要在已有项目上修改目标来练习；改环境不会迁移旧主机上的容器和数据。

## 2. 完成项目初始化，但先不部署网关

继续到“准备网关”，核对并创建关联网关定义。当前项目初始化需要网关及其服务记录，即使第一次业务访问不经过网关也要完成此步。

本例使用 HTTP、本地端口访问，不申请证书、不写 DNS：

- 网关镜像填写你准备使用的可信 Traefik 镜像；本步骤仅保存定义，不拉取或部署它。
- 默认入口选 `web`，TLS 选 `none`，ACME 不启用，外网域名、邮箱和 DNS Token 留空。
- 内网域名只用于后续派生入口。可为隔离示例使用 `example.test`，它不会自动解析；本例不依赖该域名访问。
- 管理 API 地址按实际执行位置填写。暂未部署网关时不宣称地址可达；以后使用网关需按[网关、DNS 与路由](../guides/gateway-dns-routes.md)核对网络及管理地址。

创建完成后进入业务应用页面。**先不点击网关部署**；后面的业务服务选择不加入 Traefik 网络，因此不需要运行中的网关。不要将“初始化完成”理解为网关已运行。

## 3. 创建应用并配置初始版本

1. 打开“持续部署 → 应用”，创建名称“示例网站”、编码 `hello-web` 的普通应用。
2. 进入自动生成的初始未发布版本，添加一个组件：

| 字段 | 本例填写 |
| --- | --- |
| 组件名 | `web` |
| 镜像 | 你的已确认 Nginx 镜像引用 |
| 拉取策略 | 按镜像供应方式选择；目标已有固定镜像时可选 `missing`，需要每次拉取时可选 `always` |
| 重启策略 | `unless-stopped` |
| 入口、命令 | 保留镜像默认，不额外覆盖 |

3. 保存后进入组件详情，在端口 / 暴露配置中添加一个端点：协议 `http`、暴露模式 `local`、容器端口 `80`、宿主端口 `18080`。
4. 本例不添加环境变量、挂载、依赖或自定义健康检查。保存端点，回到版本点击“预览”。
5. 确认镜像和容器端口正确，宿主端口绑定为回环地址 `127.0.0.1:18080`，没有误加数据卷、秘密或公网绑定，再发布版本。

`local` 表示执行目标的回环端口，不是 Orbit 容器自己的 Web 监听端口。不要改成 `host` / 全接口暴露来解决浏览器跨机器访问问题。发布版本只冻结定义，不会拉取镜像或创建容器。

## 4. 创建服务并预览实际配置

1. 打开“持续部署 → 服务”，创建服务，选择 `hello-web` 应用、刚发布的版本，编码填写 `hello-web-main`。
2. 进入服务详情，核对所选版本。新服务尚未运行，本例不需要填写 Service 环境变量或组件覆盖。
3. 点击服务“预览”，选择**不加入 Traefik 网络**；检查实际镜像、回环端口及无数据挂载的配置。若已有预览选项仍加入网关网络，调整后重新预览。
4. 预览报错时先修正配置，不连续点击部署。版本预览与服务预览不同，后者需要包含该服务的运行选择和覆盖。

变量、挂载和覆盖的更多规则见[变量与 Compose 约束](../reference/variables-compose.md)。本例刻意不用它们，先确认最小运行链路。

## 5. 提交部署并等待本次结果

1. 点击服务的“部署”，再次核对版本和目标。
2. Docker 安装主路径使用目录 `/app/data/projects/first-example/deployment/hello-web-main`；原生或 SSH 路径改成你实际环境工作目录下的独立服务目录。不要使用平台安装根目录、系统根目录或已有服务的数据目录。
3. **取消“加入 Traefik 网络”**，使本次执行与预览一致。按准备镜像的方式确认拉取策略，首次部署无需勾选强制重建。
4. 提交后打开对应的部署记录，记下编号，核对服务、版本和工作目录；等待结束并阅读日志。
5. 进入服务详情查看 `web` 容器是否存在、处于运行状态，实际镜像是否符合预期；退出或不断重启时查看该容器日志。

“任务已创建”不是成功。如果任务长时间等待，先让实例维护者核对执行进程和队列；镜像、端口或目录错误应依据本次日志处理，不通过删除服务或更换目录试探。

## 6. 从执行目标检查 HTTP 响应

在 Docker 执行主机上访问：

```sh
curl --fail --show-error http://127.0.0.1:18080/
```

预期返回该镜像的页面内容；核对内容来自本次示例，而不是同端口的其他服务。浏览器在同一主机时也可打开该地址；不在同一主机时使用已有安全通道转发这个回环端口，不临时开放公网。

| 检查 | 应保留的结果 |
| --- | --- |
| 本次部署 | 对应编号成功结束，版本与目录正确，日志无执行失败 |
| 当前容器 | `web` 正在运行，镜像正确；未设置健康检查时不要期待一定显示 `healthy` |
| 实际访问 | 执行主机回环端口返回预期页面，而非仅建立了 TCP 连接 |

只有这三层都符合预期，才算走通本例。容器运行但访问失败时按[故障定位](../operations/troubleshooting.md)检查监听端口、映射和业务进程；此路径不经过 DNS、Traefik 或 TLS，不需要先改它们。

## 结束练习或继续使用

- 要保留示例，可以保持服务运行并记录本次版本和部署编号。
- 要停止，使用服务的“停止”，**不勾选删除 volumes**，等待本次停止记录结束，确认容器不再运行。虽然本例没有声明数据卷，也不要养成默认删卷的习惯。
- 删除停止后的服务和不再使用的应用记录，不等于清理所有执行目录或外部资源；如需清理文件，先核实实际路径与归属，不删除整个项目或平台数据目录。
- 需要对外域名时，再按[网关、DNS 与路由](../guides/gateway-dns-routes.md)部署网关、调整网络和入口；需要从源码构建镜像时，再接入[流水线与制品](../guides/pipelines-artifacts.md)。

后续版本更新、配置变更及运行覆盖的完整操作见[应用、版本与服务](../guides/applications-services.md)。给有状态服务增加数据库或卷之前，先阅读[数据保留与升级](../operations/data-upgrades.md)。
