# 项目概览

Pomelo Orbit 是面向 Docker Compose 工作流的自托管 CI/CD 平台。它把代码构建、应用版本、服务运行和网络入口放在同一个管理界面中，支持本机和 SSH 环境中的 Compose 部署。

本文帮助你判断产品是否适合当前场景，并认识主要工作区。对象之间的具体关系见[核心概念](../concepts/core-model.md)；本文不是安装或业务部署教程。

## 适用场景

- 使用 Docker 镜像和 Compose 组织应用，希望集中管理应用版本、运行配置及部署记录。
- 希望把仓库构建的镜像制品与应用组件关联，减少构建输出和部署定义之间的手工衔接。
- 需要管理本机或 SSH 执行目标，并通过 Traefik 网关及路由组织应用入口。

项目以 Compose 为主要部署模型，不以 Kubernetes 或多集群编排为主要使用路径。可管理某类资源不等于当前环境已经具备执行条件：Docker、SSH、仓库身份、网络和相应权限仍需按实际环境准备。

## 从源码到运行服务

可以把主要工作流理解为四个环节：

1. **确定项目与执行环境。** 项目组织成员和业务资源；环境保存本机或 SSH 目标及工作区。仓库和仓库凭据是跨项目共享资源，与环境 SSH 凭据分开管理。
2. **按需构建镜像。** 应用流水线绑定仓库，执行后留下运行记录和制品。对配置了组件映射的镜像制品，可以形成新的应用版本。
3. **声明应用版本并配置服务。** 版本描述组件镜像、变量、挂载和端口等内容；服务选择要运行的版本，并保存该运行绑定的配置覆盖和部署目录。
4. **执行并检查结果。** 部署、重启或停止操作留下独立的部署记录。通过操作结果、日志和服务运行状态判断本次执行，而不是仅凭请求已受理或配置已保存判断成功。

流水线不是部署已有镜像的强制前置步骤。应用也可以直接使用已有镜像声明版本，再配置服务；构建与部署是相关但不同的环节。

网络入口是另一层配置：网关和路由负责流量进入服务的方式，DNS 管理负责域名记录。保存 DNS 记录不等于创建路由，也不等于服务已经部署。

## 三个主要工作区

| 工作区 | 主要内容 | 适合处理的问题 |
| --- | --- | --- |
| 持续集成 | 仓库、仓库凭据、流水线、阶段、运行记录和制品 | 使用什么源码和构建定义，某次构建执行了什么、产生了什么 |
| 持续部署 | 应用、版本、服务、部署记录、部署对话，以及网关、DNS 和路由 | 运行哪个版本，本次操作结果如何，应用入口如何配置 |
| 系统管理 | 项目、执行环境、用户、角色、登录历史、访问令牌和系统设置 | 资源属于哪个项目，在哪执行，谁可以操作，以及实例如何配置 |

部分页面和操作取决于当前项目状态及登录用户权限。部署对话还需要相应的 LLM 配置；它不是创建应用版本或配置服务的必经入口。
