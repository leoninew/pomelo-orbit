# 部署对话

部署对话让模型通过平台提供的 MCP 工具查询或修改当前项目资源。它不是纯聊天帮助，也不是部署已有应用的必经入口；手工操作路径见[应用、版本与服务](./applications-services.md)。

本指南适用于 `develop` 分支。下文消息仅说明如何表达操作范围；使用前需确认模型配置、当前项目以及允许外发的数据。

## 开始前

- 已有可用实例并已登录，明确选中要操作的项目，当前用户属于该项目。
- 查看历史需要 `dialogue:read`，发送、继续及删除需要 `dialogue:write`；从当前页面完整使用通常需要两者。菜单可见不等于有操作权限，角色与成员关系见[用户、权限与访问令牌](./users-access.md)。
- 维护者已准备并启用可用的模型配置，确认工具调用能力、数据处理约定及费用承担；没有配置时仍可查看已有历史，发送会提示对话服务未配置。
- 若准备执行业务，先按[项目与执行环境](./projects-environments.md)准备目标、凭据和目录；网关相关工具还需相应网关记录及配置。打开对话页面并不证明 Docker、SSH 或网关已运行。

**发送消息后可能直接执行真实工具，当前没有通用的逐项二次确认或强制只读开关。** 不要在生产项目试验含糊的需求，也不要把“先看看”“只给建议”当作服务端权限隔离。

## 维护者准备 LLM 配置

当前连接器向配置的基础地址追加 `/chat/completions`，发送消息和工具定义，并处理模型返回的工具调用。供应商需兼容这套请求、消息和工具结果格式；一个接口能返回普通文本，不等于它能完成工具循环。本文不提供已验证的模型或供应商清单。

| 系统设置键 | 用途及约束 |
| --- | --- |
| `llm__base_url` | 供应商基础地址，不是完整的 `/chat/completions` 地址；优先使用可信 HTTPS 端点 |
| `llm__api_key` | 供应商认证秘密，不是 Web JWT 或个人 PAT，不在对话里填写 |
| `llm__model` | 供应商认可且支持所需工具调用的模型标识 |
| `llm__timeout` | 每次模型 HTTP 请求的超时；当前仓库默认 `60s`，启用配置时必须为正 |
| `llm__max_tool_call_rounds` | 单轮用户消息的模型循环上限；当前仓库默认 `64`，至少为 `1` |

基础地址、API Key、模型须成组配置，三者全部未填表示未启用，只填一部分会被配置校验拒绝。启动配置和应用覆盖可能改变默认值，以实例当前生效值为准。

在“系统管理 → 系统设置”中处理时，查看需要 `setting:read`，修改需要 `setting:write`。从空配置启用时，先编辑三项，再一起保存；不要逐个提交尚不完整的组合。保存后检查返回状态和重启提示：页面当前值仍代表该进程运行值，没有独立的待生效值列。由维护者按运行安排使后端重新加载，再核对实际配置，**不是刷新浏览器就生效**。本文不要求实际修改或重启。

也可通过可信的启动配置提供相应 `POMELO_ORBIT_LLM__*` 环境值；来源优先级、批量保存和重置语义见[配置与密钥](../operations/configuration.md)。不要把真实 API Key 放进受版本控制文件、命令参数、截图或问题反馈。

### 先确认数据可以外发

当前模型请求包含对话上下文和工具定义，后续请求还会包含工具参数与结果。资源详情、预览、运行日志或诊断中可能出现敏感信息；不能假定平台会在交给模型前自动脱敏。

选择符合组织要求的端点和模型，只发送允许外发的内容。页面遮罩、模型回答中的隐藏提示或删除本地历史，都不构成供应商侧的数据清除、保密或费用保证。

## 理解身份与项目范围

应用内对话使用当前 Web 登录身份，不要求另启本地 MCP 进程，也不需要把个人 PAT 交给模型。

一次对话请求只操作当前选定项目，不能靠一句“切到另一个项目”改变。需要换项目时，先等当前操作结果明确，再从页面切换并重新核对。**页面切换或关闭不等于取消旧请求，更不会回滚已受理部署。**

继续其他成员创建的历史时，执行身份是当前发送者，不是会话创建者。工具仍按实际资源及成员规则校验；拥有对话权限并不证明目标、镜像或业务配置正确。外部 MCP 的 PAT 和手工项目选择规则见 [MCP 与 CLI](../reference/mcp-cli.md)，不要直接套用到应用内对话。

## 新建、选择和继续对话

1. 打开“持续部署 → 对话”，再次核对当前项目。历史按项目列出，页面通常打开最近更新的一项，不要直接在旧对话中输入就假定这是新任务。
2. 需要独立上下文时点击“新对话”；选择已有历史可继续。窄屏可从历史按钮打开列表，不要求一直显示侧栏。
3. 输入精确目标、资源标识、允许的范围和明确的禁止事项，发送前自行确认这些内容可以被模型和有权限的项目成员看到。
4. 点击发送或按 Enter 提交，等待当前轮完成；不要重复点击或在另一页面同时发相同操作。新对话不是配置副本，也不是独立执行环境。
5. 观察工具活动和回答，再回到资源页面核对当前配置与本次操作记录；旧回答不能代替最新状态读取。

首次使用时，可以在隔离项目按下面的方式说明读取目标。**这只是消息示意，文字约束不是强制只读模式：**

> 请只列出当前项目已有应用的 ID、编码和名称。不要创建或修改资源，不执行部署、探测、网络同步或清理；缺少信息时直接说明。

预期观察的是当前项目和工具返回的资源标识，而不是模型自行编造一张清单。即使工具只列出空结果，也可能是正常情况；不要为了得到非空回答要求它创建示例资源。

## 区分活动、回答和实际结果

页面在请求进行中显示“思考中”及工具的执行 / 完成 / 失败活动，回答下可展开本轮工具结果。当前流式输出主要报告这些活动和最终回答，不是逐字输出模型文本。

| 观察到的内容 | 可以说明什么 | 还要核对什么 |
| --- | --- | --- |
| 工具开始 | 模型选中了一个调用，后端开始处理 | 是否被防护或业务校验拒绝，不能据此判断资源已改变 |
| 工具完成 | 收到了该工具的结果 | 结果中的错误、资源标识和状态；“完成”不等于部署成功 |
| 对话最终回答 / 流完成 | 当前交互返回了一段结果 | 可能是部分结果说明，不保证本轮已保存或所有目标已完成 |
| 返回 `deployment_id` | 已创建相应操作记录 | 本次部署状态、日志、容器及业务入口 |
| 等待返回 | 已观察到终态，或达到等待上限 | 同时检查 `timed_out` 和部署状态；终态也可能失败 |

部署需要已管理的执行进程处理，模型循环和等待工具都不替代 Worker。拿到部署 ID 后，按[应用、版本与服务](./applications-services.md)检查本次记录、当前容器和业务响应；网络访问另按[网关、DNS 与路由](./gateway-dns-routes.md)分层检查。

### 当前单轮防护的范围

遇到回读、预览或重复部署提示时，按以下顺序处理：

- 修改版本组件后，先要求重新读取并核对版本，再部署。
- 创建服务或修改其配置后，先预览并确认服务；预览不证明运行侧可用，变量填写见[变量与 Compose 约束](../reference/variables-compose.md)。
- 同一轮已经成功提交某个服务的部署时，不重复提交；下一轮、其他会话或外部客户端仍可能重复操作，需自行核对。
- 得到部署记录后检查等待结果；等待可能超时，**不代表一定等到部署成功**，继续查看该部署记录。

平台会对部分操作顺序作检查，但不要把这些提示当作覆盖全部路径的强制审批、重复操作保护或失败回滚。一个工具失败后，模型仍可能继续后续调用，不应将其视为整轮立即停止。

需要实际变更时，先明确版本、服务、当前值和目标差异；更换版本必须先更新服务绑定，部署使用服务当前保存的版本。集合类写入可能替换整个集合，不能只发一个新增项就假定其他内容自动保留。不要让模型通过清空数据卷、改密码或删除资源来试探配置。

## 历史不是私有聊天或完整审计

历史按项目而不是创建者隔离：有相应权限的项目成员可以查看、继续或删除同一项目会话。标题取自首条用户消息的前一部分，也可能暴露内容，不在消息或标题中写秘密。

正常取得最终模型回答后，系统才保存本次用户与助手消息对，并更新会话时间；继续时，Web 将当前加载的用户 / 助手消息作为上下文发送。历史不完整保存每次工具调用及结果，重新打开后不能指望恢复当前页面的全部工具详情。

模型失败、轮数耗尽、流中断或历史保存失败时，已有工具可能已经执行，但本轮未落入历史。部分执行后即使正常返回“已停止”的最终说明，也可能不保存本轮；**历史里没有记录，不等于没有操作。** 保留当页脱敏的资源和部署标识，先核对实际状态再继续。

删除时，选择相应会话并在删除对话框确认，随后核对列表。删除会移除该会话及消息，不撤销已经发生的配置、部署、DNS 或其他外部写入，也不保证供应商删除已接收内容；“新对话”同样不是清理或回滚。

## 中断与失败定位

当前 Web 对话请求的等待上限为 10 分钟，与每次模型请求的 `llm__timeout`、工具自己的等待 / 执行上限分开。`max_tool_call_rounds` 限制的是模型循环，不是工具总数、费用或完整业务耗时；一个循环可能含多个工具调用。

| 现象 | 优先检查 |
| --- | --- |
| 历史或发送被拒绝 | Web 登录、对话读写权限与当前项目成员关系，不凭菜单或角色名推断 |
| 提示未配置 | 三项 LLM 配置是否齐全、当前生效值与待重启差异；不要把 Key 粘进对话 |
| 供应商拒绝、不可用或响应格式异常 | 基础地址是否重复拼接路径、模型 / 凭据、网络和工具调用兼容；保存成功不是连通测试 |
| 工具提示项目 / 环境未准备 | 当前固定项目及该工具的环境 / 网关前提，不通过切换执行目标绕过 |
| 防护要求回读或预览 | 检查具体版本 / 服务和前序结果，不重复发部署绕过顺序约束 |
| 等待超时、网络中断或达到轮数上限 | 保留已完成工具的标识，先查看实际资源和部署记录，结果未知时不直接重发 |
| 回答出现但历史未更新 | 区分正常保存、部分结果和保存失败；保留当页证据，不假定后端没有执行 |

没有工具结果的早期失败可能直接报错；已有工具完成后可能返回部分结果说明，流中断也可能在页面保留已收集结果。反馈时附脱敏错误、可用的请求关联 ID、项目及资源 / 部署标识，不附完整会话、API Key、PAT、预览或敏感工具原始输出。
