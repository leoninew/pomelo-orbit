# DNS 解析

“DNS 解析”页面直接调用 Cloudflare，管理 A 记录。它使用当前环境[网关](./gateway.md)保存的 DNS API Token，网关容器无需运行。

## 准备 Token

为所需 Zone 授予 `Zone Read` 和 `DNS Edit`，在网关证书配置中选择含 DNS 的 ACME profile，保存邮箱和 Token。

可见 Zone 取决于 Token 权限，可能由多个项目或环境共同管理。核对 Zone 和完整记录名后再修改。

## 管理记录

1. 打开“DNS 解析”，选择 Zone 并搜索现有记录。
2. 新建时填写名称、IPv4、TTL 和代理状态。
3. 编辑时可修改 IPv4、TTL 和代理状态，名称只读。
4. 保存后重新查询，从实际客户端检查解析。删除前确认受影响的服务。

| 项目 | 当前规则 |
| --- | --- |
| 记录类型 | 仅 A 记录 |
| TTL | `1` 为自动，否则 30–86400 秒；实际可用值受上游套餐限制 |
| Cloudflare 代理 | 启用时使用自动 TTL；可代理的协议和端口受 Cloudflare 限制 |

## 写入与排障

DNS 创建、编辑和删除**立即写入 Cloudflare**，独立于路由同步。请求超时后先刷新上游记录，确认是否已写入，再决定是否重试。

| 症状 | 检查 |
| --- | --- |
| 无 Zone 或权限不足 | 当前网关 Token、Zone 授权及两项权限 |
| 记录存在但解析仍旧 | 客户端缓存、TTL、代理及实际使用的解析器 |
| 地址正确但访问失败 | [路由](./routes.md)、端口、TLS 与下游服务 |

网关 ACME 切到不含 DNS 的 profile 会清空 Token，变更前同时检查 DNS 管理的依赖。
