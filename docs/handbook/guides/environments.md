# 执行环境

执行环境保存项目的 Docker Compose 目标和工作目录。在“系统管理 → 环境”或项目初始化向导中配置。

| 类型 | 实际执行位置 | 配置项 |
| --- | --- | --- |
| 本机 | Orbit 后端运行侧 | 工作目录；平台、主机和用户由后端展示 |
| SSH | 后端通过 SSH 连接的主机 | 平台、主机、端口、用户、工作目录 |

浏览器所在电脑不决定执行位置。后端在容器中时，还要区分容器路径与 Docker 宿主机路径。

## 本机环境

选择“本机”，填写执行用户可写的工作目录并保存，然后点击“检查连接”或“探测”。执行侧需要 Docker 与 Docker Compose。

工作目录使用目标平台绝对路径或 `~/...`，例如 Linux 的 `/srv/orbit`、Windows 的 `C:\Orbit`。`~` 指执行用户的家目录。

## SSH 环境

1. 保存平台、主机、端口、SSH 用户和工作目录。
2. 点击“生成初始化命令”。没有环境凭据时生成专属密钥，已有凭据时复用。
3. 核对目标和命令内容，在目标主机执行：Linux 使用配置的 SSH 用户；Windows 使用管理员 PowerShell。
4. 点击探测，通过可信管理通道核对首次记录的主机指纹，并阅读诊断结果。

初始化命令会写入公钥、准备目录；Windows 还可能安装或调整 OpenSSH、服务和防火墙。Docker、WSL2、Docker Desktop 等条件仍需按目标平台准备。

环境 SSH 凭据只用于连接执行主机，[仓库凭据](./repository-credentials.md)用于获取源码。

## 判断是否可用

| 结果 | 下一步 |
| --- | --- |
| 探测通过 | 继续配置应用；镜像、目录、端口在具体部署时检查 |
| 缺少凭据 | 生成并执行初始化命令，检查公钥授权 |
| 认证或指纹失败 | 核对目标身份、用户和授权，再重新探测 |
| Docker 检查失败 | 检查执行用户权限、Compose 和目标平台条件 |

探测是诊断，执行时还会校验当前目标、凭据与指纹。SSH 失败直接报错。

## 初始化与变更

只做 CI 时，保存环境后即可返回流水线。业务部署还需完成向导中的[网关](./gateway.md)定义及服务记录；网关是否部署取决于业务是否使用它。

修改主机或工作目录**不会搬迁旧容器、文件和数据**。变更前明确原目标的清理与数据迁移方案；变更后重新检查目标和指纹。出现共用执行目标警告时，还需检查其他项目的端口与目录冲突。
