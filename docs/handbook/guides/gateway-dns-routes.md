# 网关、DNS 与路由

本文说明怎样准备服务的网络入口，区分网关运行、域名解析、组件入口和自定义路由，并逐层检查结果。执行目标准备见[项目与执行环境](./projects-environments.md)，业务服务的配置与部署见[应用、版本与服务](./applications-services.md)。

## 开始前

- 已有可用且已登录的实例，选中了有操作权限的项目，项目执行环境已配置；SSH 环境还需有效凭据和主机指纹。
- 知道流量应到达哪台主机、哪个服务和端点，已规划宿主机端口、Docker 网络、域名及防火墙。不要用生产域名或共享 Zone 试验操作。
- 部署网关前准备来源可信、能在目标上运行的 Traefik 镜像，确认目录、挂载和端口条件；本文不保证某个公共镜像标签可用。
- 如需管理 DNS 或申请证书，确认域名管理权限、Token 范围和变更影响。DNS 修改、路由同步及证书生成都不是只读检查。

本指南适用于 `develop` 分支。网关部署、DNS、路由同步及客户端访问需要分别检查；请先用独立测试域名与非生产目标熟悉操作。

## 先区分四层结果

| 层次 | 解决的问题 | 不能由此推断 |
| --- | --- | --- |
| 网关与运行服务 | Traefik 在项目执行侧运行，管理 API 可查询 | DNS 已传播、证书已可信、业务响应正常 |
| DNS 记录 | 客户端把域名解析到相应地址 | 网关或服务已部署、目标端口已开放 |
| 组件入口或自定义路由 | Traefik 按规则把流量转给下游 | 下游进程健康、身份认证或业务逻辑正确 |
| 客户端访问 | 从实际使用网络检查解析、TLS 与业务响应 | 其他网络、账号或所有业务路径同样可用 |

DNS 和路由没有必须互相等待的保存顺序，但实际访问需要整条链路具备条件。不要通过重复创建 DNS 记录解决容器启动问题，也不要通过重启网关绕过 Token 权限错误。

## 准备并检查网关配置

项目环境关联一个受管网关。尚未关联时，从“初始化项目”的“准备网关”填写镜像及配置；已有网关则进入“持续部署”的“网关”，检查基本信息、Traefik API、组件入口默认策略和自定义 Route 证书分组。

| 配置 | 如何选择和理解 |
| --- | --- |
| 内网域名 | 用于派生组件入口域名；填写后不会自动创建 DNS 记录或给客户端安装解析规则 |
| 外网域名 | 可选；自定义路由创建表单优先用它生成域名建议，没有时使用内网域名，不等于已取得域名控制权 |
| 容器 Traefik API URL | 本机目标且 Orbit 后端在容器中运行时使用，须从该容器执行侧可达 |
| 宿主机 Traefik API URL | 本机非容器运行或 SSH 目标使用；SSH 时在远端主机访问，不是从浏览器访问 |
| Traefik API 就绪超时 | 1–300 秒，控制网关部署后等待管理 API 的时间，不是外部访问的 SLA |
| HTTP 入口 / TLS 模式 | 组件入口默认策略；入口为 `web` / `websecure`，TLS 模式为 `none` / `tls` / `letsencrypt`，不替代自定义 Route 的协议和证书配置 |

管理地址必须是合适的 HTTP / HTTPS 地址，不包含账号、密码或 Token。容器内的 `127.0.0.1` 与宿主机的回环地址不是同一个位置；管理 API 请求失败不会自动改用另一地址或回退本机。

修改网关域名不会改写已有自定义 Route 或外部 DNS 记录；应分别核对旧入口、新入口和相关服务的重新部署安排，不把域名配置当作入口迁移。

受管初始定义把管理端口绑定到宿主机回环地址，并使用 Docker socket。它不是可直接公开的安全管理面：不要为方便访问把管理端口暴露到公网，也不要把网关 Dashboard 当作已经具备生产认证的入口。检查实际版本的端口、挂载、网络及访问控制，不仅看表单默认值。

### 选择 ACME 能力

| ACME 配置 | 提供的能力及必需内容 |
| --- | --- |
| 未启用 | 不提供 Let's Encrypt resolver；自定义路由仍可按条件使用手动证书或 mkcert |
| `http` | HTTP-01，需要有效 ACME 邮箱 |
| `dns` | Cloudflare DNS-01，需要有效邮箱和 Cloudflare DNS API Token |
| `http-dns` | 同时声明两种能力，需要有效邮箱和 Token |

组件默认 TLS 模式为 `letsencrypt` 时，需要选择 `http` 或 `http-dns`，不能只选 `dns`。自定义路由选择 DNS-01 则需单独确认网关的 DNS 能力和 Token，不能用组件默认模式代替。

**切换到不含 DNS 的 ACME 配置会清空网关 Token。** DNS 页面也使用这个 Token，因此变更前应检查 DNS 管理和既有路由的依赖。Token 在详情中可查看，页面遮罩不是不可恢复的秘密存储；不要放进截图、工单、公开配置或日志。

## 保存不等于部署网关

1. 在初始化中创建关联网关，或在网关页保存所需配置；确认当前项目、域名和管理地址。
2. 从网关页点击“部署”，核对实际部署目录、镜像拉取策略与是否强制重建。目录及数据迁移边界见[应用、版本与服务](./applications-services.md)。
3. 提交后查看对应部署记录及 Traefik 日志，等待最终结果，不把“任务已创建”当成已运行。
4. 查看“Traefik 路由”页面能否读取当前管理 API；分别核对提供者、规则、入口和状态。能读取 API 不等于应用流量已经通畅。

网关部署会按保存的 ACME 配置选择对应的受管版本，并检查管理 API 就绪；不会因为创建了网关定义就自动完成部署。更改证书能力、Token 等运行配置后，需要重新部署才能更新运行侧；修改默认组件入口策略后，相关业务服务也需重新部署，才会重新生成其标签。

停止网关会影响依赖它的入口，不只是关闭一个管理页面。“同时删除 volumes”可能删除数据，必须先明确保留和恢复方案。停止网关不会撤销 Cloudflare DNS 记录，也不等于停止全部业务服务。

## 选择组件入口还是自定义路由

这两条路径可以并存，但来源和生效动作不同：

| 路径 | 定义在哪里 | 何时进入 Traefik |
| --- | --- | --- |
| 组件 `gateway` 端点 | 应用版本及服务运行覆盖中声明的 HTTP 端点 | 服务加入 Traefik 网络并部署后生效；在“Traefik 路由”中显示为 Docker 来源 |
| 自定义路由 | “自定义路由”页面，指定域名、协议和目标 | 保存后预览并确认同步；在“Traefik 路由”中显示为 File 来源 |

组件 `gateway` 模式只适用于 HTTP，派生域名为 `<组件名>.<服务编码>.<内网域名>`；这里使用服务编码，不是应用编码，也不会自动改用外网域名。`internal` 端点不发布宿主机端口，`local` / `host` 端点则按声明绑定回环 / 指定宿主机地址，不等于自动拥有域名路由。

需要独立域名或高级下游地址时再创建自定义路由。选中服务端点不等于已部署服务；应确认下游容器运行且与 Traefik 网络互通。同步自定义路由不会部署目标或更新组件入口；调整组件入口应修改相应配置并重新部署业务服务。

高级下游地址由 Traefik 访问，必须从网关运行侧可达；其中的 `127.0.0.1` 指网关容器自身，不是浏览器、Orbit 后端或任意宿主机。

## 管理 Cloudflare A 记录

DNS 页面通过后端直接调用 Cloudflare，使用当前环境网关保存的 Token。它不是项目私有 DNS 数据库：可见 Zone 由 Token 权限决定，多个项目或环境可能管理同一个外部 Zone，修改会影响其他使用者。

1. 准备限制在所需 Zone 的专用 Token，具备相应 Zone Read / DNS Edit 权限，在网关证书配置中保存合适的含 DNS profile、邮箱和 Token。不要在文档或反馈中粘贴真实值。
2. 打开“DNS 解析”，选择 Zone，先核对现有记录和作用范围。没有 Zone 时检查 Token 授权，不要据此断言域名不存在。
3. 创建记录时填写所需名称、有效 IPv4、TTL 及是否启用 Cloudflare 代理；当前页面只管理 A 记录，不是 AAAA、CNAME、TXT 或任意记录编辑器。
4. 编辑现有记录可调整地址、TTL 和代理，名称只读；若需不同名称，应另行安排记录变更，避免误删仍在使用的入口。
5. 保存后重新查询记录，并从实际客户端检查解析和访问。删除前确认 Zone、完整记录名及受影响服务，不能把删除当成本地列表清理。

TTL 为 `1` 表示自动，否则范围为 30–86400 秒；上游套餐仍可能限制可用值，例如 30 秒需要相应 Enterprise 条件。启用代理时当前实现使用自动 TTL，代理能力还受记录及 Cloudflare 支持范围限制，不保证任意 TCP 端口可通过代理。

DNS 保存、编辑和删除是即时提交的外部操作，**不等待路由的“同步”按钮**。超时或响应异常时，上游可能已经完成写入；先刷新并核对实际记录，再决定是否重试，避免重复创建。记录写入成功不代表所有解析缓存已经更新，也不会创建路由、申请证书或部署服务。

## 创建 HTTP 或 TCP 自定义路由

在“自定义路由”点击创建，选择协议、填写编码和域名。编码以小写字母开头，1–32 位，只含小写字母、数字和连字符，不以连字符结尾；使用能识别用途的稳定编码。自动生成的域名建议仍需按实际解析方案确认。

| 协议 | 目标和匹配 | 额外限制 |
| --- | --- | --- |
| HTTP | 域名和路径前缀匹配，目标选择服务、组件及已声明的 HTTP 端点；也可用“高级：自定义下游地址” | 自定义地址形如 `http[s]://host[:port]`，不带路径；路径前缀匹配不自动删除该前缀 |
| TCP | 选择服务、组件及已声明的 TCP 端点，填写监听端口 | 当前按端口转发，不按填写的域名做 HTTP Host 或 SNI 分流；不支持在此配置 HTTP 路径或路由 HTTPS 证书 |

HTTP 路径前缀默认为 `/`。新建路由从停用配置开始，创建成功只是记录已保存；进入详情复核目标与协议，再配置证书或准备启用。

TCP 监听端口范围为 1–65535，80、443、8080 为网关保留端口；还会检查已启用 TCP 路由和运行中组件宿主机端点的冲突。这些检查不能覆盖宿主机所有外部进程，实际端口可用性仍需确认。

**创建 TCP 路由不会自动修改网关静态配置或开放宿主机端口。** 运行中的网关需已声明名为 `tcp<监听端口>` 的 entrypoint 及相应端口映射，防火墙也需符合访问方案；初始网关只有基础入口。缺少时先在受管网关的版本 / 运行定义中准备并部署，不靠反复同步生成缺失入口。

## 配置自定义 HTTP 路由证书

从路由详情进入“配置证书”，保存后仍需同步，不能把协议徽标变化视为证书已经对客户端生效。

| 方式 | 前提与边界 |
| --- | --- |
| HTTP | 不启用路由 HTTPS，发布到 `web`；不等于强制 HTTP 跳转到 HTTPS |
| HTTPS · PEM | 上传同时包含证书和私钥的 PEM 文件；同步会检查二者能否配对，但不证明证书域名、有效期及客户端信任都符合要求 |
| HTTPS · mkcert | 在 Orbit 后端所在环境生成，后端需有 mkcert 和 CA 材料；不会自动安装客户端信任，也不等于公网可信证书，不应公开 CA 私钥 |
| Let's Encrypt · HTTP-01 | 公开注册域名、网关 `http` / `http-dns` 能力及实际挑战可达条件；不适用于 IP、localhost 等本地名称 |
| Let's Encrypt · DNS-01 | 公开注册域名、网关 `dns` / `http-dns` 能力及有效 Cloudflare Token；域名控制、权限与挑战传播仍需单独验证 |

自定义 HTTPS 路由使用 `websecure`，HTTP 使用 `web`，不因为网关默认入口改变就自动换到任意入口。选择 ACME 方式只保存申请配置，不证明证书已签发；签发、续期及客户端信任需要查看实际 Traefik 日志和访问结果。

## 显式预览并确认同步

1. 编辑域名、目标或证书后保存；点击“启用”或“停用”产生页面上的待同步意图，不要把按钮文字或列表颜色当作已发布状态，也不要把未确认的页面意图当作已持久化配置。
2. 点击“同步”。详情页处理当前路由；列表页预览项目范围，不只是当前分页，并可能包含已删除路由遗留的受管发布撤销项。
3. 检查每项的发布 / 撤销 / 跳过、协议、匹配条件和目标。预览会读取实际执行目标及网关配置，不是离线文本预览；它列出发布计划，不是公网流量或业务健康检查。
4. 确认后逐项等待完成。配置、证书、目标或受管发布状态发生变化时，旧预览可能失效，应重新预览，不绕过校验或切回本机。
5. 查看每项结果与失败原因，再到“Traefik 路由”检查加载的规则及提供者，最后从实际客户端检查解析、端口、TLS 和业务响应。

同步后在“Traefik 路由”核对实际加载的域名、规则和目标。同步成功只说明相应配置步骤完成，**不证明证书信任、ACME 签发或下游业务访问通过**。

批次可能部分成功：已完成项保留，失败项可能业务配置已保存、运行文件却未发布。不要假定全批回滚，也不要只看路由的“启用”字段判断实际流量。保留逐项失败信息，排除问题后重新预览；若提示自动恢复失败，应保留发布记录和恢复材料，不手工删除受管文件来消除错误。

## 停用、删除与故障定位

撤下入口时先选择停用、确认同步并核对撤销结果，再删除不再需要的路由记录。当前只允许删除已停用的路由；删除配置本身不等于已经撤销运行文件，也不会删除 DNS 或停止业务服务。保留其他入口和共享资源，不把删除路由当作完整下线流程。

| 症状 | 优先核对 |
| --- | --- |
| 网关部署失败或 API 未就绪 | 当前本机 / SSH 目标、Docker、目录、镜像、端口及相应执行侧管理地址；延长超时不能修复不可达地址 |
| DNS 提示未配置、无 Zone 或权限不足 | 网关是否保留含 DNS profile 的 Token、Zone 授权、Zone Read / DNS Edit 和当前项目 |
| DNS 写入超时或响应异常 | 先刷新上游实际记录，不马上重复提交；区分上游失败与客户端解析缓存 |
| 组件入口没有出现 | HTTP 端点是否为 `gateway`、服务是否加入 Traefik 网络并重新部署、派生域名和 Docker provider 规则 |
| 同步提示容器未运行、缺少入口或 resolver | 先核对实际网关版本及部署；TCP entrypoint 和 ACME 能力必须存在于运行配置中 |
| 同步提示预览过期、文件变更或恢复失败 | 核对当前目标及受管发布状态，保留证据并重新预览；不要直接覆盖未知文件或删除恢复材料 |
| 部分同步失败或配置已保存但入口仍旧 | 查看逐项失败原因、Traefik 日志与实际加载配置，不能用列表状态代替发布结果 |
| 规则已加载但访问失败 | 从客户端按 DNS / 代理 → 防火墙与端口 → TLS → 路由 Host / 路径 → 网络及下游服务逐层检查 |

反馈时提供当前项目、脱敏域名、路由编码、失败时间、请求 / 操作编号和脱敏错误，不附 Token、私钥或包含秘密的配置。需要调整业务运行配置时回到[应用、版本与服务](./applications-services.md)，更改执行目标前先阅读[项目与执行环境](./projects-environments.md)的迁移与目录风险。
