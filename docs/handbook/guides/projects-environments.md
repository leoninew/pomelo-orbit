# 项目与执行环境

本文说明怎样为项目选择执行目标、保存工作目录，以及检查本机或 SSH 环境。先阅读[核心概念](../concepts/core-model.md)，区分项目、环境和两类凭据。

## 开始前

- 已有可访问的 Pomelo Orbit 实例并已登录，当前用户有相应操作权限；使用已有项目时，需属于该项目。
- 知道实际执行 Docker Compose 的位置、可用工作目录和运行身份。不要直接使用生产目标试验初始化命令或目录变更。
- 执行侧已准备 Docker 与 Docker Compose，以及相应的访问和目录写入权限。选择 SSH 时，还需准备能从后端访问的主机、端口和用户。

本指南适用于 `develop` 分支，以已有可用实例为前提，不包含安装和首次登录。网络入口配置另见[网关、DNS 与路由](./gateway-dns-routes.md)。

## 选择或创建项目

1. 打开“系统管理”中的“项目”，选择你有权限操作的项目。
2. 如需新建，点击“创建项目”，填写名称和编码。编码以小写字母开头，可含小写字母、数字、`+`、`.` 和 `-`，总长不超过 32 位；选择有意义且稳定的编码，创建后界面不提供修改。
3. 确认当前选中的项目，再进入“环境”。已有环境时打开项目环境页；尚未配置时会进入“初始化项目”。

项目只有一个 CI/CD 共用执行环境，不是在同一项目下分别创建开发、测试、生产三个 Environment。如果需要不同执行目标，应先规划项目及资源隔离，而不是把服务编码当成环境选择器。

项目创建者会成为初始成员；已有账号还需加入项目才能访问相应资源，系统角色不会自动授予所有项目权限。添加 / 移除成员及成员页面的读取权限要求见[用户、权限与访问令牌](./users-access.md)。

## 确定执行位置和工作目录

| 选择 | 在哪里执行 | 需要填写或核对的内容 |
| --- | --- | --- |
| 本机 | 后端运行侧使用的本机执行环境，不是访问网页的电脑 | 工作目录，以及页面展示的平台、主机和用户 |
| SSH 远程主机 | 后端通过 SSH 访问的目标 | Linux / Windows 平台、主机、端口、SSH 用户、工作目录 |

“本机”不表示浏览器拥有本机 Docker 权限；后端在容器中运行时，还要考虑容器侧路径与 Docker 宿主机路径的对应关系。

工作目录用于组织流水线与部署文件。使用目标平台的绝对路径，或 `~` / `~/...` 形式；不要填写相对于浏览器或仓库的路径。`~` 指执行用户的家目录。以下只是路径格式示例，不表示目录已存在或有权限：

- Linux：`/srv/pomelo-orbit` 或 `~/.pomelo-orbit`。
- Windows：`C:\Orbit` 或 `~/.pomelo-orbit`。

选择本机时，平台、主机和用户由后端展示，不是 SSH 输入项。选择 Windows SSH 时，执行环境检查还涉及 OpenSSH、WSL2 与 Docker Desktop，不能只以普通 SSH 登录成功判断 Compose 已可运行。

## 保存本机环境

1. 在初始化的“选择环境”步骤选择“本机”，填写工作目录；已有环境则从项目环境页编辑基本信息。
2. 初始化时点击“下一步”保存；已有环境在编辑对话框中保存。
3. 重新查看类型和工作目录，确认当前项目与执行侧信息无误，再运行连接检查。

保存只记录配置，不等于 Docker 已可访问、工作目录已可写或应用已经部署。本机不需要环境 SSH 凭据。

## 准备 SSH 环境

### 保存目标并生成命令

1. 选择“SSH 远程主机”，填写目标平台、主机、端口、SSH 用户和工作目录。端口范围为 1–65535，主机地址不带空白。
2. 保存目标配置。仅保存不会生成受管 SSH 凭据，也不会在远端安装公钥。
3. 点击“生成初始化命令”。系统保存提交的 SSH 目标，并在该环境尚无凭据时生成环境专属密钥；已有凭据会复用，不要把反复点击当作密钥轮换。
4. 先阅读生成命令、确认目标和运行身份，再决定执行。命令显示和复制完成不代表已经执行。

环境 SSH 身份与“持续集成”中的仓库凭据分开管理，不要尝试通过修改 Git 凭据解决环境 SSH 认证问题，也不要将私钥或实例密钥粘贴到反馈中。

### 在目标上审阅并执行

生成的命令不是只读检查，会改动目标系统。下表说明平台生成命令的执行要求，不是本手册提供的 Bash 示例；Windows 原生初始化不能直接改用 Bash 执行：

| 平台 | 执行位置与主要影响 |
| --- | --- |
| Linux | 在目标主机以配置的 SSH 用户执行；写入该用户的公钥授权文件、设置权限、准备工作目录及其子目录，部分目录操作可能需要 `sudo` |
| Windows | 在目标主机的管理员 PowerShell 中执行；可能安装 OpenSSH、调整 SSH 配置、密钥授权和 ACL、防火墙及服务启动状态，重启 SSH 服务可能影响现有连接 |

请通过已信任的管理通道操作，保留恢复访问方式，并按目标主机管理要求安排变更。不要在未核对的主机、普通开发终端或生产维护窗口之外直接粘贴执行。生成命令不替代 Docker、WSL2 等执行前提的准备。

## 运行连接检查

初始化页面的第二步是“连接检查（可选）”，点击“检查连接”；已有环境页点击“探测”。检查后查看探测状态、时间和诊断信息，SSH 环境还应查看主机密钥指纹。

| 观察结果 | 如何理解和继续 |
| --- | --- |
| 本机探测通过 | 当次本机 Docker / Compose 前提检查通过，仍需在具体部署时检查镜像、端口、目录和配置 |
| SSH 首次探测通过 | 当次连接及执行前提检查通过；系统会记录首次成功连接观察到的主机指纹，执行前应通过可信渠道确认目标身份 |
| 提示先生成并运行初始化命令 | 目标可能已保存但尚无有效凭据；完成 SSH 初始化，再检查远端授权和探测结果 |
| 连接、认证、指纹或 Docker 检查失败 | 核对当前目标、网络、SSH 用户、公钥授权及执行前提；不要通过切回本机来绕过 SSH 失败 |
| 检查期间环境发生变化 | 重新载入并核对配置，再对当前目标探测，不沿用旧结果 |

向导中的“可选”指诊断步骤不以成功状态阻止前进，不代表 SSH 可以没有凭据或主机指纹就执行。新建 SSH 目标通常需要通过探测记录首次指纹；实际操作仍会校验当前目标、工作目录、凭据和指纹，SSH 失败不会回退本机。

历史探测通过也不是长期就绪保证。工作目录或连接信息变化后应重新检查；旧时间和诊断不能证明新目标已验证，更不要在未知主机身份时反复改配置消除指纹错误。

## 理解“准备网关”的边界

环境保存后，初始化还可能停在“准备网关”。本指南到环境配置与检查为止；网关的镜像、管理地址、域名、TLS 和端口需按实际网络方案准备，不要为完成向导随意填入生产域名或令牌。

创建网关资源与部署网关是不同操作。项目初始化完成不证明 Traefik 容器已经运行、DNS 已生效或应用入口已经可用。继续部署业务服务前，应完成项目初始化；需要加入 Traefik 网络时，还应确认网关已部署就绪。

后续按[网关、DNS 与路由](./gateway-dns-routes.md)核对管理地址、入口策略、证书能力和部署结果；不要把可选环境探测通过当作这些网络条件已完成。

## 修改已有环境前

- 先核对当前项目和已有服务。修改目标或工作目录不会搬迁旧主机上的容器和数据；后续操作会使用当前目标，不要把编辑环境当作迁移步骤。
- 更换 SSH 主机、端口、平台或用户后，原主机指纹可能被清空，需检查新目标的公钥授权和指纹；仅修改工作目录不等于更换 SSH 身份。
- 出现“其他活跃项目有相同的目标配置”警告时，保存已经完成，但项目可能共用 Docker。项目隔离不自动隔离宿主机端口、容器名和数据目录，继续前应检查资源冲突。
- 反馈问题时保留失败时间、当前目标类型和脱敏诊断；不要附带私钥、令牌、真实密码或完整敏感配置。

准备好环境并完成项目初始化后，继续阅读[应用、版本与服务](./applications-services.md)。

如果只进行 CI，可先阅读[仓库与仓库凭据](./repositories-credentials.md)和[流水线与制品](./pipelines-artifacts.md)。CI 在环境保存后可从初始化返回流水线，不强制先创建网关；这不免除 SSH 凭据、主机指纹及执行前提的校验。

需要从命令行列出 SSH 环境、执行远程命令或建立转发时，阅读[MCP 与 CLI](../reference/mcp-cli.md)。CLI 使用项目编码且只操作 SSH 目标；不要将它与 MCP 要求环境及网关服务记录的项目选择流程混用，也不以列表可见代替连接验证。
