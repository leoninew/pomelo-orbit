# 仓库与仓库凭据

本文说明怎样登记源码、选择当前流水线支持的认证方式，以及检查共享配置和敏感信息的边界。执行环境的准备见[项目与执行环境](./projects-environments.md)，构建和产物的后续操作见[流水线与制品](./pipelines-artifacts.md)。

## 开始前

- 已有可访问且已登录的实例，选中了你有操作权限的项目。
- 确认源码来源、实际分支和访问方式。需要认证时，准备只授予必要仓库权限的专用令牌，不使用生产管理员身份作试验。
- 使用本地目录前，确认该 Git 目录能被后端读取，并能从实际 Docker 执行侧正确挂载；浏览器所在电脑的路径不一定可用。

本指南适用于 `develop` 分支。保存仓库与凭据后，还需通过实际取源码阶段确认地址、权限和网络可用，不要在反馈中公开令牌。

## 先理解共享范围

仓库和仓库凭据是跨项目共享资源，界面要求选择项目并校验成员身份，不表示保存后的对象只属于当前项目。切换项目不是复制仓库，也不是为同一个凭据生成隔离副本。

仓库编码在共享范围内唯一，凭据名称也不能与已有凭据重名。修改共享仓库的地址、分支或凭据，以及修改凭据内容，都可能影响其他项目中使用它们的流水线；变更前先确认引用及维护责任。

这里的 Git 凭据与项目环境的 SSH 执行凭据不同：前者访问源码，后者连接运行主机。个人访问令牌用于访问 Pomelo Orbit 本身，也不能替代二者。

## 选择源码类型

| 类型 | 适用条件 | 当前限制 |
| --- | --- | --- |
| 远程 Git | 通过 Git 地址读取源码，按需要绑定凭据 | 使用令牌认证时选 HTTPS 地址；SSH 执行环境中的流水线也要求有效 HTTPS Git 地址 |
| 本地目录 | 后端可读取的普通 Git 工作目录或裸仓库 | 不是文件上传，不接受普通非 Git 目录；不支持 linked Git worktree，不绑定 Git 凭据，也不能用于 SSH CI |

优先为远程执行准备 HTTPS Git 源码。不要因为环境通过 SSH 连接，就把源码地址改为 `git@...`：运行主机连接协议与 Git 取源码协议是两件事。

本地目录建议填写明确的绝对路径。后端会解析真实目录并检查 Git 元数据；目录存在不代表容器侧挂载或目标分支有效。未提交的本地修改也不等于已成为某个 Git ref 的内容，构建所取的提交仍由脚本和运行参数决定。

## 按执行支持准备凭据

打开“持续集成”中的“凭据”，创建名称明确的凭据，选择类型并填写内容。当前界面可保存的类型不等于当前流水线执行器都能使用：

| 类型 | 内容形式 | 在 Git 流水线中的含义 |
| --- | --- | --- |
| `github_token` | GitHub 令牌 | 用于 HTTPS Git 认证，仍需令牌具有相应仓库权限 |
| `gitee_token` | `用户名:令牌` | 两部分均需填写，只有令牌字符串不符合执行要求 |
| `gitea_token` | `用户名:令牌` | 两部分均需填写，使用目标 Gitea 实例认可的身份 |
| `git_ssh` | SSH 私钥内容 | 可以保存，但当前流水线执行器不支持用它取源码 |
| `registry_token` | 镜像仓库凭据内容 | 不是受支持的 Git 认证类型；绑定到仓库不会自动完成镜像登录或推送 |

不要把带真实令牌或密码的 URL 填入仓库地址。仓库地址会出现在详情、变量或执行配置中，应保持不含秘密，再通过凭据绑定提供认证。

保存成功只证明配置已记录，不证明令牌格式、远端权限、网络连通和 Git 操作已经通过。当前执行器会在使用仓库地址的阶段配置中应用 Git 认证，脚本仍需执行实际取源码命令；不要另行把令牌拼进脚本、命令行或日志。

## 登记仓库

1. 打开“持续集成”中的“仓库”，点击创建入口，填写名称及仓库编码。
2. 编码只含小写字母、数字、连字符或下划线，例如 `orders-source`；它用于固定 CI 工作目录，创建后不可修改。
3. 选择远程 Git 或本地目录，填写对应地址。远程私有仓库绑定合适的 Git 凭据；公开仓库可不使用凭据；本地目录不绑定凭据。
4. 显式填写真实存在的默认分支，不依据表单占位提示推断仓库一定有 `master`、`main` 或 `develop`。
5. 保存后进入仓库详情，复核类型、源码位置、默认分支和绑定凭据名称。不要通过截图暴露令牌内容。

仓库登记不会自动克隆源码、创建流水线或构建镜像。下一步应选择合适的模板，建立应用流水线并检查取源码阶段，见[流水线与制品](./pipelines-artifacts.md)。

## 默认分支与仓库变量

仓库详情的变量区域显示内置变量与可配置项。`repository_url` 描述源码位置，`repository_ref` 用于运行时选择分支或标签；触发流水线时应重新确认本次 ref，不把默认分支当作已经固定的提交 SHA。

需要共享构建配置时，可以按界面允许的范围添加或编辑仓库变量，填写值、说明，并将敏感项标为敏感变量。仓库级配置会参与使用该仓库的流水线变量解析；在排查覆盖问题时查看本次运行的变量快照，不只看当前仓库页面。

同名的有效仓库配置优先于流水线阶段和全局配置；空白值、引用处默认值及嵌套限制见[变量与 Compose 约束](../reference/variables-compose.md)。这些 CI 值不会自动成为业务 Service 的环境值。

敏感标记和页面遮罩不是日志防泄露措施。不要在脚本中使用 `env`、调试追踪或输出命令来打印秘密，也不要把包含秘密的文件声明为制品。

## 查看、更新与导出凭据

- 凭据详情提供敏感内容查看能力。UI 默认遮罩不代表平台只存哈希或无法恢复原值，应限制能够访问实例和项目的用户范围。
- 编辑可更新名称和内容，凭据类型在编辑时不可改；需要另一类型时，创建合适的凭据并重新绑定，不把旧内容留作兜底。
- 更新共享凭据前检查所有引用，安排维护窗口，确认新的上游权限；保存新值不会验证所有历史或后续阶段都能成功。
- **导出文件包含解密后的凭据内容。** 它不是仅含名称的元数据或公开可分享的加密备份，不要提交到 Git、上传公开附件或贴进工单。
- 导入也会创建可被使用的敏感配置。只接收可信文件，核对类型、内容和名称，使用后按组织要求保护文件；没有迁移或备份需求时不必导入或导出。

## 删除前核对引用和文件

仍被仓库引用的凭据不能直接删除，仍绑定流水线的仓库也不能直接删除。先查清所有项目中的使用情况，确认替换或移除方案，不要为了通过删除检查清空正在使用的配置。

当前仓库删除操作只移除配置，不承担源码工作区清理；即使界面出现相关清理选项，也不要把删除成功当作目录已经清理的证据。它也不会删除远端 Git 仓库、撤销上游令牌或替你备份本地源目录。上游身份撤销及执行侧文件处理需要另行安排和核对。

## 遇到失败时

| 症状 | 优先核对 |
| --- | --- |
| 编码或凭据名称冲突 | 是否已存在跨项目共享对象，不要通过切换项目重复创建 |
| 本地目录无法保存 | 后端能否读取真实目录、是否为受支持的 Git 仓库、是否为 linked worktree |
| SSH 环境不接受源码配置 | 使用有效 HTTPS Git 地址，不用本地目录或 SSH Git 地址 |
| 取源码阶段认证失败 | HTTPS 地址、绑定类型、用户名与令牌格式、上游权限、执行侧网络及脚本是否实际使用仓库地址 |
| 修改默认分支后运行仍不符合预期 | 检查触发 ref、变量覆盖、本次快照及实际取到的提交，不只查看当前设置 |
| 删除被拒绝 | 先处理引用关系；不要把删除共享对象当作单项目清理 |

反馈问题时提供脱敏地址、类型、失败时间和本次运行编号，不附凭据、导出 JSON 或完整认证环境。接下来阅读[流水线与制品](./pipelines-artifacts.md)，把源码配置与可观察的执行结果联系起来。
