# 角色与权限

系统角色是一组权限码。用户持有多个角色时，权限取并集；项目访问另由[成员关系](./projects.md)决定。

## 权限目录

| 权限 | 操作 |
| --- | --- |
| `user:read` / `user:write` | 查看 / 维护用户 |
| `role:read` / `role:write` | 查看 / 维护角色与权限 |
| `login:read` | 查看登录历史 |
| `setting:read` / `setting:write` | 查看 / 保存系统设置 |
| `dialogue:read` / `dialogue:write` | 查看 / 发送、继续和删除部署对话，还需属于项目 |

给用户分配角色时，后端同时要求 `user:write` 和 `role:write`；页面还需两类读取权限。`setting:read` 可读取敏感原值，页面遮罩不构成脱敏权限。

## 创建与分配

1. 在“系统管理 → 角色”创建，填写唯一编码、名称及可选说明。编码只含字母、数字、`_`、`-`。
2. 新角色初始没有权限。在角色详情编辑权限，选择完整权限集合并保存。
3. 在用户详情编辑角色，选择需要保留的完整角色集合；清空选择会撤销所有角色。
4. 刷新用户身份和页面，检查允许的操作。

角色变更影响所有持有者；仍被用户分配的角色不能删除。系统不保证保留最后一位管理员，撤权前保留其他可用管理身份。

权限按实际权限码判断，角色名称不产生额外能力。当前未提供“仅能部署某个服务”等细分角色，也没有项目只读成员角色。
