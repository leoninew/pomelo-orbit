# 服务

服务选择一个应用版本，保存运行变量、组件覆盖和部署目录。同一应用可创建多个服务，例如 `orders-main` 和 `orders-preview`；它们共用项目执行环境。

## 创建与预览

1. 打开“持续部署 → 服务”，选择应用、版本，填写项目内唯一的服务编码。
2. 编码最长 63 位，使用小写字母、数字和连字符，首尾不能是连字符。
3. 在详情中填写[服务变量](../reference/service-variables.md)。按需在服务组件中覆盖命令、策略、挂载或端点；镜像通过版本管理。
4. 点击“预览”，检查版本、实际变量和覆盖合成的 Compose。

新服务处于停止状态。保存变量或切换版本后，需要重新部署才会更新容器。

## 部署

1. 确认项目[执行环境](./environments.md)和初始化已完成。
2. 点击“部署”，核对版本、拉取策略、强制重建选项和是否加入 Traefik 网络。使用网关网络时先部署好网关。
3. 确认部署目录。首次通常为环境工作目录下的 `deployment/<服务编码>`；使用目标平台绝对路径或 `~/...`，不能含 `..`。
4. 提交后打开本次[部署记录](./deployments.md)，等待执行结果。

::: warning 部署目录与数据
修改部署目录会改变相对挂载位置，旧数据不会自动迁移。先确认旧目录、数据归属和迁移方案。若确认窗口打开后环境发生变化，重新打开窗口核对目标与目录。
:::

## 更新、停止与删除

| 任务 | 操作 |
| --- | --- |
| 更新版本 | 准备新版本 → 改服务绑定 → 检查变量及覆盖 → 预览 → 部署 |
| 停止 | 提交停止操作，检查本次记录和当前容器 |
| 删除 | 仅停止或失败状态可删除；先确认运行资源和数据如何处理 |

停止窗口中的“同时删除 volumes”可能删除持久化数据。删除服务记录不负责证明容器、目录或外部资源已清理，失败状态下也应核对实际资源。
