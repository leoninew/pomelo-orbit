# 阶段

阶段定义一段容器内执行：镜像、脚本、变量和制品声明。在“持续集成 → 阶段”维护可共享的阶段模板，再由[流水线](./pipelines.md)组织依赖。

## 配置执行

1. 选择包含所需工具的执行镜像。阶段入口需要 `/bin/sh`；脚本使用 Bash 时还需镜像包含 Bash。
2. 编写脚本，显式取源码、构建并输出产物。
3. 按需声明[制品](./artifacts.md)，使平台能在阶段结束后收集输出。

| 容器路径 | 用途 |
| --- | --- |
| `/workspace` | 构建工作目录 |
| `/artifacts` | 本次运行的制品文件目录 |
| `/source` | 本地目录源码的只读挂载，远程 Git 源码不使用此路径 |

工作目录可能保留历史文件，脚本应明确处理自己的构建输入。

## 示例：生成文件制品

在包含 Bash 的 Linux 阶段镜像中填写脚本：

```bash
bash <<'BASH'
printf 'pipeline smoke check\n' > /artifacts/report.txt
BASH
```

添加制品声明：名称 `report`、收集器 `file`、引用 `report.txt`。引用相对制品目录，不填写 `/artifacts/report.txt`。

将阶段加入模板并复用为应用流水线后运行。检查退出码、运行终态和实际文件制品。本例只验证脚本与文件收集；源码认证和镜像发布需由对应阶段验证。

## 阶段依赖

在流水线中设置“依赖哪些阶段”。前置阶段成功后，下游才能执行。依赖不能重复、自依赖或成环；需要记录源码提交时，将 `command` / `git_object_id` 制品放在镜像阶段的依赖链上。
