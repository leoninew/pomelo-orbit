# 备份与恢复

平台记录、执行侧文件和业务数据分别保存。备份前先列出它们的实际位置。

## 备份范围

| 范围 | 内容 |
| --- | --- |
| 平台数据库 | 用户、项目、定义、执行记录和加密凭据 |
| 配置与主密钥 | 启动配置、dotenv、`overwrite.env`、`data/config/` |
| 执行文件 | 制品、部署目录、运行日志和 SSH 目标工作区 |
| 网关材料 | 路由发布文件、证书、ACME 状态及相关权限 |
| 业务数据 | 命名卷、挂载目录及数据库内容 |

只备份 Compose 文件无法恢复卷中数据。本机安装目录也不包含 SSH 主机上的工作区。

## 创建一致备份

1. 安排维护窗口，停止新写入，等待或处置在途流水线与部署。
2. 停止访问同一平台数据的 Web、Worker、MCP 和 CLI 进程，再检查远端仍在执行的命令。
3. 按存储类型备份，同时保留匹配的程序版本和主密钥。
4. 业务容器单独安排停写或业务一致性快照。

| 数据库 | 要求 |
| --- | --- |
| SQLite | 全部连接关闭后离线备份，或使用 SQLite 支持的一致性备份；运行中不能只复制主 `.db`，保留 WAL 状态 |
| MySQL / PostgreSQL | 使用数据库原生一致性备份或受控快照，不复制正在写入的数据目录 |

记录备份时间、版本、范围和未包含项。

## 隔离恢复演练

1. 准备独立数据库、目录和 Docker，阻断生产执行目标及外部写入。
2. 从备份恢复匹配的程序、数据、配置和原密钥。
3. 检查登录、权限、项目与服务记录、凭据解密和文件制品。
4. 用专用测试服务验收执行与业务响应。

**启动恢复实例前先隔离生产目标。** `serve` 会自动启动 Worker，恢复的数据可能包含排队任务和外部服务凭据。

数据库恢复不会回滚真实容器、DNS 或镜像推送，需按恢复前清单核对这些资源。
