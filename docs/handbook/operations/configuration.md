# 配置与密钥

本文面向已有实例的维护者，说明平台从哪里加载配置、系统设置保存了什么，以及哪些值不能随意替换。项目执行目标见[项目与执行环境](../guides/projects-environments.md)，业务变量见[变量与 Compose 约束](../reference/variables-compose.md)。

本指南适用于 `develop` 分支，以已有可用实例为前提。先在系统设置中确认当前配置，再按维护安排修改；涉及数据库、密钥和进程重启时，应保留可用的恢复入口。

## 先确定配置属于哪一层

| 配置位置 | 控制什么 | 不会自动改变什么 |
| --- | --- | --- |
| 实例启动配置 / 系统设置 | 平台进程的数据库、日志、监听、认证、LLM、Worker 等 | 已保存的业务资源、运行容器和其他进程的配置 |
| 项目执行环境 | 项目的本机 / SSH 目标、工作目录及连接身份 | 平台的启动工作目录和实例数据库 |
| 流水线 / Service / 组件变量 | 构建输入、服务运行配置及容器环境 | 平台的 `POMELO_ORBIT_*` 实例配置 |
| `project_initialization` 实例配置 | 项目初始化向导使用的默认值 | 已有环境、网关或服务的实际配置 |

不要为了调整某个业务容器的变量去修改系统设置，也不要以为更改初始化默认值会更新已有项目。配置变更不负责迁移数据库、工作目录、日志或持久化卷。

## 读懂系统设置中的值

打开“系统管理 → 系统设置”需要 `setting:read`，更新和重置需要 `setting:write`；完整页面操作通常需要两者。权限分配见[用户、权限与访问令牌](../guides/users-access.md)。

| 含义 | 应怎样理解 |
| --- | --- |
| 默认值 | 来自启动配置文件和进程启动环境，不含系统设置保存的覆盖；**不是出厂值** |
| 当前值 | 该后端进程实际使用的值，保存后仍可能是旧值 |
| 应用覆盖 | `overwrite.env` 中已保存的值，存在覆盖不等于尚未生效 |
| 待重启提示 | 已保存配置与进程当前使用配置有差异，或下次配置有错误；先检查原因，再安排重新加载 |

页面展示默认值、当前值、覆盖标记和重启提示，没有独立的待生效值列。保存后不要因当前值仍旧就反复提交；应先确认保存结果，再安排重新加载。

覆盖与当前值相同也可能显示覆盖标记，但不要求重启，不能只凭颜色判断是否生效。若页面提示下次配置有错误，应先解决；页面能打开不代表下次一定能启动。

## 修改、保存与重置

### 一次保存有关联的一组配置

1. 先记录目标字段、当前值、预期值及其来源，确认是否影响监听、数据库、身份或执行进程。记录中不要抄入真实秘密。
2. 按键名或说明搜索，编辑需要调整的字段。编辑框优先带入已保存覆盖，没有覆盖时使用默认值；**不一定从当前运行值开始**，提交前核对。
3. 可以让多行同时处于编辑状态。有关联的项一起编辑，再点击“保存全部”；即使从某一行点击，也会提交本页全部待保存修改和重置项，包括被搜索隐藏的项。
4. 后端按完整候选配置校验。比如 LLM 基础地址、API Key 和模型必须成组有效；从空配置启用时一起保存，只填一项会失败。关闭或重置时也要核对下层配置，不假定重置三项就一定得到全空值。
5. 保存成功后核对返回状态及重启提示，按维护安排使受影响进程重新加载，再检查实际运行值和所需业务。页面取消只撤销对应行未保存的编辑 / 重置，不撤销已保存内容。

字段格式正确只是第一关。启用 Turnstile 时需要相关字段齐备，超时、Worker 并发和租约也有组合约束；保存会校验整组配置，可能因另一处无效配置失败。**保存校验不测试数据库、SSH、模型供应商或外部网络连接。**

### 重置只删除应用覆盖

只有存在覆盖的项才能重置。点击重置并确认后，页面先标记“待重置”，**仍需再保存**才删除 `overwrite.env` 的对应项；可以在保存前取消该行。

重置不会修改 YAML、启动 dotenv 或 OS 环境，不是清空字段、恢复出厂、撤销业务或轮换密钥。删除覆盖后，候选值回到下层配置；下层若有旧秘密或不同数据库地址，下一次加载可能重新使用它们。关联项的部分重置若使组合无效，会被拒绝而不写入本次变更。

### 保存不是热更新，也不主动重启

例如当前日志级别为 `warn`，保存为 `debug` 后，当前值仍是 `warn` 并提示待重启；重新加载后才使用 `debug`。刷新浏览器不会让它生效。

系统设置不会替你重启后端，也不会将配置推送给其他 Web、独立 Worker、MCP 或 CLI 进程。共用实例数据的进程应核对数据库、密钥和路径一致性，按维护安排分别重新加载；本地客户端的操作见 [MCP 与 CLI](../reference/mcp-cli.md)。不要在生产实例试验重启或切换数据库。

## 启动配置与覆盖来源

当设置与预期不同、重置后出现旧值，或本地客户端使用了另一套配置时，再检查启动配置。

### 确认工作目录和文件

平台从**进程启动时的工作目录**读取必需的 `configs/config.yaml`，不向父目录自动查找。`overwrite.env` 也固定在这个目录，不一定在程序文件旁。

`orbit.root` 参与日志和平台工作区等运行路径的处理，**不会移动配置文件的查找位置**；不要把所有数据库或业务目录都推断为相对 `orbit.root`。容器运行还要核对容器内工作目录和实际挂载。

### 确认 profile 和优先级

profile 从启动环境的 `POMELO_ORBIT_APP__ENV` 选择；若 `overwrite.env` 有同名项，以覆盖为准。profile 只能包含字母、数字、下划线和连字符，也可为空，不能填写路径。

配置优先级从低到高如下：

| 顺序 | 来源 | 读取规则 |
| --- | --- | --- |
| 1 | `configs/config.yaml` | 必需的基础配置 |
| 2 | `configs/config.<profile>.yaml` | 有 profile 时合并，可缺省 |
| 3 | `.env` 或 `.env.<profile>` | 无 profile 只读 `.env`；有 profile 只读对应文件，可缺省 |
| 4 | 进程启动环境 | 覆盖文件中的同名配置 |
| 5 | `overwrite.env` | 系统设置保存的应用覆盖，优先级最高，可缺省 |

例如 profile 为 `development` 时，会尝试 `configs/config.development.yaml` 和 `.env.development`，**不会再叠加 `.env`**。不要在 `.env` 内设置 profile 来选择应该读取哪个文件；profile 应在启动环境或应用覆盖中指定。`.env.example` 只是模板，不会自动加载。

可选文件不存在可以继续，存在但格式错误或不可读则可能导致加载失败。`overwrite.env` 不接受未知配置键，不应放入业务变量；空字符串也不是删除覆盖或自动回退，仍须通过校验。

读取或保存系统设置时会重新读取配置文件，但仍使用该进程启动时的环境变量。另一个终端中新设置的环境不会改变现有进程；真正重启时又会重新读取启动环境，所以安排重启前也要核对它。

### 按入口填写同一字段

| 位置 | 日志级别字段示意 |
| --- | --- |
| YAML 路径 | `logging.level` |
| 系统设置键 | `logging__level` |
| 环境 / 覆盖文件键 | `POMELO_ORBIT_LOGGING__LEVEL` |

`POMELO_ORBIT_LOGGING__LEVEL=warn` 只说明字段命名，不是要求覆盖现有文件。页面支持字符串、布尔、整数、时长和列表；时长使用 `60s`、`2m` 等形式，列表每行一项。环境中的列表使用 CSV 逗号分隔，不是 JSON 数组。

`overwrite.env` 按字面值保存，不展开业务 Liquid、Service 占位符或 shell 变量。不同层的变量用法见[变量与 Compose 约束](../reference/variables-compose.md)。

## 区分密钥用途

| 值 | 当前用途 | 维护边界 |
| --- | --- | --- |
| `jwt__secret_key` | Web JWT 签名；也用于仓库凭据、环境 SSH 私钥、可再次查看的 PAT 原值及 Google 临时登录会话的加密 | 实例级稳定密钥，不能随意生成新值替换 |
| `mcp__access_token` | 本地 MCP / CLI 使用某个用户已创建的 PAT 进行认证 | 不是 JWT 签名密钥；替换客户端配置不撤销旧 PAT，需显式撤销 |
| 仓库凭据 / 环境 SSH 私钥 | 访问源码、镜像仓库或项目执行目标 | 在对应业务入口管理，不靠修改 JWT 密钥轮换 |
| `llm__api_key`、`google__client_secret`、`turnstile__secret_key` | 各外部服务的认证秘密 | 需与供应商及相关字段匹配，不能互换，格式可保存不等于外部有效 |
| `database__url`、网关 DNS Token | 实例数据访问，或初始化默认 / 实际网关的外部 DNS 身份 | 连接串可能含密码；初始化默认与已有项目配置分开处理 |

`jwt.secret_key` 必须是 URL-safe Base64 编码的 32 字节 Fernet 密钥，不是任意密码。**已有实例不要重新生成后直接替换**，应保管并使用与实例数据匹配的原有密钥；格式正确也不代表随机性或保管方式安全。

换成另一把有效密钥后，旧 JWT 将无法由新密钥验签，已有仓库凭据、SSH 私钥和 PAT 的可恢复密文等也不能由新密钥正常解密。当前没有通过系统设置自动重加密旧数据或维护多把历史密钥的通用轮换流程；恢复数据库时也必须保留与数据匹配的密钥。

PAT 的认证按已存哈希匹配，不靠解密其可查看原值。因此改变 JWT 密钥**不能当作统一撤销 PAT 的手段**；已持有的 PAT 仍需按令牌管理流程撤销。Google 临时会话和已有登录也会受各自密钥 / 身份校验影响，不能仅靠重新登录证明所有凭据已恢复。

## 敏感遮罩不等于加密或隔离

`settings.secret_keys` 使用系统设置键名，决定哪些项在页面遮罩。有权查看设置的人仍可取得这些原值，页面也可显示；`setting:read` 不是只能看脱敏信息的权限。修改敏感列表需重新加载才影响页面标记，而且不会将原始配置加密。

- 保护启动 dotenv、进程环境、`overwrite.env` 及其备份，不提交到版本控制，不打印全部配置，不将原始响应、截图或诊断直接发到公开问题中。
- 应用覆盖是可解析的明文 ENV，不是秘密保险库；数据库中部分业务凭据的加密不保护这些配置文件，也不代表全部业务变量都加密。
- 覆盖文件的锁和中断写入恢复记录位于**启动工作目录下的 `data/config/`**，并非按 `orbit.root` 迁移；临时 / 恢复记录可能含此前的秘密，同样需要访问控制和持久化安排。
- 文件存储会请求受限的新建权限，但已有文件、Windows ACL、容器挂载和备份权限仍需维护者检查，不能只凭文件名或页面遮罩判断安全。
- 容器重建时，未持久化的覆盖可能丢失并回到下层配置；只持久化数据库不能替代保管匹配的主密钥和实际启动配置。备份范围与维护步骤见[数据保留与升级](./data-upgrades.md)，恢复方案应先在隔离环境演练。

## 保存或加载失败时

| 现象 | 优先核对 | 不要直接做什么 |
| --- | --- | --- |
| `settings_revision_conflict` | 有人已修改应用覆盖；先保留非敏感修改意图，重新加载并核对他人变更，再编辑 | 不拿旧页面反复保存或覆盖他人设置 |
| `settings_store_busy` | 配置存储正被另一协同访问持有；稍后重新加载，持续失败再检查相关进程和运行环境 | 不删除锁文件或强行同时写入 |
| 页面提示下次配置无效 | 字段类型、关联项、所选 profile 及实际文件，区分当前配置和未生效修改 | 不因当前进程还在运行就立即重启 |
| 无法访问 `overwrite.env` | 启动目录、目标挂载和文件权限；`data/config/` 也需可访问及写入 | 不通过清空覆盖、删除恢复记录或放宽所有权限来试探 |
| 修改启动环境后仍看到旧值 | 是否仍为旧进程的 OS 快照，以及更高优先级应用覆盖 | 不将刷新浏览器当作重新加载进程 |
| 重启后出现解密或认证错误 | 是否误换主密钥、profile、数据库或配置根目录，是否与其他进程一致 | 不继续生成新密钥或重建数据库试图修复 |

文件存储有中断写入恢复机制，会在后续访问时处理自己的恢复记录；它不是完整历史备份或业务回滚。遇到持续文件错误，应先保全相关文件与非敏感错误信息，再由维护者安排恢复，不手工清理锁 / 恢复目录来“解锁”。

最终应分别确认配置可加载、目标进程实际使用预期值，以及受影响的业务可用；这三件事不能相互替代。涉及真实密钥、数据库、进程重启或外部服务的验证，应在有恢复入口的隔离实例中另行安排。
