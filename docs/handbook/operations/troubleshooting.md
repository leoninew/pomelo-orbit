# 故障定位

本文按使用中的症状选择检查入口。先确定失败发生在配置、任务执行、容器还是访问链路，不要把反复提交、删除资源或换密钥当成通用修复方法。本指南适用于 `develop` 分支；具体按钮和配置以你的实例版本为准。

## 先保留一次失败的线索

1. 记录发生时间和时区、当前项目、操作类型，以及对应运行或部署编号；有请求编号时一并保留。
2. 打开**本次**记录，确认目标环境、服务、版本和目录，阅读状态、错误及最后一段相关日志。旧记录成功不能证明本次操作成功。
3. 区分“没有提交成功”“已受理仍等待”“执行失败”“执行完成但业务不可用”。网页超时、关闭页面或模型中断都不能证明任务没发生。
4. 在重新提交前刷新记录和真实资源，确认没有仍在执行的操作；准备修改目标、目录或数据时先安排备份与维护窗口。

不要公开完整环境变量、Compose、启动配置或原始日志。它们可能含密码、令牌、SSH 私钥、数据库连接串和业务数据；页面遮罩不保证复制结果或日志已经脱敏。

## 页面打不开、无法登录或没有权限

| 症状 | 先检查 | 下一步 |
| --- | --- | --- |
| 页面打不开 | 实例进程是否运行，访问地址、监听端口、反向代理和网络是否对应当前实例 | 由维护者检查启动日志与实际监听；不要通过重建数据库修复网页访问 |
| 页面可打开但登录失败 | 使用的是邮箱而非显示名称；账号是否启用，是否访问了正确实例 | 核对账号状态；需要恢复访问时联系有权限的管理员，不从测试数据推断默认密码 |
| 登录后没有项目或看不到资源 | 当前项目是否正确，账号是否加入该项目 | 请项目维护者核对成员；拥有系统角色不等于拥有所有项目 |
| 能看到页面但保存被拒绝 | 读取权限与写入权限是否同时满足，角色是否刚被修改 | 按权限指南核对具体操作；不要靠换 URL 或复用他人令牌绕过 |
| 本地 MCP / CLI 认证失败 | PAT 是否有效，配置、工作目录、数据库和主密钥是否匹配原实例 | 检查客户端配置并按需创建新 PAT；浏览器 JWT 不是 PAT，撤销后不要继续重试旧值 |

详细步骤见[用户、权限与访问令牌](../guides/users-access.md)及 [MCP 与 CLI](../reference/mcp-cli.md)。创建账号不会自动分配角色和项目成员；改密码、退出登录也不能替代撤销 PAT。

## 环境保存了，但无法执行

从“系统管理 → 环境”核对目标类型、平台、主机、用户和工作目录，再查看最近一次探测时间和诊断。

- **本机：** 指后端运行侧，不是浏览器电脑。后端在容器中时，核对容器内路径、Docker 访问权限及宿主机挂载的对应关系。
- **SSH：** 保存主机信息不会安装公钥。确认已审阅并在正确目标上执行初始化命令、远端授权用户正确，网络与 SSH 可达。
- **指纹错误：** 先通过可信管理通道确认目标身份；不要反复改主机、删除记录或切到本机来消除提示。
- **Docker / Compose 失败：** 普通 SSH 能登录不等于部署条件满足。核对执行用户的 Docker 权限、Compose、目录权限及目标平台要求。
- **旧探测成功：** 修改主机、目录或执行用户后，重新检查当前配置；历史结果不能证明新目标可用。

完整路径见[项目与执行环境](../guides/projects-environments.md)。改目标不会搬迁旧容器和数据，SSH 失败也不会回退到本机。

## 流水线不运行、失败或没有制品

| 所处阶段 | 检查位置与判断 | 后续处理 |
| --- | --- | --- |
| 没有运行按钮 | 当前是否为共享模板，而非项目应用流水线 | 先复用模板，再检查项目副本、仓库和阶段变量 |
| 提交前被拒绝 | 变量、依赖、ref、组件映射或环境校验信息 | 修正当前配置，不通过连续触发绕过 |
| 已受理但长期等待 | 本次运行状态、维护者看到的执行进程日志，以及目标是否发生变化 | 请维护者核对 Worker 是否正常运行、执行队列和当前配置；不要另开同库执行进程来试探 |
| 取源码失败 | 本次阶段的 ref、仓库认证方式、执行侧网络 | 核对仓库凭据与 Git 支持范围，不混用环境 SSH 凭据 |
| 脚本退出非零 | 失败阶段日志、镜像内工具和工作目录 | 先定位第一处实际失败，不只阅读最后的汇总错误 |
| 脚本成功但运行失败 | 制品收集命令、本地镜像检查、源码提交格式及应用版本生成错误 | 脚本成功不代表后续收集成功；逐项检查声明的输出 |
| 运行成功但缺少制品 | 是否声明并生成了对应文件，文件是否被跳过 | 核对实际制品，不把运行成功当作远程镜像已经推送的证据 |

参阅[仓库与仓库凭据](../guides/repositories-credentials.md)、[流水线与制品](../guides/pipelines-artifacts.md)和[变量与 Compose 约束](../reference/variables-compose.md)。重试按当前配置创建执行，不是旧快照的原样重放；取消或删除记录不是回滚。

## 服务预览或部署失败

1. **先检查服务预览。** 核对选中的版本、必填 Service 变量和组件覆盖。版本预览不读取某个服务的实际值，不能替代服务预览。
2. **再检查受理与执行。** “部署任务已创建”只表示受理；打开对应部署记录，核对版本、目标和目录，等待状态结束并阅读错误。
3. **按错误处理运行条件。** 拉取失败检查实际镜像与执行侧网络；目录冲突检查其他服务和历史目录；端口冲突检查宿主机占用；容器退出查看组件日志和健康检查。
4. **最后检查业务。** 容器运行、部署成功、业务访问是不同结果。业务仍不可用时继续检查下一节的访问链路。

保存服务变量或切换版本不会即时更新容器；修正后需重新预览并按维护安排部署。若环境在确认窗口打开后改变，重新打开窗口核对目标和部署目录。不要通过改目录、删除卷或删除失败服务来修复缺变量；失败状态不证明文件和容器已清理。

细节见[应用、版本与服务](../guides/applications-services.md)。状态检查只读取并按确认同步记录状态，不会重新部署或修复容器。

## 容器运行但访问失败

先明确你走的是“宿主机端口”还是“网关域名”，从客户端到服务逐层检查：

| 层次 | 要确认的事实 |
| --- | --- |
| 客户端与 DNS | 域名是否解析到预期地址，是否有代理或旧缓存；本地 `localhost` 是否误指访问者自己的电脑 |
| 端口与网络 | 目标宿主机端口映射、防火墙、网关入口是否实际存在；不要仅凭表单中的端口值判断 |
| TLS | 证书域名、有效期、客户端信任及 ACME 日志；规则加载不等于证书已签发 |
| 路由规则 | Traefik 中实际加载的提供者、Host、路径和目标；路径前缀匹配不会自动删掉前缀 |
| 下游服务 | 服务是否加入所需网络，目标组件与容器端口是否正确，业务进程是否在监听并正常响应 |

- 组件入口缺失：核对 HTTP 端点是否选择 `gateway`、服务是否加入 Traefik 网络并重新部署。
- 自定义路由保存后未生效：需要预览并确认同步，查看每项结果；部分成功不会自动全批回滚。
- TCP 路由无法连接：实际网关必须已有对应静态 entrypoint 和宿主机映射；路由同步不会自动添加它们。
- DNS 写入超时：先刷新上游实际记录再决定是否重试，避免重复写入。停止网关不会删除 DNS，也不会停止业务服务。

操作入口见[网关、DNS 与路由](../guides/gateway-dns-routes.md)。不要靠关闭认证、公开管理端口或放宽全部防火墙规则排障。

## 配置不生效或对话没有得到结果

| 症状 | 处理顺序 |
| --- | --- |
| 保存设置后当前值没变化 | 保存不是热更新；检查重启提示、实际启动目录及更高优先级覆盖，再安排相关进程重新加载 |
| `settings_revision_conflict` | 重新加载并比较其他人的变更，再编辑提交；不要重复覆盖旧 revision |
| `settings_store_busy` 或文件访问错误 | 核对协同进程、目录挂载和权限；保留恢复文件，不删除锁或恢复目录来解锁 |
| 重启后认证或凭据解密失败 | 检查是否换了数据库、profile、工作目录或主密钥；保全原配置，不再生成新密钥试探 |
| 部署对话不可用 | 核对对话权限、项目成员及 LLM 地址 / Key / 模型成组配置是否已生效 |
| 对话超时、断流或没有保存历史 | 先查工具涉及的服务、部署记录和实际资源；已发生操作不因模型失败自动回滚，不立即重发同一写入请求 |

参阅[配置与密钥](./configuration.md)及[部署对话](../guides/deployment-dialogue.md)。模型回答不是执行证明；历史缺失也不是“没有操作”的证明。

## 提交可用的问题反馈

向维护者或 [GitHub 仓库](https://github.com/leoninew/pomelo-orbit/issues)反馈时，提供：

- 实例版本、安装方式、平台，以及本机 / SSH 目标类型。
- 最少复现步骤、预期结果与实际结果；涉及外部写入时说明是否已检查真实资源。
- 发生时间和时区、运行 / 部署编号、脱敏的项目 / 服务标识及相关错误。
- 已检查的层次、最近是否改过版本、目录、配置或执行目标。

只截取必要的脱敏日志，不上传数据库、备份包、完整配置、PAT、密钥或带凭据的 URL。涉及安全问题时避免在公开 Issue 暴露可利用的细节，先使用仓库提供的安全反馈渠道。
