# 升级

平台升级与业务服务更新分别进行。平台启动会自动执行数据库向上迁移，升级前先完成[一致备份和恢复演练](./backup.md)。

## 升级步骤

1. 固定当前与目标版本，阅读变更和迁移要求，保留旧程序或镜像。
2. 排空或处置任务，停止旧 Web、Worker 及本地自动化进程。
3. 替换程序或镜像，保留已确认的数据挂载、配置根目录和原有主密钥。程序包的二进制与 `static/` 保持版本匹配。
4. 检查[配置来源](./configuration.md)，尤其是最高优先级的 `overwrite.env`。
5. 启动目标版本，检查迁移和运行日志，再恢复其他入口。
6. 验收登录、权限、配置、记录与文件，使用测试业务检查一次执行和访问。

旧版和新版避免同时对同一数据库执行任务或迁移。更换安装目录时，显式迁移相对路径中的数据库、日志和配置文件。

## 失败后处理

| 情况 | 处理 |
| --- | --- |
| 启动配置无效 | 检查新版本字段和组合约束，保留原密钥 |
| 迁移失败或 dirty | 停止其他写入，保全错误和数据，由维护者安排修复或恢复 |
| 已迁移但需退回 | 判断数据库兼容性；必要时恢复旧程序、匹配配置与升级前一致备份 |
| 恢复了数据库 | 核对容器、文件与外部服务的真实状态，协调恢复点之后的变更 |

旧二进制不能直接假定兼容已升级数据库。回退会涉及恢复点后的写入，保留备份至观察期结束，不修改已执行的迁移。
