# Compose 生成规则

平台将结构化版本、服务变量和组件覆盖合成为 Compose YAML。支持的配置以组件界面为准。

## 两种预览

| 入口 | 输入 |
| --- | --- |
| 版本预览 | 版本声明，使用合成的服务标识；可能保留变量占位符 |
| 服务预览 | 所选版本、服务实际变量和组件运行覆盖 |

预览使用合成路径，不连接 SSH 目标，不运行 `docker compose config`、拉取镜像或启动容器。目录权限、端口、Docker 版本及业务就绪在实际执行侧检查。

生成器将**环境变量值**中的 `$` 转为 `$$`，防止 Compose 再次插值。已经合成的环境值按字面值使用，其他字段不适用此规则。

## 命令与依赖

- 入口和命令按参数数组生成。管道、重定向等语法需要显式选择 shell；健康检查区分 `CMD` 与 `CMD-SHELL`。
- 依赖只能指向同版本组件，不能重复、自依赖或成环。
- 依赖条件为 `service_started`、`service_healthy` 或 `service_completed_successfully`；健康依赖的目标需配置健康检查。
- 端点暴露方式见[组件](../guides/components.md)，加入 Traefik 网络还需网关元数据和策略符合条件。

## 挂载

| 来源 | 准备要求 |
| --- | --- |
| `directory` | 执行时可按配置准备目录 |
| `file` | 文件预先存在 |
| `controlled_file` | 写入字面内容，不替换服务变量；最多 256 KiB，权限用 `0644` 等四位 Unix mode |
| `named_volume` | 使用卷名，不能含 `/` 或 `\` |

目录和文件使用明确的 `./...` 或绝对路径，不含 `..`；Windows 来源写作 `D:/data`，不支持反斜杠或 UNC。`source_is_host_path` 仅适用于目录 / 文件的绝对来源，表示 Docker 宿主路径，平台不物化该路径。

受控文件的部署写入策略只有“覆盖已有文件”和“保留已有文件”两项，版本与服务入口使用相同语义。相对来源随部署目录变化，策略作用于新目录中的目标文件，不自动搬移旧文件；修改目录前按[备份与恢复](../operations/backup.md)安排数据迁移。

### 服务受控文件覆盖

在服务组件的挂载编辑中，直接修改来源；目录和普通文件可设置只读，受控文件可编辑内容、权限和部署写入策略，不设置只读。修改的字段保存为服务配置，未操作的字段保持原设置；空内容和否值也会保存。挂载列表的“重置”可恢复整条挂载的版本设置。

| 部署写入策略 | 文件不存在 | 文件已存在 |
| --- | --- | --- |
| 覆盖已有文件 | 使用有效内容和权限创建 | 完整替换内容并应用权限 |
| 保留已有文件 | 使用有效内容和权限初始化 | 保留原内容和权限 |

覆盖模式适合由平台持续管理的配置；保留模式适合首次初始化后由应用或管理员维护的文件。编辑器显示平台保存的内容，不读取服务器当前文件。选择保留时，修改平台内容或权限、升级版本、重复部署和强制重建都不会替换已有文件；只有目标文件不存在时才使用新内容及权限初始化。需要平台更新已有文件时，显式选择覆盖策略并部署。

确认挂载编辑后仍需保存组件，文件写入发生在部署时。应用持续维护的状态通常适合持久化目录或卷；受控文件的保留模式适用于需要平台提供初始文件的场景。

文件替换采用临时文件重命名，已运行容器的单文件 bind mount 可能仍引用旧文件。需要加载替换后的文件时，部署选择“强制重建容器”；重建仍遵循文件的覆盖或保留策略。权限使用 `0000`–`0777`，Windows 目标不提供等价的 POSIX 权限保证。

受管 Gateway 也遵守所选覆盖/保留策略；选择保留时，其新生成的静态配置不会替换已有文件。Gateway 仍有独立的静态内容调整、选版和强制重建逻辑，这些行为不代表文件策略失效，也不表示已完成 Gateway 整体治理。
