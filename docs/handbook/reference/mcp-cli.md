# MCP 与 CLI

本文介绍本地 stdio MCP 和环境 CLI 的接入方式、项目选择及结果检查。先阅读[用户、权限与访问令牌](../guides/users-access.md)，准备合适的账号、项目成员关系和个人 PAT；SSH 前提见[项目与执行环境](../guides/projects-environments.md)。

本指南适用于 `develop` 分支，以已有实例、匹配的本地程序和个人 PAT 为前提。命令和参数仅说明使用方式；本文不提供程序下载、默认账号或完整工具目录。

## 选择入口

| 入口 | 当前用途 | 执行位置与边界 |
| --- | --- | --- |
| `mcp` | 让支持 stdio 的代理操作项目、应用、服务、部署及网络等资源 | 客户端启动本地程序，使用配置选中的实例数据和执行资源；不是连接 Web 地址的远程客户端 |
| `cli env` | 列出 SSH 环境、执行远程命令、交互 SSH 和本地端口转发 | 本地进程读取相同实例配置，经受管 SSH 身份访问目标；不是所有 Web 功能的命令行版 |

“本地”指启动 MCP / CLI 的进程所在主机，不是浏览器设备；在远程开发容器中启动时，网络、路径和本地转发端口也属于该容器侧。

## 准备同一实例的配置

1. 请实例维护者准备与实例版本匹配的可信程序、已初始化数据库的访问配置及原有密钥。不要为了接入客户端重新生成实例密钥；无需先搭建源码开发环境。
2. 将启动工作目录明确设为包含 `configs/config.yaml` 的应用配置根目录，不能只使用程序所在目录或任意父目录。相对数据库和运行路径也可能受工作目录影响。
3. 选择与实例一致的 profile，并核对数据库 URL、密钥及 `POMELO_ORBIT_MCP__ACCESS_TOKEN`。PAT 使用所有者当前身份，没有每令牌只读或单项目限制；不需要为了外部 stdio 客户端另配 LLM。
4. 经可信父进程环境或被 Git 忽略的启动 dotenv 注入秘密，不在客户端的受版本控制配置、命令参数或公开日志里填写真实令牌、密钥或数据库密码。

配置从 `configs/config.yaml`、可选的 `configs/config.<profile>.yaml`、`.env` 或 `.env.<profile>`、OS 环境变量依次覆盖，工作目录的 `overwrite.env` 优先级最高。profile 由 `POMELO_ORBIT_APP__ENV` 选择，`overwrite.env` 也可覆盖它；不要只看终端环境就认定最终配置，也不要依赖向父目录自动查找配置。

有 profile 时只读对应 dotenv，不叠加 `.env`；系统设置保存也不会让已经运行的本地进程热更新。完整来源、设置基线 / 当前值和 JWT 密钥兼作凭据加密密钥的风险见[配置与密钥](../operations/configuration.md)。

配置是进程启动时的快照。替换 PAT 或更改配置后应由客户端建立新 MCP 进程 / 会话，CLI 则使用新的调用；这不要求重启 Web 服务，也不代表可以未经维护安排切换实例数据库。

若 Web 实例运行在另一主机或容器，仅复制 Web 地址或相对 SQLite URL 不会连接到同一实例；还需正确准备数据库访问、文件路径、挂载与执行资源。本文不提供跨主机分发方案，不假定这些资源自动共享。

MCP / CLI 不执行数据库迁移，不自动启动 HTTP 服务或 Worker。异步部署仍需目标实例已有受管理的执行进程处理；单独启动 MCP 不会把排队操作跑完。不要用空数据库或误指向的新 SQLite 文件试探连接。

## 配置 stdio MCP

客户端所需的启动字段如下，具体配置语法以使用的客户端为准；这不是可直接粘贴到所有客户端的完整配置文件。

| 字段 | 填写要求 |
| --- | --- |
| 命令 | 维护者准备的 `pomelo-orbit` 程序绝对路径；Windows 使用对应 `.exe` 文件 |
| 参数数组 | `["mcp"]` |
| 工作目录 | 实际应用配置根目录的绝对路径 |
| 非秘密环境 | `POMELO_ORBIT_APP__ENV` 使用与实例一致的 profile，不照搬其他环境的值 |
| 秘密环境 | 从可信来源注入 `POMELO_ORBIT_MCP__ACCESS_TOKEN` 及实例所需配置，不硬编码值 |

**不能省略 `mcp` 子命令：直接运行程序默认启动服务，不是 MCP。** 客户端能够启动进程也不代表身份和项目已确认，还要完成下面的读取步骤。

stdio 的标准输出属于协议，诊断写入标准错误及配置的日志文件。不要把日志合并到协议标准输出，也不要在包装脚本中向 stdout 打印欢迎语。当前入口不是 HTTP MCP URL，不应为它猜测 `/mcp` 路由或开放监听端口。

### 先走通最小读取路径

在客户端依次选择或要求代理调用以下工具。参数只作填写示意，不是终端命令；项目 ID 必须来自你有权访问的真实列表。

| 顺序 | 工具 | 参数及检查点 |
| --- | --- | --- |
| 1 | `orbit_list_projects` | `{}`；从 `projects` 核对 `id`、`code`、名称和 `is_active` |
| 2 | `orbit_select_project` | `{"project_id":"<列表返回的项目 ID>"}`；明确确认目标，不传项目编码或名称 |
| 3 | `orbit_get_current_project` | `{}`；再次核对返回的项目、环境、网关和服务摘要 |
| 4 | `orbit_list_applications` | `{}`；默认查询 `standard` 应用，空列表也可能是正常结果 |

项目选择要求用户是成员，且项目已有环境、网关及网关服务记录；缺少时会返回 `project_not_ready`，应先在 Web 完成相应准备，不是用 `orbit_provision_gateway` 从空项目补齐整个初始化。

这里的“就绪”不要求 Probe 成功，也不检查网关容器一定已运行；选择成功不证明 Docker、SSH、DNS、证书或业务连通。上述最小路线不包含主动探测、部署或网络写入。

### 管理连接内的项目作用域

- 后续项目操作使用当前连接的选择；读取详情后核对应用、版本和服务是否属于该项目。
- stdio 连接可重新选择另一所属项目；选择不是给 PAT 绑定永久项目，也不改变 Web 当前项目。新进程应重新列出并选择，不假定继承之前的连接状态。
- 同一连接先等待选择完成，再按该范围操作；不要并发切换项目并发起写入。每次重要操作前重新核对当前项目和资源。
- 应用内[部署对话](../guides/deployment-dialogue.md)使用当前登录用户和页面选定项目，不要求个人 PAT；换项目应从页面操作，不能照搬本地连接中的项目切换方式。

### 判断工具结果，而不只看调用返回

查看客户端显示的参数要求、结果和错误提示。仅能连接或列出工具不代表 PAT 可用，每次实际调用仍会检查身份。`unauthorized` 时先检查身份，`project_not_selected` 时先选项目，不盲目重试写入。

工具并非都只读：配置修改、DNS 写入、路由同步和部署会产生真实影响；带有 `probe`、`runtime` 或 `verify` 的诊断也可能连接执行侧、运行容器命令或网络请求。日志、Compose 配置及原始诊断可能包含敏感数据，不能假设自动脱敏或可直接发给外部代理。

读取或修改服务环境前，先按[变量与 Compose 约束](./variables-compose.md)核对完整占位符、组件字面覆盖与删除；保存和生成预览都不代表运行容器已更新，返回的预览内容也可能包含真实值。

工具显示的操作摘要不能代替运行结果，也不是要求你按其中的地址再执行一次操作；先检查实际资源，避免重复写入。

需要实际部署时，先按[应用、版本与服务](../guides/applications-services.md)确认版本、运行配置、完整部署目录和当前执行目标，再使用 `orbit_deploy` 等写入工具；参数以客户端当前显示的要求为准。发送前自行确认操作授权，工具不会替你作业务决定。

| 观察入口 | 结果应怎样理解 |
| --- | --- |
| `orbit_deploy` 返回 `deployment_id` | 已创建操作记录，不是容器更新成功；后续按该 ID 检查 |
| `orbit_deployment_status` | 查看当前 `deployment` 状态和命令，不以历史成功覆盖新操作 |
| `orbit_deployment_logs` | 传入 `deployment_id` 和增量 `offset`，检查返回的日志、offset、完成标记及状态 |
| `orbit_wait_deployment` | 检查 `timed_out` 和部署状态；等待超时不取消部署，终态也可能是失败 |

停止 MCP 客户端不负责取消已受理部署；超时或连接丢失后先查看当前记录，不假定没有发生，也不立即重发写入。容器状态、外部入口与 TLS 信任仍需分别验证，见[网关、DNS 与路由](../guides/gateway-dns-routes.md)。

## 使用环境 CLI

环境命令行提供 `cli env list`、`exec`、`ssh` 和 `forward start/status/stop`，不覆盖 Web 中所有业务操作。

以下命令从本地 Bash 发起，用 `pomelo-orbit` 代称已经准备的可信程序；若不在 PATH 中，使用它的实际路径，Windows 使用对应 `.exe` 文件。在实例配置根目录运行，PAT、数据库与密钥按前述方式注入，不写在命令中。远程程序和路径仍按目标平台选择，不因本地使用 Bash 而改变。

```bash
pomelo-orbit cli env --help
pomelo-orbit cli env list --json
```

先查看帮助以确认当前程序支持的参数，再列出可见环境。帮助命令不需要连接实例，但列表等业务操作会访问实例数据并检查 PAT；帮助能打开不代表已连通。

### 列表与项目编码

`env list --json` 返回 `projects`，只含当前成员可见、已配置为 SSH 的环境，按项目编码排序；本机或未配置环境不出现在这里。列表不是连接测试，也不要求已有网关或探测成功，出现目标不表示已具备 SSH 凭据或能执行命令。

后续 `--project` 使用**精确项目编码**，不是 MCP 的项目 ID、名称或当前浏览器项目。列表 JSON 还可核对环境、平台、主机、端口、用户及 `is_active`，不要只凭名称猜测目标。

### 执行单次远程命令

下面仅展示读取目标身份的参数；把 `demo` 换成已确认的项目编码，并确认相应程序在远端可用：

```bash
# Linux SSH target
pomelo-orbit cli env exec --project demo --json -- whoami

# Windows SSH target
pomelo-orbit cli env exec --project demo --json -- whoami.exe
```

- `--` 后是程序和字面参数，不默认解析管道、重定向、`$HOME` 或脚本表达式；本地 shell 的引用和展开仍会先发生。需要 shell 时必须显式调用，执行风险也随之扩大。
- `--workdir` 默认为已保存的环境工作区，也可传目标平台的绝对路径或 `~` / `~/...`；它不是本地文件路径，目录需存在且可访问。
- `--timeout` 默认 60 秒，范围 1–300 秒；默认向远端 stdin 发送 EOF，只有指定 `--stdin` 才读取本地输入，最多 64 KiB。
- stdout 与 stderr 合计最多 1 MiB，超限结果标为 `output_limit` 并截断。非 JSON 模式分别输出原始字节；`--json` 返回状态、远端退出码、时长和文本，非法 UTF-8 用替代字符并标记 `output_decoding_replaced`，不适合无损传输二进制。

当前 CLI 会使用受管 SSH 凭据并确认主机指纹，不因 SSH 失败退回本机。命令或转发连接首次确认可能记录主机指纹，不应将普通远程读取包装成完全无状态操作；需经可信渠道确认目标身份。运行中也会检查成员及目标 / 凭据变化，但这不是持续轮询 PAT 是否撤销。

自动化应同时检查结果状态和进程退出码。以下是**直接执行二进制时**的 `exec` 映射；远端程序也可能返回同样数值，不能只靠数字区分原因：

| 结果 | 退出码与判断 |
| --- | --- |
| `exited` | 使用已知的远端 0–255 退出码；`exit_code=0` 才表示该命令正常退出 |
| `timed_out` | 124；不知道远端业务是否已产生影响 |
| `output_limit` / `access_or_target_changed` | 125；结果不完整，先检查输出或访问与目标变更 |
| `transport_lost` 或一般平台错误 | 255；没有可靠远端退出结果，不自动重试写入 |
| 参数校验 / 本地取消 / 配置加载错误 | 分别可能为 2 / 130 / 1，需结合实际错误判断 |

`--json` 的平台失败可能返回 `state=platform_error` 和错误文本，不保证每种参数错误都有 JSON。连接关闭或本地取消不保证远端进程及其派生任务全部停止，应另行核对远端状态。

### 交互 SSH

`cli env ssh --project demo` 要求 stdin 和 stdout 都是 TTY，不适用于普通管道或无人值守脚本；不带 `--project` 时可从可见 SSH 项目中交互选择。`Ctrl+]` 在本地断开，`Ctrl+C` 通常交给远端 shell。会话有连接、空闲和总时长限制，不是持久后台任务容器。

不要在 shell 中执行未经确认的生产命令，也不要依赖断开终端替你回滚远端修改。

### 后台端口转发

确认本地端口未占用、目标服务已准备后，按下面的方式建立转发。命令会建立或停止真实监听，不要将其当作无副作用的检查：

```bash
pomelo-orbit cli env forward start --project demo -p 15432:5432
pomelo-orbit cli env forward status -p 15432 --json
pomelo-orbit cli env forward stop -p 15432
```

`-p` / `--port` 的启动格式是 `LOCAL:REMOTE`，两端端口范围均为 1–65535。本地监听 `127.0.0.1:LOCAL`，SSH 远端连接该主机的 `127.0.0.1:REMOTE`，不是任意目标地址、反向转发或对公网开放；远端服务及其认证仍需单独准备。监听就绪不证明远端服务可用。

启动会派生后台进程；退出启动命令不等于停止转发。使用相同配置根工作目录和 OS 用户运行 `status` / `stop`，本地记录位于 `data/cli/forward/` 下的用户隔离目录；改目录或换用户可能找不到记录，不能据此断言端口没有监听。不要手工删除记录或按未知 PID 终止进程来代替受管停止。

`status` / `stop` 仅控制当前 OS 用户在该目录的受管进程，不打开业务数据库或校验 PAT，但仍需通过应用配置加载。停止成功后核对反馈；“没有记录”只说明当前本地管理范围内未找到，状态不响应或停止失败不能当作已停止。PAT 撤销不代替转发停止；成员 / 目标变化或 SSH 丢失可使连接终止，不承诺所有远端进程也已退出。

## 常见定位顺序

1. 启动失败：检查显式子命令、工作目录、配置文件及 profile / 覆盖来源；不要以换密钥、初始化新库或启动迁移来绕过。
2. 认证或项目错误：检查 PAT、账号状态、成员关系；分清 MCP 的项目 ID 和 CLI 的项目编码，并重新核对连接范围。
3. 工具 / 命令失败：保留脱敏错误、状态和资源标识，区分配置错误、拒绝访问、目标变化和执行结果未知，先查已有操作再决定重试。
4. 输出与网络问题：分别检查 stdout 协议污染、CLI JSON / 原始输出、本地转发管理范围、SSH 与远端服务；反馈不包含真实 PAT、认证头、私钥或敏感原始日志。
