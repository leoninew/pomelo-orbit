# 变量与 Compose 约束

本文用于查明“这个值由谁提供、在哪一层展开、预览证明了什么”。先了解[流水线与制品](../guides/pipelines-artifacts.md)及[应用、版本与服务](../guides/applications-services.md)的操作路径，不要把不同页面中相似的变量语法视为同一种机制。

本指南适用于 `develop` 分支。字段示意用于说明页面填写方式，不是可直接运行的部署样例；真实值应在相应仓库、流水线或服务中配置。

## 按任务选择配置入口

1. **给构建脚本提供值：** 在仓库或流水线的变量区域配置，再查看本次运行的变量快照。不要把它填写到业务服务中。
2. **给业务组件提供不同服务的值：** 在版本组件的环境变量中声明完整占位符，再到服务详情填写实际值；仅在服务中新增键不会自动传给所有组件。
3. **只改变一个服务组件：** 在服务组件详情选择继承、覆盖或删除。保存后先查看服务预览，再按[应用、版本与服务](../guides/applications-services.md)重新部署并检查结果。

## 先区分五个层次

| 层次 | 值从哪里来 | 作用边界 |
| --- | --- | --- |
| 实例启动配置 | `POMELO_ORBIT_*`、配置文件和启动 dotenv | 配置平台进程，不是给所有流水线和业务容器提供同名变量；来源、覆盖和重启规则见[配置与密钥](../operations/configuration.md) |
| CI 模板变量 | 仓库、流水线全局 / 阶段配置及内建上下文 | 在阶段脚本和制品的名称、引用、命令中使用 Liquid；解析后的阶段变量也作为该阶段的环境值传入 |
| Service 环境变量 | 服务详情保存的键和值 | 供版本组件环境变量的完整占位符读取，不自动注入每个组件 |
| 组件容器环境 | 版本声明，加上服务组件的继承 / 覆盖 / 删除 | 决定生成 Compose 中该组件的 `environment` |
| 执行 shell 与 Compose | 实际执行程序自己的语法和环境 | 不等于平台模板解析器；例如 shell 的 `$NAME` 不是 Liquid 引用 |

CI 变量不会因为同名就自动成为 Service 环境变量。启动目录的 dotenv 也不是业务服务的变量仓库；先确定要修改的对象，再选择配置入口。

## 流水线：Liquid 引用与取值

### 名称、作用域与默认值

可配置的 CI 变量名以英文字母开头，后续允许字母、数字和下划线，即 `^[A-Za-z][A-Za-z0-9_]*$`。同名、同作用域不能重复；阶段私有配置必须对应当前流水线的阶段，不同阶段可以有同名配置。

- 简单引用写作 <code v-pre>{{ APP_MODE }}</code>。
- 引用处的字面默认值写作 <code v-pre>{{ APP_MODE | default: "test" }}</code>，也可使用单引号包围字面值。
- 不用 `${APP_MODE:-test}`、`${APP_MODE:=test}` 或 `${APP_MODE-test}` 代替上述写法；当前模板字段会拒绝这类 shell 默认值语法。
- 配置变量时使用上述简单引用和字面默认值；任意过滤器、对象路径或条件表达式不一定会成为界面中的可编辑变量。

在每一份保存的配置中，先取“值”，没有有效值时再取“默认值”。未填写、空串或只有空白都不算有效 CI 值。普通阶段的同名取值按以下顺序选择第一个有效配置：

1. 仓库配置。
2. 流水线中该阶段的配置。
3. 流水线全局配置。
4. 当前 Liquid 引用处的默认值。

因此仓库中的有效值会覆盖阶段配置；仓库只有空配置时，仍可继续查找下层值。引用处的默认值只用于该引用，不会变成其他阶段可用的全局值。已经声明但最终缺值的全局项也可能阻止运行，不要以“脚本暂时没用它”为由保留无效配置。

运行对话框主要用于确认分支或标签，不是任意变量编辑器。重试会优先复用原运行中允许保留的值；排查重试取值时同时查看原运行，不只看当前仓库页面。

### 内建上下文与嵌套值

| 内建名称 | 含义 |
| --- | --- |
| `repository_code` | 绑定仓库的编码 |
| `repository_url` | 绑定仓库的源码位置 |
| `repository_ref` | 本次选择的 ref；未另选时使用仓库默认分支 |
| `runtime_datetime` | 本次运行的 UTC 时间文本，格式为 `YYYYmmdd-HHmmss` |

普通自定义配置不能覆盖内建上下文；`repository_ref` 通过运行 / 重试路径选择，不是靠新增同名自定义变量改写。

填写“值”时可以用简单引用嵌套，例如 <code v-pre>{{ repository_code }}-web</code>。嵌套值不支持过滤器、点路径或标签；填写“默认值”时只用普通文本，不含 Liquid 分隔符。未知引用、循环引用和不完整表达式会被拒绝。

全局值不能引用阶段私有值，一个阶段也不能读取另一阶段的私有值。即使较高优先级的仓库值遮住了某项，无效的嵌套定义仍可能被校验拒绝，应修正定义本身。

### 用运行快照解释历史

仓库或流水线的变量页面描述当前配置，不等于某次 Run 的实际输入。排查时查看本次运行的定义、变量及作用域快照；重试使用当前定义和允许复用的原值并重新校验，**不是重放旧快照**。

敏感标记和页面遮罩不保证脚本、日志或制品自动脱敏。Liquid 插入脚本文本也不负责 shell 参数引用或转义；不要把不可信输入直接拼成可执行片段，更不要用打印全部环境的方式调试秘密。

## Service：只解析完整环境值

Service 环境变量名允许字母或下划线开头，后续允许字母、数字和下划线，即 `^[A-Za-z_][A-Za-z0-9_]*$`；键会去除首尾空白并检查重复，值原样保留。这与 CI 的空白有效值判断不同。

在**版本组件的环境变量值**中使用完整占位符，不能在外侧加空格或只引用字符串的一部分：

| 版本声明值 | 当前解析规则 |
| --- | --- |
| `${KEY}` | 服务必须有该键，且值不是空字符串，否则无法通过服务预览或部署配置检查 |
| `${KEY:?message}` | 同样要求存在且非空；不要依赖 `message` 作为自定义执行逻辑 |
| `${KEY:-fallback}` | 键不存在时取字面 `fallback`；键存在但值为空时保留空串 |
| `https://${HOST}/api`、`$KEY` 或其他不匹配写法 | 不替换其中的变量，保留原样 |

**`${KEY:-fallback}` 不完全遵循原生 Compose 的默认值语义。** 这里的空串不会触发回退；必填检查也只排除空串，纯空白并不会被视为缺值，应在保存前自行核对。

不要在服务的值中再写 `${OTHER}`，平台不会继续替换。镜像、命令和受控文件内容也不会按这套规则替换。需要完整地址时，将完整值放在服务的 `APP_URL`，版本中只写 `${APP_URL}`，不要拼成 `https://${HOST}/...`。

### 非敏感字段示意

下表只展示环境字段，不提供镜像或可执行 Compose。假设服务组件保持继承：

| 版本组件中的环境键 | 版本声明值 | 服务配置 | 组件最终取值 |
| --- | --- | --- | --- |
| `APP_MODE` | `${APP_MODE}` | `APP_MODE=test` | `test` |
| `APP_URL` | `${APP_URL}` | `APP_URL=https://app.example.invalid/api` | 完整地址，不再拼接 |
| `LOG_LEVEL` | `${LOG_LEVEL:-info}` | 不保存 `LOG_LEVEL` 键 | `info` |
| `LOG_LEVEL` | `${LOG_LEVEL:-info}` | 保存该键，值为空串 | 空串，不是 `info` |

最后两行是两种不同情况，不是在同一组件中声明重名键。真实秘密应由服务侧准备，在需要它的版本组件中精确引用，不复制进公共版本、截图或示例。

### 组件继承、覆盖与删除

| 服务组件中的状态 | 结果 |
| --- | --- |
| 继承，没有覆盖项 | 使用版本声明，并解析其中完整的 Service 占位符 |
| 覆盖 | 使用提供的字面值，不再解析一次 Service 占位符 |
| 删除 | 从该组件的最终环境中省略这个键 |
| 恢复继承 / 重置 | 移除覆盖，重新使用版本声明及其解析规则 |

空串覆盖会保留一个值为空的环境键，不等于删除。在覆盖值中写 `${APP_MODE}` 也不会获得 Service 的 `APP_MODE`；需要读取它时应恢复继承，并让版本声明引用它。

覆盖只能作用于所选版本中已声明的环境键，不能借服务覆盖新增组件、未声明的环境 / 挂载 / 端点或更换镜像。镜像变化通过版本定义处理，其他字段按界面允许的覆盖范围修改。

服务配置可以保存、详情可以打开，不代表必填值已经齐全；部署前先用服务预览检查。修改配置不会立即更新容器，需要重新部署并检查本次记录。数据库初始化凭据通常只在空数据卷上生效，重新部署不等于修改已有数据库密码；不要通过删除卷试图修复变量问题。

## 生成的 Compose 能证明什么

平台根据结构化组件和服务配置生成 YAML，预览不是任意 Compose 编辑器，也不承诺支持完整 Compose 字段或任意文件导入。

| 入口 | 使用的输入 | 不会证明什么 |
| --- | --- | --- |
| 版本预览 | 版本声明，使用合成的预览服务标识；不读取某个 Service 的实际值或覆盖 | 可能保留声明中的占位符，不能证明 Service 必填值齐全 |
| 服务预览 | 当前选中版本、服务环境值及组件覆盖合成后的配置 | 不等于已部署，也不读取正在运行容器的真实环境 |
| 实际部署 | 冻结本次输入、核对执行目标并在执行侧操作 | 请求受理仍不是成功，需检查本次部署和业务结果 |

预览使用合成路径，不解析实际 SSH 目标和远程工作区。它不执行 `docker compose config`、镜像拉取或容器启动，也不验证 Docker / Compose 版本、目录权限、端口占用、GPU、镜像可用性或业务就绪。加入 Traefik 网络时还需网关元数据及策略满足条件，不能假定预览会自动创建网关。

生成器会把**环境变量值中的**每个 `$` 转成 `$$`，避免 Compose 再按宿主环境插值。因此已合成的环境值应按字面值理解，不能再靠宿主 dotenv 补齐；未被平台识别的 `prefix${KEY}` 也不会因此得到展开。不要把这个转义规则推及命令、健康检查或所有 YAML 字段，更不要把 `$$` 当作加密。

服务预览和执行文件可能包含真实解析后的环境值。页面遮罩不会自动保护这些输出；分享前逐项脱敏，不把完整预览、Compose 文件或容器环境贴入公开问题。

## 常用结构化配置的限制

### 命令、依赖与网络

- 组件名在版本内唯一，以小写字母开头，只含小写字母、数字和连字符；镜像必填，但预览不会检查能否拉取。
- 入口和命令按参数数组生成，不自动解释管道、重定向和其他 shell 运算符。确有需要时显式选择 shell，并承担对应风险；健康检查的 `CMD` 与 `CMD-SHELL` 也要区分。
- 依赖只能指向当前版本已有组件，不能重复、自依赖或成环；条件为 `service_started`、`service_healthy` 或 `service_completed_successfully`。健康依赖需要目标组件实际具备健康检查，不能用依赖条件代替业务就绪验证。
- 端点使用 `internal`、`local`、`host` 或 `gateway` 模式；`gateway` 仅支持 HTTP，生成入口需加入网关网络。端口发布、路由与 DNS 的分层检查见[网关、DNS 与路由](../guides/gateway-dns-routes.md)。

### 挂载与受控文件

| 来源类型 | 行为与准备要求 |
| --- | --- |
| `directory` | 执行时可按配置准备目录；不能把目录创建理解为数据恢复 |
| `file` | 文件应预先存在，平台不替你生成内容 |
| `controlled_file` | 执行时写入保存的字面内容，不做 Service 变量替换；内容最多 256 KiB，权限使用 `0644` 这类四位 Unix mode |
| `named_volume` | 来源是卷名，不能含 `/` 或 `\`；不使用宿主路径或文件内容选项 |

目录 / 文件类来源使用明确的 `./...` 或绝对路径，不写裸路径 `data`，不包含 `..` 路径段；Windows 来源使用 `D:/data` 这类正斜杠形式，不使用反斜杠或 UNC。`source_is_host_path` 仅用于 `directory` / `file` 的绝对来源，表示 Docker 宿主路径，不由平台物化目录或文件。

受控文件的 `ignore_if_exists` 可保留已有文件，修改保存内容不保证覆盖它，更不是密码轮换机制。相对来源与部署目录相关，改目录不会搬迁旧数据；挂载目标、权限和镜像内实际用途仍应按运行环境核对。预览不会创建这些目录和文件，不要为消除校验错误而清理现有数据。

## 按现象定位

| 现象 | 优先核对 |
| --- | --- |
| CI 缺变量或取值意外 | 名称 / 阶段作用域、有效值优先级、嵌套定义，再看本次 Run 快照 |
| Service 缺少必填值 | 是否在正确服务保存了精确键、是否为空串、组件是否仍继承该版本声明 |
| 保存了 Service 值但容器没有 | 版本是否声明并完整引用该键、是否被字面覆盖 / 删除、是否已重新部署 |
| 默认值没有生效 | 先分 CI 与 Service；Service 键存在但空串时不会用 `:-` 回退 |
| 版本预览与服务预览不同 | 前者只有声明，后者合成实际 Service 值和覆盖；都不是容器实况 |
| 预览通过但部署失败 | 本次执行目标、镜像、实际路径 / 权限、挂载、端口和 Docker 条件；不反复改变量绕过 |

反馈时只保留脱敏键名、声明形式、继承状态、版本 / 服务及本次操作标识。需要执行时回到[应用、版本与服务](../guides/applications-services.md)；自动化读取或写入的身份与结果边界见 [MCP 与 CLI](./mcp-cli.md)。
