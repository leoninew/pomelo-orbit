# 移除环境领域

最后修改时间: 2026-07-26 16:40:51

Review status: Accepted

## Background

当前系统把环境作为项目下的独立资源，并将其用于服务实例、部署记录、Compose 工作目录、API 和前端导航。当前没有多机部署计划，该层级不能提供实际业务价值，反而使部署、服务查看和配置流程多出无意义选择。

## Goal

- 从数据库最终结构、后端领域/API/Proto、部署运行路径和前端页面中移除环境概念。
- 同步移除 MCP 客户端的环境工具、请求字段和运行目录层级。
- 服务运行绑定以应用和实例键唯一定位；部署、重启、停止、状态查询、日志和预览不再接收或推导环境。
- Compose 工作目录以应用和实例构成，不再创建环境目录层级。
- 删除环境的导航项、路由、页面、前端 API 和展示字段。

## Non-goal

- 不实现多主机、多环境或环境替代概念。
- 不移除项目、应用、版本、实例、服务或网关领域。
- 不保留环境 REST/Proto 参数、前端路由或兼容映射。
- 不重构与环境无关的部署、枚举展示和页面样式逻辑。

## User scenarios

- 用户部署应用版本时只选择版本和实例，不再选择环境。
- 用户从应用或服务页面执行停止、重启、查看状态和日志时，系统以服务 ID 或应用加实例键定位运行实例。
- 用户查看服务、部署记录和应用详情时，不再看到环境名称、编码或筛选条件。
- 用户在持续部署导航中不再看到环境页面，也无法调用环境管理 API。

## Acceptance

- 最终数据库没有 `environment` 表，`service` 和 `deployment` 没有 `environment_id` 列或外键；服务唯一键为应用和实例键。
- 后端不存在环境模型、仓储、用例、HTTP 处理器、路由或依赖注入；Proto 和生成的 Go/TypeScript 类型不再声明环境消息或字段。
- 部署、服务、应用版本预览和运行查询的接口、DTO、存储端口、Compose 项目名及工作目录不再接收、查询或使用环境。
- 前端没有环境页面、路由、导航、API 客户端、i18n 词条、部署表单字段、服务字段或查询参数。
- MCP 不再请求环境 API 或接受环境 ID；运行工具以应用和实例键定位工作目录。
- 开发数据库通过重建使用删除环境后的初始结构，不提供增量迁移或旧记录折叠。
- SQLC 与 Proto 生成代码重新生成，后端和前端相关检查通过。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

- 保留实例键作为应用下运行实例的唯一业务维度。
- 环境 API 和数据不做向后兼容；客户端必须使用删除环境字段后的契约。
- 开发阶段直接修改既有建表和种子脚本，数据库需要重建，不提供增量迁移。

## Risk

- 该变更会破坏现有 API、Proto 和数据库结构；开发数据库必须重建，旧前端或外部调用方不能继续工作。
- 不提供已存在环境数据的迁移、折叠或恢复路径。
