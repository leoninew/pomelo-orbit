# 表单校验反馈统一
最后修改时间: 2026-07-31 09:43:37

Review status: Accepted

## Background

当前前端的业务表单同时存在缺失校验、校验失败只显示在表单底部或 Toast、选择控件没有错误边框，以及模态窗提交行为影响背景界面的情况。已有部分表单的错误样式与登录表单不一致。

## Goal

- 审视业务表单的提交校验路径，缺失的必填与格式校验补齐到对应表单控件。
- 本地校验失败时，在对应控件正下方显示 12px 红色错误信息，并以红色边框标记控件，交互效果与登录表单一致。
- 模态窗的确认操作只触发当前模态窗的处理逻辑，不应提交或影响背景页面表单。
- 业务表单的必填标签显示红色 `*`；未显示 `*` 的字段视为可选，不再追加“（可选）”等文字。

## Non-goal

- 不改变后端接口校验、错误契约或服务端返回的业务错误语义。
- 不将网络请求、加载、权限或异步操作失败强行映射为字段校验错误；这类错误仍可使用 Toast 或页面级错误状态。
- 登录和密码类非业务表单不受必填星号规范约束。
- 不启动、停止或访问开发服务器；运行态验收由用户自行完成。

## User scenarios

- 用户在创建、编辑或部署等业务模态窗中遗漏必填内容时，立即能看到对应控件的红色边框和下方错误文本。
- 用户修正字段内容或重新选择选项后，该字段的错误状态清除，不影响其他字段。
- 用户在任何业务模态窗点击确认或按回车时，不会向背后的页面表单传播提交事件。
- 用户通过标签上的 `*` 区分必填与可选字段，无需阅读额外的可选提示。

## Acceptance

- 所有已识别的业务表单本地校验错误都紧邻对应控件展示，使用统一的 12px 红色样式和错误边框。
- 选择类控件（原生 select、RawValueSelect、SelectControl、ComboboxSelect）支持同样的错误边框与字段错误文本。
- 不再存在使用 Toast 或底部通用 tip 作为本地字段校验唯一反馈的提交路径。
- 模态窗确认按钮不使用 HTML `form` 关联来跨层提交；回车提交仅在当前表单范围内生效。
- 业务表单中的逻辑必填字段有红色 `*`，可选字段不显示“可选”文字。
- 类型检查、lint/format、构建等静态验证在后续 Verification / 验证阶段记录；不启动开发服务器。

## Open questions

暂无需要用户确认的未决事项。默认将“业务表单”理解为应用、组件、服务、网关、流水线、仓库、路由、项目、凭据等管理表单；登录和密码类表单按用户说明排除。

## Decisions

- 复用登录表单的 `app-input-error` 与 `app-field-error` 视觉和交互模式。
- 保留 Toast 用于无法可靠归属到单一控件的异步失败，不作为本地字段校验的替代品。
- 模态窗操作使用显式点击处理函数，避免 footer 按钮通过 `form` 属性触发背景表单。
- 业务代码不为旧数据做兼容或静默适配；如发现旧数据与当前业务规则冲突，应检查开发库并就地修正数据，而不是在前端隐藏或吞掉异常值。

## Risk

- 组件配置类编辑窗含有动态行与条件字段，字段错误映射需要与现有序列化校验保持一致，避免提示位置和实际拒绝条件不一致。
- 本轮只进行静态检查，不替代用户的运行态交互验证。
