# 详情页面包屑
最后修改时间: 2026-08-15 12:03:29

Review status: Accepted

## Background

当前详情页层级较深，但部分页面只提供返回按钮，或者用过于泛化的面包屑节点。用户从应用、版本、服务和组件详情继续深入时，缺少清晰的父实体入口，且顶级模块名并不适合作为 breadcrumb。

## Goal

为详情和编辑页提供一致、可访问、可本地化的父实体导航；导航路径与当前页标题合并为同一个头部，页面保留既有返回按钮与操作区。

## Non-goal

- 不调整 API 路由或后端响应契约。
- 不引入集中式 breadcrumb 映射表或路由猜测逻辑。
- 不在顶级模块名和当前页标题之间再加一层无意义的 breadcrumb。
- 不改变既有详情页的数据加载、操作权限或返回行为。

## User scenarios

- 用户在版本组件页可跳转回所属版本和应用。
- 用户在服务组件配置页可跳转回所属服务和应用。
- 用户在持续集成任一详情页可识别当前资源所属列表；快照可跳转回流水线。
- 用户在网关编辑页可返回网关详情或网关列表。

## Acceptance

- 提供共享详情头部组件：祖先路径是语义化导航，当前页标题是同一头部内唯一的 `h1`。
- 需要祖先导航的详情页自行声明面包屑数据，且面包屑内容使用该页面已加载的真实父实体名称。
- 版本组件页至少展示应用与版本两级，服务组件页至少展示应用与服务两级。
- 顶级详情页不渲染无意义的模块级 breadcrumb，例如“持续部署”或“持续集成”。
- 路径中的可跳转节点使用 `RouterLink`，并且点击父实体应返回父实体详情页而不是列表页。
- 操作按钮和既有返回按钮保留；`DetailPageHeader` 不重复展示状态、类型或其他 label，文案支持中英文。
- 顶级详情页没有祖先路径时，头部退化为当前页标题，不渲染模块级 breadcrumb。
- 从一级列表进入的详情页均视为顶级详情页；实体的归属关系本身不得生成 breadcrumb。路由语义明确的嵌套详情页另行展示真实父级路径。
- 窄屏下长父实体名称可在导航区域截断或横向查看，当前页标题不得因路径过长而消失。
- 前端 lint 与类型检查通过。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

- 每个页面自行声明父实体 breadcrumb 数据，不再依赖集中式路由映射或全局注入状态。
- 页面优先使用已加载数据中的真实父实体名称；只有在父实体信息不在当前响应时才补充最小额外请求。
- 面包屑只表达父实体链路，不再展示顶级模块名；当前页标题紧随路径作为唯一 `h1`。
- 一级详情页的 breadcrumb 行为以应用详情页为基准：列表进入详情时不展示父级路径；服务详情不再因归属应用而显示应用 breadcrumb。
- 一级详情页标题使用列表中同一实体的主显示名称；服务详情使用 `application_name`，不再使用泛化的“服务详情”。
- `DetailPageHeader` 仅负责祖先导航和当前页唯一的 `h1`，不提供操作按钮 slot。
- 页面自行负责操作按钮和返回按钮的布局，避免共享导航组件承担页面操作区职责。

## Risk

- 个别层级的父实体名称仍依赖额外请求补齐；如果后续要继续收敛，应该优先扩展详情响应而不是把页面语义退回到列表或模块名。
