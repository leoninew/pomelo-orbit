# 持续部署对话记录持久化
最后修改时间: 2026-08-15 20:06:00

Review status: Accepted

流程模式: 标准 / standard

## Background

持续部署对话页当前只将消息保留在浏览器页面内。刷新页面、重新登录或从其他设备访问后，已有问答无法恢复，也不能回看一次部署对话的完整结果。

## Goal

为持续部署对话引入持久化会话记录：

1. 一条对话记录（Conversation）表示一次独立的持续部署对话。
2. 一条对话记录拥有多条按时间排序的消息（Message），保存用户提问与最终助手回答。
3. 用户能够在持续部署对话工作区的历史导航中打开已有记录并回看全部问答；这不是独立的业务记录管理列表。
4. 助手回答仅在大模型及工具调用完成、得到最终回答后写入记录。

## Non-goal

1. 不持久化或在历史回放中展示模型思考过程、工具调用进度、工具参数或工具原始结果；既有实时 SSE 事件保持不变。
2. 不实现消息编辑、消息重试、会话搜索或导出功能；保持现有 SSE 对话消息传输与工具事件不变。
3. 不改变 MCP 工具、部署领域模型、Deployment worker 或运行态流程。
4. 不在本需求中引入共享协作、评论或跨项目会话。

## User scenarios

1. 用户在某个项目的持续部署对话页创建一条新对话，发送多个部署相关问题；每轮完成后，这条记录包含连续的用户问题和最终助手回答。
2. 用户稍后重新打开持续部署对话页，在历史导航中选择此前的一条记录，看到自动生成的标题和完整历史，并可继续发送下一条问题。
3. 大模型正在调用工具或处理请求时，既有实时 SSE 事件按原有方式传输；中间推理与工具活动不写入记录，也不在历史回放中展示。只有最终回答完成后，才写入持久化记录。
4. 大模型或工具调用失败而未产生最终回答时，不写入一条伪造的助手回答；用户仍可看到此前已完成的问答。
5. 具备对话写权限的用户可以删除一条对话记录；删除后该记录及其全部消息不再出现在列表或详情中。

## Acceptance

1. 数据模型包含对话记录与对话消息两个独立持久化实体；消息通过对话记录 ID 归属，且保留角色、内容和创建时间。
2. 一条对话记录可以包含任意多轮用户问题与最终助手回答，并按稳定时间顺序读取。
3. 每次成功完成一轮对话后，用户问题和最终助手回答作为该轮持久化结果写入；中间过程不落库，既有 SSE 实时传输不变。
4. 持续部署对话页在同一对话工作区提供创建、历史导航、切换和加载；不得将对话实现为独立的业务列表页或表格。
5. 刷新页面或在另一台设备重新登录后，用户仍能打开其既有对话记录并阅读已完成的内容。
6. 现有 SSE 对话请求、消息传递、工具调用事件和页面流式状态保持不变；持久化仅插入在最终回答完成路径中。
7. 对话记录标题由首条用户问题自动生成；用户不能在本期手工编辑标题。
8. 对话记录仅对同时具备项目成员关系与 `dialogue:read` 权限的用户可见；创建、继续与删除需要 `dialogue:write` 权限。
9. 删除一条对话记录时，其全部消息一并删除。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

1. “对话记录”建模为一条 Conversation 与多条 Message，不再将全部项目消息混为一条历史流。
2. 只保存用户消息和完成后的最终助手回答；不保存或展示思考过程及工具执行细节。
3. 回答持久化在模型完整执行成功后进行；失败不会伪造助手消息。
4. 现有 SSE 对话请求、消息传递和工具调用事件保持不变；获得最终模型回答的路径在本轮问答持久化成功后才发送既有 `complete` 事件，不改变既有中断流语义。
5. 对话是项目级资源，RBAC 控制访问：读操作使用新权限 `dialogue:read`，创建、继续和删除使用 `dialogue:write`；两者均以当前用户仍是该项目成员为前提。
6. 对话标题取首条用户问题自动生成，本期不支持重命名。
7. 本期支持删除对话记录，删除记录级联删除其消息。
8. 历史在桌面端使用对话工作区内的可收起侧栏，在移动端使用抽屉；删除是会话的上下文菜单操作，而不是列表中的常驻操作列。

## Risk

1. 回答执行完成后再落库意味着最终写入失败时，该轮回答不能作为已完成历史可靠交付，必须显式向用户报告持久化失败。
2. 新权限需要作为数据迁移写入权限表，并分配给合适的既有角色；权限未配置时，对话访问会被拒绝。
3. 关闭中间过程展示会降低实时反馈；页面需保留简洁的请求进行中状态，避免用户重复提交。

## User review notes

1. 用户要求先按 SpecFlow 编写文档，未接受前不得开始代码实现。
2. 用户明确要求一条对话记录包含多轮提问与回答，供之后打开回看。
3. 用户明确要求仅在大模型完成最终回答后更新回答记录，不展示思考过程。
4. 用户确认使用既有 RBAC 控制对话访问，标题自动生成，并支持删除记录。
5. 用户明确反对将对话历史实现为普通业务列表；历史应是对话工作区内的导航。
