# 自定义路由同步优化与环境目标恢复
最后修改时间: 2026-10-03 13:04:00

Flow mode: light
Review status: Accepted

## Background

用户要求先摸清列表批量和详情单条同步的执行操作，再实现合理的优化；本次明确要求“light 记录问题后，开始实现”，因此记录意图后直接进入 Implementation。

2026-10-03 的单条 minio-api 同步中，预览耗时 28.951 秒，确认到收尾结束约 71.293 秒。三轮全量发布状态扫描合计 55.140 秒，占两次请求执行时间约 55%。所贴阶段均完成；额外 pending_recovery 表示处理上次中断，不代表本轮失败。

同日还发现环境目标切换后的恢复问题：Environment 从 SSH 切换为 local，或工作目录、SSH 地址、平台、凭据变化时，TargetRevision 递增。当前工作区可能仍有历史 revision 的 `.orbit/route-publication/<route-id>/state.json`。合法的 Project 范围预览使用 `scope=project`、空 `route_ids`，却因任一历史记录 revision 不同而返回 500，预览与确认被永久阻断。历史来源修订被错误用作当前读取的硬性条件。用户已明确要求允许只读检查历史记录，并由显式确认在当前目标重新发布；本次合并两项工作的意图和验证依据。

以下操作次数为优化前的基线：

| 操作 | 优化前单条同步 | 优化前批量 B 条 | 目的 |
|------|--------------|---------------|------|
| 浏览器预览 | 1 次 | 1 次 | 冻结范围、业务及发布修订 |
| 浏览器确认 | 1 次 | B 次 | 前端逐条反馈，单条失败后继续 |
| 鉴权、业务及依赖校验 | 每个请求 | 每个请求 | Project 成员、上游、端口、证书和 hash |
| Gateway 同步锁 | 2 次 | B+1 次 | 串行化同一 Gateway 的请求 |
| 全量发布状态扫描 | 3 次 | 2B+1 次 | 预览、确认准备及发布入口重复读取 |
| state.json 读取 | 3P 次 | (2B+1)P 次 | P 为已有记录数；还读取活动 YAML、证书及 pending 的 previous 文件 |
| 完整 Gateway 检查 | 2 次 | B+1 次 | Compose 容器、静态配置、实际挂载，共三个主要 Docker 查询 |
| 保存草稿 | 1 次短事务 | B 次短事务 | 复核业务修订，仅有修改时写入；无远端 I/O |
| 文件发布或撤销 | 1 轮 | B 轮 | 备份、pending、证书准备、活动文件替换/撤下 |
| 重载和加载匹配 | 1 轮 | B 轮 | Windows HUP；每次轮询查询 HTTP/TCP router/service 四个接口 |
| 收尾 | 1 轮 | B 轮 | confirmed 记录与证书版本清理 |
| pending 或失败恢复 | 条件执行 | 条件执行 | 根据持久化材料确认或恢复，再重载和匹配 |
| 列表刷新 | 全成功时 2 次 | 全成功时 B+1 次 | saved 每条刷新，synced 最后再刷新 |
| 详情刷新 | 全成功时 2 轮 | 单条入口 | 每轮 GET Route 和 Gateway，共四个 GET |

次数按全部进入文件发布/撤销、无重试计算；从未发布且禁用的项跳过文件操作，加载未收敛时重复轮询。优化前 SSH runtime 每次文件操作/查询重新建立连接。单次 1–2 秒日志包含连接、通道、远端进程和文件操作，不能全部归因于握手。

## Goal

1. 保留列表批量与详情单条使用同一同步流程，前端循环逐条确认并立即反馈。
2. 为一次预览或确认复用 SSH/SFTP 连接，退出时关闭；阶段取消后淘汰连接，恢复可在独立预算内重新连接。
3. 按业务范围逐条读取：先取得当前 Route 业务记录与 code，再只读取其发布记录及对应 YAML/PEM、必要 previous。单条预览和确认不列发布目录、不读取其他 Route 的发布记录；Project 范围沿用单条流程循环处理。
4. 按候选及撤下资源的协议读取 router/service，普通 HTTP 同步只查询 HTTP 两个接口。
5. 已确认文件与期望内容一致时复核加载结果并完成；pending 已恢复且结果等于期望时复用这次核验，不再次写文件、重载和匹配。
6. 逐条结果立即更新前端草稿；一次同步结束后合并刷新列表/详情，详情不重复查询未变化的 Gateway。
7. 保留阶段耗时与有意义的错误原因，日志使用 project_code、route_code，更新活文档中的操作说明。
8. 当前目标工作区中的历史 TargetRevision 不阻断读取和预览；用户显式确认后写入当前 revision。历史 revision 不走无变化捷径，预览与确认之间或请求执行期间的目标变化仍使预览过期。

## Non-goal

- 不改变前端逐条确认协议，不添加异步任务、批次服务端续跑或跨请求长效缓存。
- 不修改数据库 schema 或已执行迁移，不改 Gateway 部署流程、Docker 配置或远端服务。
- Environment 切换或 Probe 成功不自动改写发布记录、删除 Route 文件、迁移 state.json 或发布路由；不连接旧目标搬运文件。
- 保留当前 Route 的修订、Project/Gateway 归属、外部修改、证书完整性及恢复校验；编码目标文件已存在且不属于当前 Route 时拒绝覆盖。
- 不承诺固定网络下的绝对耗时，也不主动管理用户的开发服务器。

## User scenarios

- 详情预览并发布当前 HTTP/HTTPS/TCP Route，及时显示结果。
- 列表 Project 范围预览，包含发布、撤销及跳过项；确认依冻结顺序逐条执行。
- 失败项保留原因与草稿，重新预览后重试；成功项不重复执行。
- 改名、协议变化、文件缺失、外部修改、证书变化及中断 pending 均维持已有安全语义。
- Environment 目标切换后，用户重新预览当前工作区的历史发布记录，显式选择需要发布或撤销的 Route；新目标仍需具备合法 Gateway 部署和受管挂载。

## Acceptance

1. 单条预览与确认只读当前 Route 的业务记录、发布状态与对应文件，发布入口只复核当前项，不列发布目录。
2. selected 范围不读取无关 Route 的 state.json、YAML 或 PEM；损坏的无关发布记录不能阻断当前 Route。Project 范围枚举业务记录和已发布 ID 后逐条处理，保留已删除 Route 的撤销能力。
3. 请求内多次远端文件和命令操作复用连接；正常结束、取消及失败恢复后没有遗留连接；恢复不复用取消导致失效的连接。
4. 普通 HTTP 路由一轮加载匹配只请求 HTTP router/service；改名、协议变化和撤销仍核对必要旧资源缺席。
5. 无变化且运行配置已匹配的同步成功报告 file_commit=unchanged；外部修改仍报告冲突。pending 被确认或恢复后仅在期望内容不同的情况下执行新提交。
6. 批量反馈仍逐条呈现；每轮结束只刷新列表或详情一次，失败结果同样触发最终刷新。
7. 仓库要求的 Go/frontend 检查通过，补充连接生命周期、扫描范围、无变化/pending、协议与前端请求次数的有效回归测试。
8. 当前 Route 的读取、发布、恢复及加载日志带 project_code、route_code；业务已删除且无法取得 code 时，读取日志保留记录路径，成功解码后补充已发布 code。
9. 当前工作区存在历史 target revision 的记录时，Project 与 selected 读取/预览不因该值失败；读取与预览不改写记录或文件。
10. 用户显式确认后，新发布记录使用当前 revision；历史 revision 即使内容相同也执行当前目标的文件发布与加载核验。
11. 请求执行期间目标 revision 变化仍报告 `route_sync_preview_expired`；预览与确认之间的变化仍由依赖 hash 检查。Project/Gateway/Route 归属、当前文件外部修改、当前 Route 的证书对、版本及恢复材料仍受校验。

## Open questions

暂无需要用户确认的未决事项。用户已要求完成验证且不进行集成测试；真实 Windows SSH/SFTP、目标切换、Docker 和实际浏览器验收不作为本次完成条件。本轮不代替用户管理或重启服务。

## Decisions

- 用户后续明确收敛为“发布什么 Route，就读取什么业务记录和对应 Traefik 文件”；取消全局发布元数据缓存与跨 Route 状态/证书冲突扫描，不引入持久化索引或兼容层。
- 编码目标冲突直接检查对应 YAML，成功撤销或改名后释放的编码不再由历史 confirmed 记录追踪；其他 Route 可复用已释放编码。
- 发布前仍针对当前 Route 复核记录和文件，避免直接信任预览或较早的文件观测。
- SSH 会话复用限制于显式请求作用域，不在其他请求或不同目标之间共享。
- 已有阶段超时与 Docker 查询错误提示修复作为当前代码基础保留。
- Publication.TargetRevision 表示记录写入时的目标来源，读取时不要求它与当前 Environment revision 一致；显式发布使用当前 revision，无变化判断仍要求 revision 一致。
- 目标恢复仅操作当前工作区；Environment 切换和 Probe 不自动执行恢复，旧目标文件由用户另行管理。
- 用户根据优化后日志明确指定状态准备 10s、文件发布 5s、单次 API 10s、重载 5s、配置匹配 5s、恢复 20s；Gateway 锁等待继续为 30s。单次 API 在匹配阶段内由父 context 的剩余预算限制，取消 API 上限不得超过匹配上限的配置校验。
- 用户已授权进入 Implementation，随后要求验证两项工作，并合并 Intent 与 Verification；验证报告保持 Draft，待人工审阅。

## Risk

- 连接复用必须绑定 target/credential 修订，并处理阶段取消与异步连接关闭的竞态。
- pending、撤销及改名涉及候选和 previous 路径；缩小范围不能漏掉旧文件或证书检查。
- 无变化优化仍需确认实际加载状态；API 不可用时不能直接报告成功。
- 前端减少刷新时必须即时清理已保存草稿，避免把业务保存成功但外部发布失败误当作未保存。
- 用户已授权暂存相关变更并中文提交，本轮合并过程文档后更新对应暂存内容，不还原用户修改。
- 状态准备 10s 覆盖整个 Project 范围；当前 9 条记录的预览为 7.274s，更多路由共同使用该预算。证书写入、协议切换和失败恢复仍需实际日志校准，超时继续保留恢复材料。
- Probe 成功不能证明 Gateway 已部署或就绪；SSH 与 local 也不一定指向同一物理目录。本修复不迁移旧目标状态，目标一致性校验不构成数据库、文件和 Traefik 之间的原子事务。
