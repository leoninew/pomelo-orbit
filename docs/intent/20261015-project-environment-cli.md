# Intent / 意图：通过项目别名连接环境并执行命令
最后修改时间: 2026-10-15 21:18:08

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

用户希望利用 Orbit 已存储的环境凭据，让操作者和大模型连接项目对应的远程环境，执行命令以诊断、分析问题。交互方式接近使用 SSH alias：指定项目就能定位目标和登录身份，无需重新提供主机、用户或私钥。

当前仓库已有以下基础：

- 每个 Project 对应一个 Environment；SSH Environment 保存目标地址、端口、平台、用户名、凭据绑定和主机指纹。部署密钥由 Orbit 加密保管，独立于全局仓库凭据。
- Web 环境终端已使用受管密钥提供交互式 shell，并将终端连接与 Docker Probe 解耦，保留成员授权、目标与凭据修订校验及会话限制。
- SSH runner 已支持 Linux/Windows 的非交互命令执行；现有 MCP 主要提供受管 Service 的 Docker/Compose 诊断，未开放通用 shell。
- 现有 Python CLI 的 `remote ssh/exec/scp/tunnel` 使用 `scripts/.env` 中的 `SSH_HOST`、`SSH_USER` 和系统 SSH，不读取 Orbit 库存或受管密钥，不能直接满足本次目标。
- 现有命名 PAT 用于 stdio MCP，每次工具调用校验有效性和用户状态；普通 HTTP API 当前使用 Web JWT，尚不能直接接受 PAT。

本次目标：

1. 在项目已有脚本/CLI 体系内提供按项目定位 Environment 的连接入口，主要认证凭据从环境变量读取，复用已有 PAT。
2. 提供交互式模式：操作者可选择项目，也可直接指定项目，随后进入该项目已配置的 SSH 环境终端。
3. 提供非交互式模式：调用者明确指定项目和命令，直接执行并获得结果，适合大模型通过命令行使用。
4. 使用唯一 Project code 作为类似 SSH alias 的稳定目标标识；模型可先查询有权访问的项目，再按用户指定的项目执行。
5. 由 Orbit 服务端使用已保存的环境目标、SSH 用户、受管密钥和主机指纹完成连接。客户端只持有 Orbit 地址和 PAT，不要求访问数据库、解密配置或取得 SSH 私钥。
6. 支持按问题执行临时调查命令；不将能力限制成固定诊断命令集合，也不要求每次调查先增加 MCP 工具。

## Non-goals / 非目标

- 不增加 SCP、SFTP 上传下载、文件同步或端口转发；本次只交付连接终端与命令执行。
- 不要求生成或修改操作者的 OpenSSH config，也不要求真的通过 `ssh <alias>` 协议入口访问；SSH alias 是目标选择和使用体验的类比。
- 不增加 SSH 密码、个人私钥、临时主机或临时用户输入，不通过脚本导出受管私钥。
- 不新增固定诊断命令库、完整运维平台或远程 MCP 服务；不以接入 MCP 作为脚本供大模型调用的前提。
- 不新增环境初始化、密钥生成或轮换流程，不自动部署、修复环境或初始化 Gateway。
- 本次以既有 SSH Environment 为交付范围；不增加 local 执行能力，不把 SSH 失败回退为本机执行。
- 不将环境工作区描述为 shell 沙盒，不承诺通用命令具有只读属性，也不增加每个 Orbit 用户独立的操作系统账号。
- 不为本次功能重写已有 Web 终端或独立的 `remote scp/tunnel` 工具，不引入新旧认证兼容层。

## Scenarios / 场景

1. 操作者配置 Orbit 地址与 PAT，运行项目查询命令，看到自己有权访问的项目、唯一 code 和目标类型，不需要查看或复制 SSH 凭据。
2. 操作者运行交互式连接入口，从项目列表选择一个 SSH Environment，进入已配置用户的 shell；已给出项目 code 时直接连接。
3. 大模型收到“分析 production 项目的问题”，先查询项目确认 code，再以非交互方式执行命令，通过 stdout、stderr 和退出码继续分析。
4. 目标 Docker 不可用、Probe 失败、Gateway 未初始化或没有已部署 Service 时，只要 SSH 连接条件与授权有效，仍可进入 shell 或执行宿主机命令。
5. PAT 缺失、过期或撤销、用户禁用、非项目成员、项目不存在、Environment 未配置或目标不是 SSH 时，调用明确失败，不弹出密码或项目选择提示，不执行其他目标。
6. 主机指纹不匹配、网络连接失败、命令超时或远端命令返回非零时，调用者能够区分连接/平台失败与远端命令结果；不自动重试可能产生副作用的命令。

## Acceptance criteria / 验收标准

- A01：提供可复用的项目脚本/CLI 入口，从环境变量读取已有 PAT，并通过明确配置定位 Orbit；无需 Web 登录交互、数据库或 SSH 私钥文件。PAT 不通过命令参数传递，不进入常规日志。
- A02：提供有权访问的项目查询，返回足够定位目标的 id、name、唯一 code 和环境类型等摘要；不返回环境私钥、仓库凭据或其他认证秘密。
- A03：交互式模式支持选择项目及直接指定项目，复用既有 SSH 用户与环境凭据，支持终端输入输出、尺寸变化、控制键、退出和主动断开；覆盖现有 Linux/Windows SSH 目标。
- A04：非交互式模式要求明确项目和命令，不启动项目选择、密码输入或其他交互提示；分别提供远端 stdout、stderr，并传递远端命令退出状态。连接或平台错误以明确失败状态反馈，不伪装为命令成功。
- A05：任意时刻均按项目已保存的 SSH 目标及凭据执行，不能通过客户端覆盖 host、port、username 或私钥；执行前校验 PAT、用户状态、成员资格和目标身份，沿用既有凭据修订、主机指纹及会话失效规则。
- A06：项目发现、选择、终端连接与非交互执行均不以 Docker/Compose、成功 Probe、Gateway 或已部署 Service 为前提；不自动触发这些能力，不弱化 CI/CD 的既有就绪条件。
- A07：非交互调用无上次选择的隐式项目依赖；项目不存在、目标类型不符或连接失败时不得改选其他项目、改为 local 或自动重放命令。
- A08：连接和执行具备明确的超时、取消、输出与资源边界；超时、输出截断或会话终止能够被调用者识别。记录操作者、项目、目标身份与结果元信息，避免认证秘密和完整终端内容进入常规日志。
- A09：提供大模型可直接遵循的调用说明和示例，包含查询项目、指定项目、执行命令、处理退出码及 shell 参数的规则；示例不依赖 SCP，也不要求大模型持有 SSH 密钥或启动 MCP。
- A10：按当前接口与用例补充必要的 CLI、认证、项目归属、协议及执行结果验证，同步相关操作文档；实施涉及 Go 时运行仓库要求的 `task check` 与 `go test ./cmd/... ./internal/...`，涉及 Python 时运行 scripts 现有检查和测试入口。

## Workload and decomposition / 工作量与拆分

预计中等工作量、中等复杂度。主要交付是可供人和大模型共用的 CLI 入口，以及让该入口复用 PAT、项目授权和受管 SSH 能力的服务端支持。影响边界包括 CLI 配置与命令、认证入站、Environment 用例和 SSH 执行适配器；不需要改动业务前端或环境数据模型，标准协议生成可能新增 TypeScript DTO。

主要技术未知项是 PAT 可调用的服务端接口与传输方式、交互终端的跨平台客户端接入、非交互命令和 shell 参数语义、结果与取消边界。应在 Plan 阶段核实并确定，不由实现阶段临时选择。

当前不建立 task，任务协调不适用。认证、连接与 CLI 协议关联紧密，单一计划按依赖顺序实施和审查能够降低接口协调成本。计划阶段如发现独立且可验收的交付边界，再决定是否拆分；此处不登记执行分配。

检查重点是合法项目能正确连接并返回真实执行结果，以及无权限、目标变更、主机指纹不匹配、取消和输出过大等实际边界。需要对 Linux/Windows 的真实 SSH 行为安排最小有效联调，不能只以参数替身测试证明终端可用。

## Questions and decisions / 问题与决策

- 用户明确要求脚本读取环境变量，主要使用 PAT，并同时提供交互式和非交互式模式，能够自行指定项目、连接并执行命令。
- 用户进一步明确不需要 SCP，向大模型提供类似 SSH alias 的使用方式即可。据此聚焦项目别名、终端与通用命令执行，不扩展文件传输或固定诊断工具体系。
- Project code 作为别名、复用现有 CLI、客户端经 Orbit 使用服务端受管凭据，是本轮讨论形成的方案；用户要求开始计划，据此接受本意图。具体命令名并未由用户指定。
- CLI 命令层级、服务地址配置名、PAT 环境变量加载优先级、认证接口范围、HTTP/WebSocket 传输、工作目录、stdin 与 shell 引号规则、超时与输出限额已在[计划](../plan/20261015-project-environment-cli.md)中确定。现有 PAT 不能直接当作普通 HTTP Bearer JWT 使用，计划通过专用 CLI 路由复用其认证服务。
- 不因本次需求默认放开所有 HTTP API 的 PAT 认证，也不要求改变现有 stdio MCP 的项目选择规则；本次 CLI 的诊断入口应能独立进入未就绪环境。
- 暂无需要用户决策的意图疑问。意图已 Accepted；后续用户“开始实现”接受计划并授权 Implementation，进展与开发证据以计划实施记录为准。

## Risks / assumptions / 风险 / 假设

- 通用 shell 具有环境所保存 SSH 用户的实际权限，可能读写业务数据或控制 Docker；Project 是授权边界，工作区不是操作系统隔离边界。本次不宣称所有命令只读。
- PAT 当前用途为 stdio MCP，新增脚本接入必须明确验证和使用范围，保留撤销、过期、禁用及项目成员限制；不让脚本自行接触数据库和解密配置。
- 现有 Web 终端可复用其连接和生命周期规则，但不能推断浏览器客户端代码可直接用于跨平台 CLI；终端输入模式、信号、尺寸同步与恢复需要具体设计和验证。
- 现有非交互 Query 返回字符串与 error，输出使用内存缓冲；直接对模型开放前须设计退出码、stderr、输出限制及取消语义。连接取消不等同于已确认远端所有派生进程结束。
- 命令结果可能主动读取环境变量、配置或业务日志中的秘密；受管私钥不外泄不代表所有输出均可公开。调用说明应要求按诊断需要取数，普通日志不复制完整流，不承诺任意输出都能自动脱敏。
- 本次为仓库静态评估与意图记录，尚未连接真实目标或验证 CLI 传输方案；实机条件与未验证项应在后续计划、开发和验收中如实记录。
