# Intent / 意图：服务目录不以历史环境修订号阻断操作
最后修改时间: 2026-10-16 15:17:18

## Review status / 审查状态

Accepted

## Background / 背景

2026-10-16，跨 Orbit 数据库复制服务后，LOCAL 停止 `desktop-5c03b03/minio-default` 返回 409：`Service runtime directory belongs to a previous Environment revision. Deploy again.` 来源环境使用 local、修订号为 1，LOCAL 使用 SSH 访问同一主机、修订号为 3，复制的运行目录仍记录修订号 1。实际 SSH 核对主机、Compose project 和运行目录均匹配，容器仍运行。修订号属于各控制面的配置历史，不能作为物理目录不同的证据。

同类条件还用于无运行目录时的确认目录选择、部署目录占用检查、Gateway 路由发布和 Web 部署目录回填。

## Goals / 目标

- 操作当前选定 Environment 上保存的服务目录，不因目录记录的历史修订号不同而强制重新部署。
- 保持运行目录优先、确认目录次之；目录占用统一使用当前目标解析后的路径和实际运行挂载。
- 保留权限、Project/Service 归属、路径范围、最新 Probe、任务/会话期间目标变更检查。

## Non-goals / 非目标

- 不修改两端业务数据库、服务状态、历史修订号或已执行迁移，不实际启停、部署或同步路由。
- 不增加跨主机目录身份库、自动迁移/发现旧目标、目录确认 UI 或兼容分支。
- 不将删除旧修订准入限制扩展为移除任务、会话和预览的并发变更检查。

## User stories / scenarios / 用户故事 / 场景

- 同一宿主机由 local 切换为 SSH，或复制配置到另一控制面后，保存的目录仍可用于启停和运行时查询。
- Gateway 的目录仍可访问时，自定义路由可正常预览和显式同步。
- 其他 Service 的目录记录来自旧修订时，实际重叠目录和运行挂载仍受到保护。

## Acceptance criteria / 验收标准

- A01：停止和重启不比较历史目录修订号；优先冻结运行目录，无运行目录时使用已确认目录；新任务冻结当前目标修订。
- A02：运行状态/Compose 工具及 Gateway 路由发布不因历史运行目录修订号拒绝；缺失运行目录、文件范围、Project/Gateway 归属等有效失败边界保留。
- A03：确认/运行目录占用不按历史修订号跳过，继续比较当前目标解析的逻辑目录、daemon 挂载路径和实际运行 bind mount；共享挂载不释放 Service 根目录。
- A04：任务排队后目标变化、发布会话期间目标或目录变化仍拒绝执行或使预览过期。
- A05：Web 部署弹窗保留已保存的确认目录；没有确认目录才生成默认值；提交携带当前环境修订，路径校验保持有效。
- A06：补充上述主要流程和实际失败边界的回归证据，完成项目固定开发检查，同步活文档。

## Workload assessment / 工作量评估

工作量为一项跨入口共享规则修正，主要交付是统一目录来源语义；修改 application 目录选择/占用规则、Traefik 工作区入口与 Web 目录回填，并调整既有轻量测试和活文档。复杂度中等：需区分历史来源修订和本次操作冻结修订。风险集中于误删执行期变更检查和漏掉旧修订目录占用。路径规范化、符号链接解析、DooD 映射与挂载观察已有实现，可复用。

结论：保持单任务。各入口共享同一规则，独立拆分会增加契约协调；由主会话顺序修改并运行回归，不派发子 agent。
