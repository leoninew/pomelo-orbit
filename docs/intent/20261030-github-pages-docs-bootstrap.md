## Background / 背景

项目已有 README、业务模型入口和大量研发过程记录，但缺少面向开源读者的独立文档入口。此前评估确定使用 GitHub Pages 提供文档；首期先验证从编写、构建、检查到发布和访问的完整流程，不一次建设完整手册。

GitHub 仓库 `leoninew/pomelo-orbit` 的默认分支为 `develop`，预计项目站点地址为 `https://leoninew.github.io/pomelo-orbit/`。变更进入 GitHub 才会触发 GitHub Actions，推送 Gitee 不能替代。用户已在其他会话创建第一批提交 `80733f81`；本会话按授权将 Pages Source 设为 GitHub Actions，刷新后确认保存。实际构建、部署及线上访问仍待验收。

[旧文档中心意图](20260728-documentation-handbook.md)曾提出产品内 `/doc` 和不引入独立站点。本首期以 GitHub Pages 为交付方向，不以该草案的展示方式、全量章节或首版双语作为验收依据；旧草案保留供追溯。

第一批提供站点和开发入门。第二批先明确面向开源读者的帮助文档结构、阅读路线和后续内容边界，再实现其中一部分，而不是将整批工作等同于一篇安装指南。第二批可以先于第一批线上验收推进，但不能据此宣布站点已经发布。

## User stories / scenarios / 用户场景

- 开源读者从仓库 README 打开公开文档，了解项目定位，进入开发入门文章并找到进一步的项目资料。
- 贡献者修改 Markdown 后，能按仓库说明安装依赖、构建文档，并在提交前发现基本构建或链接问题。
- 维护者将变更合入 GitHub 的发布分支后，文档自动发布；直接访问或刷新子页面时，页面和资源仍正常加载。
- 新读者先了解产品适用范围、界面分区和基本工作流，再理解 Project、Environment、Pipeline、Application、Service 等对象的关系，不被直接导向开发环境搭建。
- 文档维护者能从一份结构表确定新内容放在哪里、解决什么读者问题、依赖哪些前置文章，并区分当前可读内容和后续计划。
- 已登录用户能找到项目环境配置和应用服务管理入口，知道每一步保存或执行后应检查什么，并能区分版本发布、服务配置和运行容器更新。
- 已有实例的使用者能配置合适的源码与认证方式，复用模板建立项目流水线，查看本次运行及制品，并判断是否形成新应用版本、是否还需部署服务。
- 已有实例的使用者能区分网关就绪、DNS 解析和路由发布，知道保存、同步及外部访问各自证明什么，并在变更共享 DNS 或停止网关前评估影响。
- 已登录用户能区分系统权限和项目访问，知道创建用户后还需配置什么，以及个人令牌如何查看、轮换和撤销；维护者能判断权限拒绝与身份失效，避免误把退出登录或改密码当作令牌吊销。
- 自动化使用者能为本地进程选择正确的配置目录、数据库和身份，在 MCP 中明确选择项目，在 CLI 中使用精确编码；遇到工具错误、输出截断、连接丢失或部署等待超时时，不盲目重试有副作用的操作。
- 使用者能判断某个值来自仓库、流水线全局 / 阶段、版本声明还是 Service 覆盖，识别“未填、空串、删除、继承”的区别；遇到缺变量或预览差异时修改正确层次，不将启动 dotenv 或原生 Compose 语义套入所有字段。
- 已有实例的使用者能判断是否适合开启部署对话，准备正确身份、模型和项目，在新建 / 继续会话时识别共享内容及执行风险，并在工具失败、等待超时、对话未保存或历史删除后从真实资源核对结果，而不是直接重发操作。
- 实例维护者能判断设置来自哪个配置层次，了解“默认值”与重置的含义，成组保存关联项并处理冲突；在变更主密钥或迁移运行目录前识别凭据解密、配置持久化及多进程一致性的影响。

## Acceptance criteria / 验收标准

### 第一批：最小站点与发布闭环

- A01：文档内容与研发过程记录隔离；构建产物不包含过程或归档 Markdown 对应的页面。公开仓库本身仍可访问这些文件，不将站点隔离描述为保密措施。
- A02：站点至少有中文首页和一篇非占位的开发入门文章；内容基于当前代码、配置和任务命令核对，说明前置条件、操作、验证方式和已知限制。README 提供文档入口，并修正本期涉及的失效开发命令。
- A03：使用仓库固定的文档依赖可在本地完成构建；构建及适用的链接检查失败时返回失败状态。操作说明包含命令运行目录和必要前置条件。
- A04：GitHub PR 具备文档构建检查且不部署；GitHub 发布分支的文档变更可通过 Actions 构建并部署到 Pages。部署权限仅授予需要发布的 job。
- A05：Pages 配置和站点资源适配 `/pomelo-orbit/`；实际发布后，首页及至少一个文章深链接可直接访问和刷新，导航、样式及资源正常，记录可核验的网址与结果。
- A06：文档正文明确其适用版本或开发状态；未核验的公开镜像、Release 下载和安装步骤不作为已验证事实发布。

### 第二批：整体结构与首选内容

- A07：原计划中提供帮助文档完整结构，按读者任务划分六个区域，列明候选文章的路径、读者问题、优先级和前置依赖；明确已有、本批实现及后续内容，结构规划不等于全量实现。
- A08：提供非占位的中文“项目概览”，说明产品定位、适用边界、主要工作区、CI 与 CD 的基本联系及建议阅读路线；依据当前实现，不将能力介绍写成已验证的部署教程。
- A09：提供非占位的中文“核心概念”，解释项目与环境、两类凭据、流水线模板与运行、应用版本与组件、服务与部署记录、网关与路由的关系及主要区别；使用帮助读者理解的示例，不罗列内部字段或复制研发记录。
