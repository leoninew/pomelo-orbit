# Intent / 意图：服务受控文件内容与写入策略覆盖
最后修改时间: 2026-11-02 21:39:17

## Review status / 审查状态

Accepted

用户确认受控文件仅配置覆盖/保留，不设置只读；目录和普通文件保留只读配置。实现及整体 Verification 已完成，具体证据见验证报告。

## Background / 背景

版本组件已经支持 `controlled_file`，保存完整文件内容、权限、是否只读和 `ignore_if_exists`。部署将有效挂载转换为 `WorkspaceFile`，通过 local 或 SSH writer 在目标环境写入文件，再由 Compose bind mount 挂入容器。

服务目前只能按挂载 `target` 覆盖 `source`、`source_is_host_path` 或删除挂载。服务声明响应未提供 `content`、`mode`、`ignore_if_exists`，覆盖模型和持久化也缺少这些字段，导致用户无法在服务中配置自己的文件内容及部署写入策略。

部分文件由应用运行期间自行维护。若每次部署均以版本内容替换，可能丢失运行数据。平台应提供通用表达能力，由用户决定内容、权限、容器访问方式及覆盖策略，不根据业务名称或文件用途代替用户选择。

仓库依据：

- `internal/model/application.go`：版本挂载声明。
- `proto/orbit/v1/service/service.proto`：服务声明响应与挂载覆盖协议。
- `sql/query/service/service.sql`：服务挂载覆盖持久化字段。
- `internal/application/service/usecase/service.go`：覆盖校验及当前与版本相等时的归一化处理。
- `internal/application/deployment/usecase/effective_service_plan.go`：按 target 合并服务覆盖。
- `internal/application/deployment/usecase/mount_env.go`、`deployment_execution.go`：文件解析及物化链路。
- `internal/infrastructure/runner/local/runtime.go`、`internal/infrastructure/runner/ssh/runtime.go`：存在则跳过、临时文件替换和权限处理。
- `web/src/views/service/ServiceComponentDetail.vue`：当前只有挂载来源编辑入口。

## Goals / 目标

1. 服务可以查看版本受控文件声明，并独立继承或覆盖 `content`、`mode`、`ignore_if_exists`，保留既有来源路径覆盖能力。受控文件不设置 `read_only`；目录和普通文件保留只读配置。
2. 明确区分“覆盖版本声明”和“覆盖目标服务器文件”：前者决定部署采用的配置，后者决定遇到已有文件时的写入行为。
3. 挂载弹窗直接编辑当前值，不增加继承或自定义开关；未操作字段保留原设置，显式编辑值即使与版本相同也保存。挂载列表保留整条重置操作。
4. 产品只提供“覆盖已有文件 / 保留已有文件”两项部署写入策略。覆盖时按已保存内容和权限创建或替换文件；保留时只初始化不存在的文件，已有内容和权限不变。修改平台内容、重复部署、版本切换和强制重建均不得越过保留策略。
5. HTTP、MCP、持久化、服务编辑与部署计划使用一致的字段存在性和合并语义，不仅增加前端按钮。
6. 提供通用能力及真实错误反馈；用户负责配置的业务适用性，不增加应用名称、文件名或内容识别驱动的策略。
7. 本任务内分析清楚 Traefik/Gateway 的配置和策略调整：记录当前覆盖点、与服务配置的冲突、目标职责、调整顺序和验收条件，不只登记为以后调查。

## Non-goals / 非目标

- 本轮通用能力实现不同时改造 Traefik/Gateway 业务流程，但本任务的 Plan 必须分析并给出其初始声明、静态配置 enrichment、ACME、Route 发布和重建策略的调整结论。先完成通用能力，再依据本次分析安排业务调整，不把分析延后。
- 本轮取消 Gateway 强制覆盖文件的例外，使其服从同一写入策略；其内容补丁、目录覆盖、选版和配置来源仍按总计划单独治理，不宣称 Gateway 整体改造完成。
- 不读取服务器文件填充编辑器，不实现远程在线文件编辑、运行内容回写版本或服务、内容合并或变量模板替换。
- 不根据文件变化自动推断业务重载方式；沿用通用部署重建选项，强制重建不改变通用文件写入策略。
- 不扩大为任意宿主机文件管理，不改变既有路径作用域、部署目录及符号链接检查。
- 意图与计划阶段仅记录设计；当前 Implementation 可修改产品代码、新增迁移并运行开发检查，不执行生产迁移、实际部署或开发服务器操作。

## User stories / scenarios / 用户故事 / 场景

1. 同一版本用于多个服务，各服务可填写自己的配置文件内容，相互独立且不修改版本。
2. 服务继续继承版本内容，仅覆盖“保留已有文件”策略；首次部署初始化，应用随后修改文件，后续部署保留应用写入结果。
3. 服务明确选择“覆盖已有文件”，部署按有效内容完整替换文件；用户自行负责已有业务数据被替换的后果。
4. 用户显式设置空内容、`false` 或与版本相同的值，保存及回读后仍是明确覆盖；版本后续变化不影响这些显式覆盖。
5. 用户在挂载列表重置一条挂载，恢复该挂载的版本设置，其他挂载和服务配置仍保留。
6. 用户选择保留已有文件时，编辑器说明声明内容只用于文件不存在时初始化，不将声明内容描述为服务器当前内容。

## Acceptance criteria / 验收标准

- A01：服务声明响应提供受控文件的版本内容、权限及写入策略；服务覆盖的读写链路完整支持内容、权限及写入策略；目录和普通文件可设置只读，受控文件不支持只读。
- A02：字段能够独立继承或覆盖，未设置与显式空内容、显式 `false` 可区分；显式与版本相同的覆盖不会被自动清除。
- A03：有效部署计划按字段合并，修改仅作用于当前服务；恢复继承后采用对应版本值，不影响无关挂载和覆盖。
- A04：覆盖模式在文件不存在时创建，存在时以有效内容替换并应用有效权限；保留模式在不存在时初始化，存在时不修改内容及权限。
- A05：版本和服务的受控文件入口统一提供“覆盖已有文件 / 保留已有文件”两项；服务字段直接编辑，不展示继承、自定义开关或来源状态。保留模式明确已有文件不会因编辑内容或权限而改变，保存不宣称服务器已更新。
- A06：策略在重复部署和强制重建下保持一致；通用文件写入不因应用类型、文件名或业务用途静默改写用户选择。
- A07：HTTP 与 MCP 的写入、回读和部署合并语义一致；沿用文件内容大小、权限格式及路径等结构校验，不增加业务适用性限制。
- A08：用通用组件验证文件写入及容器生效边界；强制重建时采用已写入的新文件，保留模式不因重建覆盖已有内容。既有 Gateway 特殊处理与通用能力分别说明，不宣称通用实现已消除业务覆盖。
- A09：相关轻量前端单测、后端主要流程与真实失败边界检查通过；本次不新增前端端到端或整页串联测试。
- A10：总计划给出 Gateway 逐项分析和明确调整结论，覆盖静态内容及写入策略、目录挂载、ACME 状态文件、邮件和 DNS 凭据、版本选择、重建及 Route 发布校验；说明仅修改单一覆盖开关为何不完整，并列明后续业务改造的执行顺序和验收。

## Workload assessment / 工作量评估

- 工作量：中等偏大，涉及协议、模型、数据库增量迁移与查询、HTTP/MCP 映射、应用校验、有效计划合并及前端编辑。底层 writer 已具备主要写入能力，应优先复用。
- 复杂度：中等。重点是每字段的存在性、显式覆盖与继承、恢复继承，以及现有挂载归一化不能丢弃新增覆盖。
- 风险：错误地将空内容或 `false` 当作未设置会改变部署结果；文件原子替换与单文件 bind mount 的生效边界须说明和验证；Gateway 当前特殊处理不应被误宣称已调整。
- 关键技术核对：Plan 阶段确定可空字段的协议和数据库表达、生成代码入口、版本切换后的覆盖校验，以及 local/SSH 对权限的实际平台差异。现有 writer 对 mode `0000` 有默认转换，需在计划中明确与既有权限契约如何一致，不能承诺未经核对的执行效果。
- 检查范围：后端覆盖读写、合并和 writer 行为；前端表单转换、继承恢复和校验；复用项目 Go、lint、typecheck 及必要单测入口。容器生效验证放在实际运行边界，不能替代为前端端到端测试。
- Review 上下文：本意图、上述代码事实、用户对通用能力的要求，以及最新“Traefik/Gateway 的配置和策略调整要在本任务中分析清楚”的范围修正。

结论：建议在 Plan 阶段建立后端契约与前端交互两个 task。二者具有可检查的独立交付，前端依赖后端确定的协议；生成契约由后端节点统一维护，避免共享修改冲突。整体部署验收由父级验证记录汇总。

## Decisions / 决策

1. 版本为基线，服务保存明确覆盖，配置选择与实际文件写入分开表达。
2. 内容、权限和写入策略由受控文件配置；目录和普通文件提供只读配置。不按业务名称推断策略，保留必要结构及执行校验。
3. 保留已有文件是持续生效的配置，不是一次性部署操作；编辑器展示声明内容，不承诺与运行文件一致。
4. Gateway 调整分析纳入本任务计划，形成具体结论；产品实施保持先通用能力、后业务调整的顺序。

## Risks / assumptions / 风险 / 假设

- 用户错误选择覆盖可能丢失应用维护的数据；界面准确表达行为，平台不擅自替用户改选保留。
- 本次不承诺普通 `compose up` 自动让单文件 bind mount 读取新 inode；用户使用既有重建选项，必要的说明和验证纳入验收。
- 平台权限实现存在差异，尤其 Windows 不具有完整 Unix mode 语义；按现有运行目标能力如实表达，不新增虚假的权限保证。
- Gateway 静态内容仍会被补丁修改，选版和目录等策略尚未移除；本轮只取消其强制覆盖例外，保留旧文件可能使新的 Gateway 配置不生效，由用户选择策略并承担结果。
- 用户已明确本次代码未推送，允许直接修改本次迁移并就地调整开发库；不新增修补迁移，不添加新旧契约并存的兼容层。两项产品策略继续由既有 `ignore_if_exists` 表达，不额外新增策略字段或转换层。
