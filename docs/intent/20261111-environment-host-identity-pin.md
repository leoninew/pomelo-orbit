# Intent / 意图：环境主机身份以稳定指纹固定
最后修改时间: 2026-11-11 17:22:34

## Review status / 审查状态

Accepted

## Background / 背景

Project `01M6QZV2D8NNXGD3YMNJK4Y7FD`（`mosh.instabox.sh`）自 2026-11-11 起无法通过 Orbit 连接。已实测：

- `mosh.instabox.sh:2222` 与 `ssh.instabox.sh:2222` 均可登录，受管公钥仍在 `authorized_keys`，Docker 29.8.2 / Compose v5.6.0 正常。
- Orbit 保存 `host_key_fingerprint = SHA256:BaAEO9gPUsf7WZxqdCC/Fjnj9UGsNvg6CJYyajRPyPc`（2026-11-06 探测时写入）。
- 服务器当前协商 `ssh-ed25519-cert-v01@openssh.com`，主机证书 `serial 0`、ID `instabox-gateway`、有效期 `2026-11-11 03:55 UTC → 2026-12-11 04:55 UTC`；证书内公钥指纹为 `SHA256:DQYkbhc9iBYcfVvhXZBsT9qhzAyLvLIyjmm57Vimfxk`。该网关身份与登录后目标机的 `/etc/ssh/ssh_host_ed25519_key.pub` 不是同一把 key，后者的文件时间不能证明网关身份是否变化。
- 用 `x/crypto/ssh` 复现：证书对象 `FingerprintSHA256(cert)` 为 `SHA256:zC8O+z7RH6VdkaHm8o8r4kqNlXG3GlRY6cjLpdQDFj8`，`FingerprintSHA256(cert.Key)` 为 `DQYk…`。未保存旧证书，因此不能断言旧值 `BaAE…` 的具体来源或历史 CA/key 是否相同。

已确认当前回调直接对协商到的公钥对象计算指纹；对象是证书时，指纹包含证书整体内容。因此同一 key 的证书重签也可能触发不匹配。此次数据库值与当前指纹不符，但历史轮换细节没有完整证据。

因此本次把“固定什么身份”做成环境级选项：默认保持现有行为，允许单个环境显式选用稳定身份。

## Goals / 目标

1. 在 SSH 环境配置中增加主机身份选项，取值“当前行为（协商身份）”与“稳定身份”，**默认当前行为**；本机环境不展示或消费该选项。
2. **只新增策略列** `host_identity_policy`；指纹继续保存在现有 `host_key_fingerprint`，该值始终表示当前策略固定的身份，不另建指纹列。
3. 稳定身份模式下，对经 CA 签发的主机证书固定证书内公钥指纹，而非证书 blob，使同一 key 的例行重签不再造成连接失败。
4. 其余语义保持不变：SSH 认证方式、Probe 诊断定位、已有指纹不匹配时的拒绝规则、目标修订、在途部署与终端会话的复核规则。

## Non-goals / 非目标

- 不关闭主机密钥校验，不引入跳过校验的配置。
- 不给现有环境自动切换选项或改写现有指纹。
- 不新增 re-pin 产品能力、CA 信任配置、证书专项诊断或运维入口；本次固定的是公钥身份，不把稳定模式扩展成证书信任系统。
- 默认策略下保持现有指纹计算与写入语义；稳定策略只改变计算对象。
- 不改变 SSH 认证方式（仍为受管密钥）。
- 不修改已执行的迁移文件。

## User stories / scenarios / 用户故事 / 场景

1. 未切换选项的既有环境升级后行为完全不变，不需要重新探测或重新固定。
2. 选用稳定身份的环境，在目标主机由 CA 定期重签证书、底层 key 不变时，探测、终端、部署与 CI 继续正常工作。
3. 稳定身份环境下主机 key 真正更换时，连接仍然失败，与现有安全语义一致。
4. 操作者切换任一方向的选项时，按现有 SSH 身份变更规则清空指纹并递增 `target_revision`；后续探测或现有允许首次固定身份的连接重新记录。保存配置本身不发起 SSH 连接。
5. 编辑已启用稳定模式的环境时，未修改策略的表单提交或未提供该字段的更新保留现有策略与指纹；重复保存同一策略不重新建立信任。
6. 导出并恢复项目环境时，策略、指纹与修订作为完整快照一起恢复；不把导入恢复套用为普通策略切换，也不访问远端确认或改写快照。

## Acceptance criteria / 验收标准

- A01：环境新增策略列 `host_identity_policy`，取值 `negotiated` / `stable`，默认 `negotiated`；存量环境升级后的指纹与校验行为不变。
- A02：两种策略均只使用 `host_key_fingerprint` 保存当前固定值，不新增第二份指纹、身份类型或 CA 配置。
- A03：稳定身份模式下，对 host certificate 使用 `cert.Key` 指纹；同一 key 重签证书不会造成校验失败。默认模式仍严格比较协商对象的整体指纹；普通公钥在两种模式下计算相同。
- A04：稳定身份模式下，普通主机 key 与 CA 签发证书都能正确比对；底层 key 发生变化时校验失败。
- A05：`target.go` 的“未固定即拒绝部署”规则对两种选项都保留；Probe、终端、命令与转发按同一选项判断。
- A06：三库（SQLite/MySQL/PostgreSQL）只新增策略列，默认 `negotiated`，不改写存量指纹；新增迁移及降级注意事项明确。
- A07：模型、SQLC、DTO、proto、初始化表单、环境编辑、MCP、CLI 运行目标与项目交接同步传递策略；新建 SSH 环境未提供选项时默认当前行为，已有 SSH 环境更新未提供选项时保留原值，非法外部取值返回现有校验错误。交接完整快照包含策略，按新格式成对恢复策略和指纹，既有权限与凭据边界不变。
- A08：普通编辑切换策略时清空指纹、递增修订，不在保存时发起 SSH；相同策略重复保存不改动指纹或修订。单测与必要的协议、持久化测试覆盖默认行为、切换、首次记录、重签通过、key 变更拒绝与交接往返。
- A09：实施后通过 `task check`、`go test ./cmd/... ./internal/... ./sql`；前端在 `web/` 下运行 `corepack pnpm lint:fix`、`corepack pnpm typecheck` 和相关轻量单测。外部数据库检查沿用现有显式启用条件，跳过时如实记录，不能以 SQLite 结果代替其他方言的实测结论。

## Workload assessment / 工作量评估

- **主要交付**：一个环境级策略列、稳定指纹计算与现有链路的策略传递。
- **工作量**：中等。涉及 runner 回调分支、环境用例、模型与 SQLC、proto 与前端环境页，以及三库迁移。
- **复杂度**：中等。主要难点是默认路径保持原行为、Probe 与通用 SSH 建连使用同一算法，以及区分普通编辑与完整快照恢复的生命周期。
- **风险**：中等偏高。任一入口漏判选项会造成“界面显示稳定身份、实际仍按 blob 校验”的不一致；迁移默认值设错会改变既有环境行为。
- **关键约束**：策略切换纳入既有身份变更生命周期；指纹仍为 `SHA256:` 格式，记录和比对共用同一算法。
- **检查范围与审查上下文**：runner 的 Probe 与 Runtime 两条握手入口、环境编辑与快照恢复、SQL/迁移、HTTP/MCP 映射及共享表单需一起审查；遵循后端架构治理与前端测试 skill。

结论：保持单任务。策略字段与各入口的指纹计算必须一致落地。

## Decisions / 决策

- 保留主机密钥校验并维持 fail-closed。
- **环境级选项**：默认使用当前行为；新选项启用稳定身份；存量环境升级后不改变行为。
- **新列表示策略开关**：新增 `host_identity_policy`，复用 `host_key_fingerprint`。
- **普通编辑的生命周期**：切换策略清空当前指纹并递增修订；相同策略或未提供该选项不触发此变化。首次连接仍按现有流程记录，不保留两套历史固定值。
- **完整快照的生命周期**：项目交接恢复按包内策略、指纹和修订原样写入，沿用当前凭据恢复与权限边界；交接格式按现有版本机制升级，不自动转换旧包。
- **其他语义不变**：SSH 认证、Probe 诊断定位、指纹不匹配拒绝、目标修订与在途会话复核规则保持现状。

## Risks / assumptions / 风险 / 假设

- **风险**：两套指纹计算语义并存期间，任一入口漏传选项都会造成行为不一致；指纹算法集中在 SSH 适配器，应用层仅管理策略和生命周期。
- **风险**：迁移默认值或读写分支设错，会让既有环境在升级后行为变化。
- **假设**：`golang.org/x/crypto/ssh` 的 `ssh.Certificate.Key` 足以取得证书内公钥指纹，无需新依赖。
- **安全边界**：稳定模式固定 key，不固定 CA；同一 key 的证书与裸公钥视为同一身份，CA、证书有效期和主机名的变化不单独构成身份变化。首次记录仍为现有 TOFU，不是由 CA 验证的首次信任。当前回调没有 `ssh.CertChecker`，本次不新增证书信任语义。
