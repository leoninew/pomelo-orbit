Accepted

依据[意图](../intent/20261028-open-canvas-visual-language.md)及用户已授权的全系统实施范围，沿用现有前端组件与业务边界。实施规则以[前端界面规范](../frontend-design.md)为准。

## 技术方案与实施范围

1. 将主题变量和表格、控件规则统一到 `web/src/style.css`，工作区及导航布局放入 `web/src/styles/workspace.css`；App 取消两页试用条件，浅/深色及浮层使用同一套变量。
2. 列表使用开放数据区，详情保留语义分节；复用共享菜单、弹窗、抽屉、确认、分页和状态组件。保持原有页面入口、内容、权限与请求。
3. 表格统一使用 `.app-data-table`，普通行高 52px；文字操作区使用 `.app-table-actions`，统一链接和各类按钮的字号、行高与字重，保留语义颜色。
4. 服务组件字段明确区分 input / select / textarea；运行用户和附加组使用单行输入，命令保留多行编辑，现有校验与序列化保持。
5. 核对全部路由和真实记录详情，检查常见浮层、特殊视图、浅/深色与窄屏；修正实际溢出、截断及局部样式冲突。只打开和取消业务编辑，不提交创建、删除或部署。
6. 运行项目现有前端检查，整理意图、计划和验证结果，保留独立的现行界面规范。设计工具连接使用仓库的 Ardot Local MCP 配置。

主要文件范围为 App 与布局、共享 UI、全局和工作区样式、相关页面模板、字体配置及文档；后端、API 和数据模型不变。

## 实际实施偏差

页面核对发现初始化页重选同一项目时清空已知项目摘要，导致顶栏误显“暂无项目”。在 `web/src/stores/project.ts` 保留同一 ID 的摘要，不同未知项目仍清空；增加一个轻量 store 测试，无新增请求。这是纯样式计划之外的局部行为修正。

## 验证与风险

在 `web/` 运行 `corepack yarn lint:fix`、`corepack yarn typecheck`、现有轻量单测和生产构建；检查 diff 与文档链接。使用临时浏览器流程核对页面和浮层，不新增整页测试套件。

主要风险为共享样式覆盖及未能触发的业务状态；按实际证据区分已检查、源码核对和未执行。回退应撤回本次对应文件的变更，保留其他工作，不修改已执行迁移或服务状态。
