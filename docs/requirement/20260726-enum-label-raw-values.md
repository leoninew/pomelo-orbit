# 枚举标签保留原始值

最后修改时间: 2026-07-26 09:43:49

Review status: Accepted

## Background

前端曾通过 i18n 将接口返回的枚举值转换为自然语言标签。切换语言会改变枚举标签的显示，且同一枚举在不同页面存在重复映射。

## Goal

- 所有前端接口枚举在展示和选择器中直接显示原始枚举值。
- 移除只为枚举标签服务的 i18n 映射、`te(...)` 回退逻辑和手工标签常量。
- 保持字段名、按钮、帮助文本、错误消息等非枚举文案继续使用 i18n。

## Non-goal

- 不调整后端 API、数据库值或枚举定义。
- 不改变枚举值对应的颜色、禁用条件、筛选行为或业务逻辑。
- 不将布尔状态（例如路由启用状态、登录是否成功）改为原始布尔值展示；它们不是接口枚举。

## User scenarios

- 用户在中文或英文界面查看应用、部署、服务、流水线等页面时，枚举值保持一致，例如 `running`、`waiting_to_run`、`docker_image`。
- 用户在创建或编辑表单中选择应用类型、镜像拉取策略、凭据类型或制品类型时，选项标签与实际提交值一致。

## Acceptance

- 应用、版本、部署、服务、网关、流水线、制品、凭据、用户和项目成员页面不再对接口枚举调用 i18n 标签映射。
- 枚举选择器直接使用原始枚举值数组，展示与提交保持一致。
- 枚举值不经过标签对象规范化；缺失或未识别的值不以其他枚举值替代。
- 枚举展示统一使用带边框的标签样式，状态枚举继续保留已有颜色语义。
- 废弃的枚举 i18n 词条和凭据类型标签常量被删除，且没有残留调用方。
- `npm run typecheck`、`npm run lint` 和 `git diff --check` 通过。

## Open questions

不适用。用户已明确要求标签保持原枚举定义，不随 i18n 切换。

## Decisions

- 将字符串形式的接口状态、类型、来源、策略和模式视为本任务的枚举范围。
- 将布尔型业务状态排除在本任务范围外，继续使用现有的本地化文案。
- 本需求为对已完成前端改动的补录；后续验证将以当前实际 diff 和已运行检查为依据。

## Risk

- 原始枚举值的可读性低于本地化文案，这是用户明确选择的行为。
- 后端新增枚举值时，前端会直接显示新值；这避免了缺失翻译，但需要确认其命名适合用户可见。

## User review notes

- 2026-07-26：要求减少枚举的规范化与回退处理，异常值应直接暴露。
